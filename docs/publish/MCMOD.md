## ⚠️ MC 百科与两大站**本质不同**（先读这段）

1. **MC 百科是 Wiki 型资料站，词条是社区共同维护的**，不是你的个人页面。
   提交后由编辑审核，其他编辑也可能修改内容。因此文案必须**客观、中立、
   去营销化**。
2. **通常不直接托管 jar**，而是引导到 CurseForge / Modrinth 下载。
   → **建议先发那两站拿到下载链接，再来建词条。**
3. **收录规则第 6 条**：「未发布过任何可运行版本的Mod」不收录。
   → 必须**先有可下载的正式构建**再提交。
4. **收录规则第 5 条**：「涉及侵权、剽窃实锤的Mod」不收录。
   → 必须明确标注原作者与 GPL-3.0 授权（下面文案已覆盖）。
5. **收录规则第 11 条**：禁止「恶意占用已存在的MODID」。
   → 我们的 modid 仍是 `tacz`，这是**移植的必然要求**（否则枪包依赖全失效），
   **需在提交备注里主动说明**，避免被误判。下面已附备注模板。

## ④ 详细介绍（正文）

```
【说明】本模组为非官方社区移植版本，不是 TaCZ 官方发布，
与 TACZ Dev Team 无隶属关系，未经其审阅或背书。

──────────────────────────────

一、模组内容

  《永恒枪械工坊:零》是一款现代枪械模组，提供高自由度的枪械改装系统，
  包含配件、瞄具、多种弹药类型，以及用于制作和改装武器的枪械工作台。
  该模组支持第三方"枪包"扩展，可加载完全独立的武器内容。

  本项目将该模组移植至 Fabric 加载器与更新的 Minecraft 版本，
  不新增枪械或玩法内容，目标是使原有模组及其枪包生态能够继续运行。

──────────────────────────────

二、移植来源与授权

  原模组：永恒枪械工坊:零（Timeless and Classics Guns: Zero）
          开发者：TACZ Dev Team
  移植来源：Sh1roCu / TACZ-Refabricated
  对应上游版本：1.1.8-hotfix
  本项目源码：[[ 填你的 GitHub 仓库地址 ]]

  原模组代码采用 GPL-3.0 开源许可，该许可允许移植与再分发，
  本移植版同样以 GPL-3.0 开源，符合原许可证要求。

  关于模组 ID：本移植版沿用原模组的 modid（tacz）。
  这是移植版的必要条件 —— 枪包通过该 ID 声明依赖，
  更改 ID 将导致所有现有枪包无法加载、存档内物品丢失。

──────────────────────────────

三、相较原版的改动

  目标游戏版本移除或重构了多项 API，因此移植过程包含较多内部重写：

  1. 瞄准镜渲染重写
     原版依靠模板缓冲（stencil buffer）实现镜内渲染，
     该功能在目标版本已被移除，相关渲染流程已重新实现。
     部分视觉效果与原版存在差异。

  2. 网络通信迁移至当前的数据包与编解码器体系。

  3. 资源与数据包加载适配新的资源格式。

  4. 枪包兼容性修复，使包括旧版本在内的第三方枪包能够继续加载。

──────────────────────────────

四、当前状态

  本移植版已可正常游玩，处于测试阶段，可能存在未知问题。

──────────────────────────────

五、运行环境

  模组加载器：Fabric
  必需前置　：Fabric API、Forge Config API Port
  Java 版本 ：25 或更高

  具体的 Minecraft 版本与依赖版本以各下载文件的标注为准。
  本移植版仅支持 Fabric，无 Forge / NeoForge 版本。

──────────────────────────────

六、枪包安装方法

  枪包目录为 .minecraft/tacz/，而非 tacz_backup。

    .minecraft/
    ├── tacz/                 ← 枪包放置于此（游戏首次启动时自动创建）
    │   ├── 某枪包.zip        ← zip 可直接放入，无需解压
    │   └── 另一个枪包/       ← 也支持解压后的文件夹
    └── tacz_backup/          ← 旧版枪包转换器的输入目录，非加载目录

  文件夹或压缩包需在根目录下存在 gunpack.meta.json 才会被识别，
  最小内容为：

    { "namespace": "枪包命名空间" }

  缺少该文件时，枪包将被跳过且不产生提示。

  枪包未生效时的排查顺序：
    1. 是否放置于 tacz/ 目录，而非 tacz_backup/；
    2. 根目录是否存在 gunpack.meta.json；
    3. 压缩包层级是否正确 —— gunpack.meta.json 须位于 zip 根目录，
       而非 zip/枪包名/gunpack.meta.json；
    4. 查看日志中是否出现 Mod version mismatch。

  关于版本号：本移植版的版本号以上游基线版本（1.1.8）开头，
  加号之后为语义化版本规范中的构建元数据。
  按该规范，构建元数据不参与版本比较，
  因此声明 "tacz": ">=1.1.8" 一类依赖的枪包可以正常通过校验。

──────────────────────────────

七、已知限制：需要 TacZ:Arcana 前置的加密枪包

  部分枪包在任何缺少 TacZ:Arcana 的 TACZ 版本上均无法加载，
  表现为：枪械条目、名称、配方均正常显示，但模型不加载、
  贴图显示为紫黑色缺失贴图。

  判断方法：将枪包解压后查看是否符合以下特征
    · 存在 recursion/taczpack.dat（体积通常占整包的绝大部分）
    · 或存在 data/<命名空间>/expansions/taczexpands.data
    · 且包内不存在任何 .png、.ogg、geo_models/、textures/ 文件

  此类枪包将模型、贴图、动画与音效加密打包于该 .dat 文件中，
  磁盘上仅保留 JSON 索引。解密由第三方前置模组 TacZ:Arcana 完成，
  该模组仅有 Forge 版本且不开放源码。

  TACZ 本体不包含该解密实现，原版 Forge 模组、上游 Fabric 移植版
  与本移植版均是如此。因此该现象不属于本移植版的缺陷，
  也无法通过修改本移植版解决。

──────────────────────────────

八、常见问题：专用服务器上通过 REI/JEI 作弊拿取枪械/弹药/配件
              显示为紫黑块与 item. 前缀原始键

  症状：专用服务器上从 REI/JEI 点击拿取（或直接执行
        /give tacz:modern_kinetic_gun，不带数据组件）得到的枪械、弹药、
        配件显示缺失贴图，名称为 item.tacz.modern_kinetic_gun 或
        item.tacz.attachment 一类的原始键；但这些物品在 REI/JEI 列表内
        显示正常，单人游戏与局域网联机也正常。

  原因：TACZ 的枪械/弹药/配件/工作台物品并非自带内容的自足物品，
        其内容 id 存放于 minecraft:custom_data 数据组件中
        （GunId / AmmoId / AttachmentId / BlockId）。当专用服务器
        未安装 REI 时，REI 的作弊给物会退回由客户端拼装的 /give 命令，
        该命令只携带物品注册表 id，数据组件部分恒为空
        （ClientHelperImpl#tryCheatingEntry，源码注释 TODO 24w09a
        标注组件化后未适配）。服务端因此只收到"裸物品"：
        TACZ 读取内容 id 得到 tacz:empty，名字回退为原版 item.* 键
        （该键无翻译，故直接显示原始键），也无法解析模型，故显示紫黑块。
        原版 Forge 模组与上游 Fabric 移植版行为相同，
        该现象属于 REI 的给物方式所致，并非本移植版缺陷。
        （铁弹药盒仍能显示名称，是因为其名称键打包在模组 jar 内，
        恰好证明了服务端收到的是裸物品。）

  解决方法：
    1. 在专用服务器上安装与客户端相同版本的 REI —— 此后作弊走 REI
       网络包，物品数据组件完整；
    2. 或从 TACZ 自带的创造模式标签页、内置的弹药查询 / 配件查询 /
       枪械工作台配方分类中拿取，这些条目已携带所需内容 id；
    3. 使用 /give 时请附带数据组件，例如：
       /give @p tacz:modern_kinetic_gun[minecraft:custom_data={GunId:"tacz:ak47"}]

  JEI 的客户端兜底走原版创造模式槽位包，该包携带数据组件；
  若仅使用 JEI 仍出现同样现象，请在反馈时附上查看器与服务器版本。
```
