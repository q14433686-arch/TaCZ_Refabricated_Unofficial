## 1. Q1-Q10 逐条回答

| # | 问题 | 26.1.2 的答案（证据级别） |
|---|---|---|
| **Q1** | `RenderType#draw` 是绘制时读 MV，还是绑 pass 时读完？ | **绘制时读**（字节码）：`RenderType#draw(MeshData)` 的顺序是 `getModelViewStack` push（layering）→ `getDynamicUniforms().writeTransform(getModelViewMatrix(), …, textureTransform)`（@31-@65）→ 解析输出目标 → `createCommandEncoder().createRenderPass(…)`（@256）→ setPipeline/scissor/`bindDefaultUniforms`/bindTexture/setUniform/setVertexBuffer/setIndexBuffer/`drawIndexed` → close。**与 1.21.11 同构**；且 writeTransform 在 createRenderPass 之前（pass 内禁 map 的顺序约束两边一致）。消费点设计原样成立。 |
| **Q2** | `renderAllFeatures()` 的调用点各在哪、`endBatch` 相对位置 | **共 7 处**（常量池全 jar 扫描 + 方法级定位）：① `GameRenderer#renderLevel(DeltaTracker)` 尾部 @570，紧跟 `bufferSource.endBatch()` @575 —— **世界那一次**（唯一世界调用点；1211 的 LevelRenderer 两个调用点在 26.1.2 不存在，LevelRenderer 全类不引用该方法）；② `GameRenderer#renderItemInHand` 开头 @9-@22 的 renderAllFeatures+endBatch 预 flush（清遗留几何，早于 MV push）；③ `ItemInHandRenderer#renderHandsWithItems` 尾部 @281 + endBatch @294（手部）；④-⑦ GUI 侧 4 处：`GuiItemAtlas`、`GuiBannerResultRenderer`、`GuiEntityRenderer`、`OversizedItemRenderer`。②③被 `inHandPass` 门拒收、④-⑦被 `levelRenderActive=false`（GUI 渲染在 renderLevel 之外）+ `ScreenRenderTracker` 拒收。`require=0` 钩子挂在方法本身（public API），与 1211 同策略。 |
| **Q3** | 有没有 `PreparedFrame#executeSolid` / `RenderType#prepare()` / `drawFromBuffer` | **没有**（全 jar 无 `PreparedFrame` 类；`RenderType` 无 `prepare()`）。⇒ 26.2 的「压栈取 MV + prepare()」路线在 26.1.2 同样不可用，自建 pass 路线与 1211 相同是唯一解。 |

## 2. 26.1.2 移植适配清单（对 1211 源的全部实质改动）

## 3. 注入点差异说明（供 1211 更新 MESH_LOADER.md「已知边界」并回流 26.2）

1. **世界 flush 归属**：1211/1.21.11 的世界 flush 在 `LevelRenderer`（两个
   调用点）；26.1.2 搬进了 `GameRenderer#renderLevel` 尾部（唯一调用点），
   且 `renderItemInHand` 开头多了一次「清遗留」预 flush。影响：消费钩子仍挂
   `renderAllFeatures` RETURN（public API，跨纪元稳），但 `levelRenderActive`
   的圈定必须包 `GameRenderer#renderLevel`（本仓用 @Redirect + try/finally），
   而不是 1211 的「LevelRenderer 调用处」同名包装。
2. **GUI 侧调用点变多**（4 个 GUI 渲染器直接调 `renderAllFeatures`）：
   `levelRenderActive`（try/finally 保证异常复位）+ `ScreenRenderTracker`
   （extract 事件）+ `outputColorTextureOverride` 三道闸缺一不可；
   26.1.2 的 `GameRenderer#renderLevel` 尾部还有 clearDepthTexture（@491-@508）
   与 HUD 投影切换（@488）——GPU 世界 pass 的输出目标/投影跟随原版
   `RenderType#draw` 同款解析（override 优先），与 vanilla 自己的实体批次
   完全同态，因此这些 vanilla 侧时序不影响等价性论证。
3. **手部链路跨纪元不变**：`renderHandsWithItems` 尾部 flush + RETURN 注入 +
   Iris 的 Wrap 对（Iris 1.10.x 与 1.11.x 源码同构）→ 1211 的 Step2 设计
   原样可用。Iris 版本门从 `1.10.` 改 `1.11.`。
4. **`DepthStencilState.DEFAULT` 存在**于 26.1.2（ENTITY_SNIPPET 用它）——
   1211 侧若做深度状态聚合化，可直接引用该常量。
