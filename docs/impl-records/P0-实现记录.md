# P0 实现记录：基础架构与数据层

> 日期：2026-07-31
> 对应文档：P0: 基础架构与数据层

## 1. 源码阅读总结

在开始实现之前，我深入阅读了TACZ的以下核心代码：

| 文件 | 关键发现 |
|------|---------|
| `ModItems.java` | 物品注册使用 `Registry.register(BuiltInRegistries.ITEM, ...)` ，Item.Properties 需要 setId() |
| `ModBlocks.java` | 方块注册使用 `Registry.register(BuiltInRegistries.BLOCK, ...)` ，方块实体使用 `BlockEntityType` |
| `ItemNbtUtils.java` | 26.2版本使用 `DataComponents.CUSTOM_DATA` + `CustomData.update()` 读写NBT |
| `AmmoItemDataAccessor.java` | 弹药数据通过 `custom_data` NBT存储，`applyMaxStackSize()` 使用 `DataComponents.MAX_STACK_SIZE` |
| `GunItemDataAccessor.java` | 枪械NBT字段（GunId/AmmoCount/FireMode等）通过 `ItemNbtUtils.getTag()/updateTag()` 读写 |
| `GunItemBuilder.java` | 枪械物品通过Builder模式创建，支持设置弹药数/开火模式/配件/热量数据 |
| `AmmoItemBuilder.java` | 弹药物品通过Builder创建，只有ammoId一个属性 |
| `CommonGunIndex.java` | 枪械数据从JSON加载，通过 `CommonAssetsManager` 管理 |
| `GunMod.java` | setup()方法中初始化所有注册：ModBlocks/ModItems/ModCreativeTabs/ModEntities等 |

**关键架构决策**：
1. TACZ使用 `custom_data` NBT（通过 `ItemNbtUtils`）存储枪械/弹药数据，而非DataComponent
2. 26.2版本的DataComponent系统已可用（`AmmoItem` 已使用 `DataComponents.MAX_STACK_SIZE`）
3. 新增的复杂数据结构（如AmmoData/GunWearData）应使用自定义DataComponent，而非塞入custom_data
4. 这样可以享受Codec序列化/网络同步的便利，且与26.2的组件化方向一致

## 3. 与文档设计的偏差

| 偏差点 | 原因 | 影响 |
|--------|------|------|
| `HeatComponent`（金属零件的热锻温度）未实现 | 热度条机制属于P2阶段（制造链路），P0只实现数据层 | 无影响，P2阶段补充 |
| `BlueprintData`（玩家持久数据）未实现 | 蓝图系统需要读取TACZ的玩家数据存储方式，属于P2阶段 | 无影响，P2阶段补充 |
| `TaczMachineBlockEntity` 通用字段未实现 | 方块实体属于P2阶段 | 无影响 |
| `GunStateData` 合并了多个文档章节的NBT字段 | 减少DataComponent数量，避免枪械物品有过多的组件类型 | 正面影响，简化数据访问 |
| `AmmoData` 使用Record而非interface | Record天然支持Codec/不可变/with模式，比interface更适合DataComponent | 正面影响 |

### 2.5 IGun接口扩展

在 `IGun` 接口中新增4个default方法，通过DataComponent访问扩展数据：

| 方法 | 返回类型 | 说明 |
|------|---------|------|
| `getGunStateData(ItemStack)` | `GunStateData` | 枪机循环/故障/烧蚀/保险状态 |
| `getGunWearData(ItemStack)` | `GunWearData` | 7个部件的独立耐久 |
| `getGunMaintenanceData(ItemStack)` | `GunMaintenanceData` | 积碳/锈蚀/润滑/异物 |
| `getToleranceData(ItemStack)` | `ToleranceData` | 公差评分/科技阶段 |

每个方法都使用 `default` 实现，不破坏现有实现类。

### 2.6 IAmmo接口扩展

在 `IAmmo` 接口中新增2个default方法：

| 方法 | 返回类型 | 说明 |
|------|---------|------|
| `getAmmoData(ItemStack)` | `AmmoData` | 弹药完整属性 |
| `setAmmoData(ItemStack, AmmoData)` | void | 设置弹药属性 |

### 2.7 GunItemBuilder扩展

新增2个Builder字段和方法：
- `setTechLevel(int)` — 制造科技阶段
- `setToleranceScore(float)` — 公差评分

在 `build()` 方法中自动初始化所有5个DataComponent。

### 2.8 AmmoItemBuilder扩展

新增完整的弹药属性Builder：
- `setCaseMaterial(CaseMaterial)` — 弹壳材质
- `setPrimerType(PrimerType)` — 底火类型
- `setPowderType(PowderType)` — 发射药类型
- `setPowderCharge(float)` — 装药量
- `setBulletType(BulletType)` — 弹头类型
- `setReloadCount(int)` — 复装次数
- `setCaseCondition(CaseCondition)` — 弹壳状态
- `setAmmoData(AmmoData)` — 批量设置

在 `build()` 方法中，如果设置了自定义弹药属性，则自动写入 `AmmoData` 组件。

### 2.9 GunData扩展

新增JSON字段：
- `action_type` — 自动原理类型（ActionType枚举），向后兼容bolt字段
- 新增 `getActionType()` 方法：如果JSON指定了action_type则使用它，否则从bolt自动映射

### 2.10 BulletData扩展

新增JSON字段：
- `bullet_length` — 弹头长度（用于缠距匹配）
- `bullet_diameter` — 弹头直径/口径
- `optimal_barrel_length` — 最佳枪管长度
- `ballistic_coefficient` — 弹道系数
