## 实现步骤（按依赖顺序）

### Step 1: 扩展 GunHeatData（JSON字段扩展）

**文件**：`resource/pojo/data/gun/GunHeatData.java`

新增字段：
- `erosion_per_shot` (float, 默认0.001) — 每发射击的烧蚀增量
- `cookoff_threshold` (float, 默认0.85) — Cook-off触发的热量百分比阈值
- `environment_cooling_modifier` (float, 默认1.0) — 环境冷却修正系数
- `caliber_heat_modifier` (float, 默认1.0) — 口径热量修正系数

### Step 2: 扩展 GunStateData（业务方法扩展）

**文件**：`api/item/component/GunStateData.java`

新增方法：
- `withErosionFromShot(float erosionPerShot, float heatPercentage)` — 过热时烧蚀加速：`erosion += erosionPerShot × (1 + heatPercentage × 2.0)`
- `withBarrelDamageFromCatastrophic(int severity)` — 炸膛后枪管损伤升级
- `getCookoffProbability()` — Cook-off概率：`(heatPercentage - 0.85) × 0.001`（仅闭膛待击）
- `getCatastrophicFailureScore(LoadedRound, GunMaintenanceData, float heatPercentage, ToleranceData)` — 炸膛综合评分

### Step 3: 扩展 GunMaintenanceData（环境交互+锈蚀速率）

**文件**：`api/item/component/GunMaintenanceData.java`

新增方法：
- `withCarbonFromShot(float carbonRate)` — 射击后积碳：使用PowderType.getCarbonFoulingRate()
- `withLubricationTickDecay()` — 每tick润滑衰减：-0.001/tick
- `withCorrosionFromEnvironment(boolean isRaining, boolean isInWater, boolean isOiled)` — 环境锈蚀
- `getCorrosionRate(boolean isRaining, boolean isInWater, boolean isOiled)` — 锈蚀速率计算
- `getAccuracyPenalty()` — 积碳+锈蚀的精度惩罚
- `getMalfunctionBonus()` — 积碳+锈蚀的卡壳概率额外贡献

### Step 4: 炸膛系统（CatastrophicFailureSystem）

**新文件**：`api/item/ballistics/CatastrophicFailureSystem.java`

核心逻辑：
```java
// 1. 炸膛评分（加权判定模型）
float score = 0.0f;
// 装药过量
if (loadedRound.isOvercharged()) score += overchargeRisk;
// Squib在枪管内
if (gunStateData.hasSquibInBarrel()) score += 80.0f;
// 枪管异物
score += gunStateData.contaminationType().getCatastrophicRiskModifier() * 3.0f;
// 极端过热
if (heatPercentage > 0.7f) score += (heatPercentage - 0.7f) * 50.0f;
// 公差差
score += (100 - toleranceScore) / 100.0f * 5.0f;
// 枪管损伤
if (gunStateData.barrelDamageLevel() >= 2) score += 10.0f;
// 积碳
if (maintenanceData.carbonFoulingLevel() > 80) score += 5.0f;

// 2. 综合概率
float probability = Math.min(0.95f, score * 0.01f);

// 3. 严重度判定
int severity = score < 5 ? 1 : (score < 20 ? 2 : 3);

// 4. 应用后果
// severity 1: 精度永久下降20%, barrelDamageLevel+1
// severity 2: 枪管/枪机部件损毁(barrelDamageLevel=3), GunWearData大幅磨损
// severity 3: 武器报废 + 射手受伤(3-8点伤害)
```

### Step 5: Cook-off系统（CookOffSystem）

**新文件**：`api/item/ballistics/CookOffSystem.java`

核心逻辑：
```java
// Cook-off判定条件：
// 1. heatPercentage > cookoffThreshold (默认0.85)
// 2. 枪膛内有弹 (chamberedRound != null)
// 3. 闭膛待击 (boltType == CLOSED_BOLT || MANUAL_ACTION)
// 开膛待击武器不受影响

// 概率模型：
// cookoff_probability = (heatPercentage - 0.85) × 0.001 per tick
// heat 85%: 0.0%/tick
// heat 90%: 0.005%/tick
// heat 100%: 0.015%/tick

// Cook-off后果：
// 膛内弹药自燃，自动发射（无人操控）
// 不消耗射手冷却时间，但视为一次射击
```

### Step 6: 过热扩展（OverheatExpansion）

**新文件**：`api/item/ballistics/OverheatExpansion.java`

核心逻辑：
```java
// 1. 射击后热量累积
// heat_amount += heat_per_shot × powder_type_modifier × caliber_modifier
// powder_type_modifier = PowderType.getHeatModifier()
// caliber_modifier = CartridgeType.maxSafePressure() / 235.0f (9mm基准)

// 2. 冷却
// if (time_since_last_shot > cooling_delay):
//     heat_amount -= cooling_rate × cooling_multiplier × environment_modifier
//     environment_modifier:
//     - 正常: 1.0
//     - 水中: 3.0
//     - 沙漠: 0.7
//     - 雨中: 1.5

// 3. 烧蚀累积
// erosion_accumulated += erosion_per_shot × (1 + heat_percentage × 2.0)
// 热量>50%时烧蚀加速

// 4. 过热→精度修正
// heat_inaccuracy = base_inaccuracy × (1 + heat_percentage × heat_inaccuracy_factor)
// 已在GunItemDataAccessor.lerpInaccuracy()中实现，P3扩展系数

// 5. 过热→炸膛联动
// if heat_percentage > 0.7:
//     catastrophic_failure_risk_bonus = (heat_percentage - 0.7) × 0.5
//     // heat 80%: +5% 炸膛风险
//     // heat 90%: +10% 炸膛风险
//     // heat 100%: +15% 炸膛风险
```

### Step 7: 环境检测（EnvironmentSensor）

**新文件**：`api/item/ballistics/EnvironmentSensor.java`

核心逻辑：
```java
// 检测玩家所在生物群系
// - 沙漠群系 → 沙尘环境：卡壳率+1.0%/发，积碳+0.1/发
// - 寒冷群系(temperature < 0.15) → 严寒环境：循环速度-20%，卡壳率+0.5%
// - 降雨中 → 潮湿环境：锈蚀速率×5
// - 水中 → 水中环境：锈蚀速率×25，枪管进水→炸膛风险

// 环境检测频率：每20tick检测一次（避免每tick检测的开销）
```

### Step 8: 保养交互（MaintenanceInteraction）

**新文件**：`api/item/ballistics/MaintenanceInteraction.java`

核心逻辑：
```java
// 保养操作流程：
// 1. 清洁（清洁刷+溶剂）→ 积碳-30
// 2. 润滑（枪械润滑油）→ 润滑+100
// 3. 除锈（钢丝刷+溶剂）→ 锈蚀-20（仅限轻度锈蚀）
// 4. 退出枪管异物（通条）→ contaminationType = NONE

// 保养效果：
// - 清洁：carbonFoulingLevel = max(0, current - 30)
// - 润滑：lubricationLevel = min(100, current + 100)
// - 除锈：corrosionLevel = max(0, current - 20)（仅corrosionLevel < 50）
// - 退出异物：contaminationType = NONE
```

### Step 9: 集成到射击流

**修改文件**：`ModernKineticGunScriptAPI.shootOnce()` / `ModernKineticGunItem.tickHeat()`

1. **射击时**：
   - 调用 `OverheatExpansion.applyShotHeat()` — 热量累积（含发射药/口径修正）
   - 调用 `OverheatExpansion.applyShotErosion()` — 烧蚀累积（含过热加速）
   - 调用 `CatastrophicFailureSystem.checkAndApply()` — 炸膛判定
   - 调用 `GunMaintenanceData.withCarbonFromShot()` — 积碳累积

2. **tickHeat时**：
   - 调用 `OverheatExpansion.applyCooling()` — 冷却（含环境修正）
   - 调用 `CookOffSystem.check()` — Cook-off判定（仅闭膛待击）
   - 调用 `EnvironmentSensor.check()` — 环境检测（每20tick）
   - 调用 `GunMaintenanceData.withCorrosionFromEnvironment()` — 环境锈蚀
   - 调用 `GunMaintenanceData.withLubricationTickDecay()` — 润滑衰减

### Step 10: Squib→炸膛联动

**修改文件**：`GunCycleMachine` 或射击流

当检测到Squib（弹头卡在枪管内）后：
- 设置 `gunStateData.hasSquibInBarrel = true`
- 下一发射击时，`CatastrophicFailureSystem` 自动将Squib加入评分（+80分）
- 严重度至少为2（中等炸膛）
