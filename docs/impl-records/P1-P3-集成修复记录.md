# P1-P3 集成修复记录

> 日期：2026-08-01
> 内容：P1-P3系统集成后的遗留问题修复

## 修复清单

### 1. 综合精度修正接入射击流

**问题**：`shootOnce()` 中的 `heatInaccuracy` 仅使用 TACZ 原始的热量精度公式
（`Mth.lerp(heatPercentage, minInaccuracy, maxInaccuracy)`），
P3 综合精度修正（过热扩展+耐久+保养+烧蚀）通过 `lerpInaccuracy()` 实现，
但 `lerpInaccuracy()` 从未被 `shootOnce()` 调用，导致实际子弹散布
**完全不受** P1/P3 系统影响。

**修复**：在 `shootOnce()` 中，计算完 `heatInaccuracy` 后，
调用 `GunIntegrationHelper.getComprehensiveInaccuracy(itemStack, heatInaccuracy)`
叠加 P3 综合修正。

**为什么不直接替换为 `lerpInaccuracy()`**：
- `shootOnce()` 中 `heatMax` 经过 `modifyProperty(RuntimeOnly.MAX_HEAT)` 修正
  （配件如散热器可增加最大热量值），影响 `heatPercentage` 的计算
- `lerpInaccuracy()` 内部使用原始 `heatData.getHeatMax()`，不经过 `modifyProperty`
- 直接替换会导致配件修正效果丢失
- 因此采用"先算 TACZ 原始精度（含 modifyProperty），再叠加 P3 综合修正"的方式

**修改文件**：
- `ModernKineticGunScriptAPI.java` — `shootOnce()` 方法

**精度修正叠加公式**：
```
heatInaccuracy = Mth.lerp(heatPercentage, minInaccuracy, maxInaccuracy)  // TACZ 原始
comprehensiveInaccuracy = heatInaccuracy × OverheatExpansion × (1/wear_accuracy) × (1/maintenance_accuracy) × (1/(1-erosion_penalty))
finalInaccuracy = base_gun_inaccuracy × comprehensiveInaccuracy × modifyProperty
```

### 2. FeedDeviceData ↔ 旧系统弹药计数同步

**问题**：TACZ 的旧系统使用 `getCurrentAmmoCount()`/`setCurrentAmmoCount()` 
跟踪弹药计数（简单整数），新系统使用 `FeedDeviceData` 跟踪每发弹药详细数据。
两套系统并行运行，但不同步，导致：
- 状态机射击后 `FeedDeviceData` 减少弹药，但旧系统计数不变
- 换弹后旧系统计数增加，但 `FeedDeviceData` 不变
- HUD 显示的弹药数来自旧系统，与实际 `FeedDeviceData` 不一致

**修复**：

1. **`syncLegacyAmmoState()`** — 新增 `FeedDeviceData → 旧系统` 同步：
   - 当 `FeedDeviceData` 存在时，将其 `getCurrentRoundCount()` 同步到旧系统
   - 在 `postShootCycle()` 和 `postBoltCycle()` 中自动调用

2. **`syncLegacyToFeedDevice()`** — 新增 `旧系统 → FeedDeviceData` 同步：
   - 在 `syncAfterReload()` 中调用
   - 旧系统弹药数 > FeedDeviceData 弹药数时：用 `addDefaultRounds()` 填充默认弹药
   - 旧系统弹药数 < FeedDeviceData 弹药数时：用 `removeRounds()` 移除多余弹药

3. **`addDefaultRounds()`** — 向 7 种供弹具添加默认弹药：
   - `BoxMagazineData.loadRound()` — LIFO 压入
   - `TubularMagazineData.loadRound()` — FIFO 尾部塞入
   - `CylinderData.loadNextEmpty()` — 装入下一个空弹膛
   - `BeltData.loadRound()` — FIFO 尾部塞入
   - `DrumMagazineData.loadRound()` — LIFO 压入
   - `StripperClipData.loadRound()` — 有序装入
   - `EnBlocClipData.loadRound()` — 有序装入

4. **`removeRounds()`** — 从 7 种供弹具移除弹药（防御性处理）：
   - 使用 `new ArrayList<>(rounds)` 创建副本，避免修改原始列表
   - BoxMagazine/DrumMagazine：LIFO 从末尾移除
   - TubularMagazine/Belt/StripperClip/EnBloc：FIFO 从头部移除
   - Cylinder：逐个清空已装填的弹膛

**修改文件**：
- `GunIntegrationHelper.java` — 新增 4 个方法，修改 `syncAfterReload()` 和 `syncLegacyAmmoState()`

**同步策略**：
- **FeedDeviceData → 旧系统**：在射击/拉栓循环中自动同步（`syncLegacyAmmoState()`）
- **旧系统 → FeedDeviceData**：在换弹完成后同步（`syncLegacyToFeedDevice()`）
- 当 `FeedDeviceData` 不存在时，旧系统由 TACZ 原有逻辑维护，无需额外同步

### 3. JSON 反序列化验证

**问题**：P0-P3 新增的 `GunData`/`BulletData`/`GunHeatData` 字段没有验证，
错误配置（如负值、非法枚举值）会导致运行时异常而非启动时报错。

**修复**：在 `CommonGunIndex.checkData()` 中新增 `checkBallisticExtensionFields()` 方法：

**GunData 验证**：
| 字段 | 验证规则 | 处理方式 |
|------|----------|----------|
| `barrel_length` | ≥ 0 | 警告（0=不参与弹道修正） |
| `twist_rate` | ≥ 0 | 警告（0=使用 Greenhill 推荐值） |
| `barrel_material` | null 或 "wrought_iron"/"carbon_steel"/"alloy_steel"/"ordnance_steel" | 异常（硬校验） |

**BulletData 验证**：
| 字段 | 验证规则 | 处理方式 |
|------|----------|----------|
| `bullet_length` | ≥ 0 | 警告 |
| `bullet_diameter` | ≥ 0 | 警告 |
| `ballistic_coefficient` | > 0 | 警告 |
| `optimal_barrel_length` | ≥ 0 | 警告 |

**GunHeatData P3 扩展验证**：
| 字段 | 验证规则 | 处理方式 |
|------|----------|----------|
| `erosion_per_shot` | ≥ 0 | 警告 |
| `cookoff_threshold` | ∈ [0, 1] | 警告 |
| `environment_cooling_modifier` | > 0 | 警告 |
| `caliber_heat_modifier` | > 0 | 警告 |
| `catastrophic_heat_threshold` | ∈ [0, 1] | 警告 |
| `cookoff_threshold ≥ catastrophic_heat_threshold` | 逻辑一致性 | 警告 |

**修改文件**：
- `CommonGunIndex.java` — 新增 `checkBallisticExtensionFields()` 方法

## 遗留问题

- **`modifyProperty` 与 `lerpInaccuracy()` 不一致**：`shootOnce()` 中 `heatMax` 经过 `modifyProperty` 修正，
  但 `lerpInaccuracy()` 使用原始 `heatMax`。当前通过"先算 TACZ 原始精度，再叠加 P3 综合修正"规避，
  但 `getComprehensiveInaccuracy()` 内部的 `OverheatExpansion.getHeatInaccuracyModifier()` 
  仍使用原始 `heatMax` 计算 `heatPercentage`。如果配件大幅改变 `heatMax`，
  过热扩展的精度修正可能略有偏差。**影响极小**，因为 `MAX_HEAT` 配件修正通常 < 20%。
  
- **`FeedDeviceData` 的 `feedRound()` 方法存在可变性问题**：`BoxMagazineData`/`TubularMagazineData`/
  `BeltData`/`DrumMagazineData` 的 `feedRound()` 方法直接修改内部 `rounds` 列表，
  但 record 应为不可变。这是 P0 阶段的遗留问题，建议后续统一修复为返回新对象的模式。
  `removeRounds()` 方法通过创建 `new ArrayList<>(rounds)` 副本规避了此问题。
