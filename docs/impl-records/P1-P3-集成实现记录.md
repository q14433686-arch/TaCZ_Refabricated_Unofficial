# P1-P3 集成实现记录

> 日期：2026-07-31
> 阶段：P1/P2/P3 系统集成（将各独立系统接入 TACZ 射击流）

## 1. 概述

P1（状态机+模块化耐久）、P2（弹药力学+弹道）、P3（过热/炸膛/保养）各自独立完成后，需要将它们接入 TACZ 的现有射击流程。本文档记录所有集成工作。

### 核心原则

- **不替换 TACZ 的现有系统**：TACZ 的 `hasBulletInBarrel`/`getCurrentAmmoCount`/`reduceAmmoOnce` 等方法继续作为主流程
- **新系统作为补充**：通过 `GunIntegrationHelper` 桥接新系统与旧系统
- **双写同步**：在关键节点同步新旧系统的数据，确保向后兼容
- **最小侵入**：修改 TACZ 现有代码时，尽量通过添加而非替换的方式

## 2. 新增文件

### 2.1 GunIntegrationHelper.java

**路径**：`api/item/ballistics/GunIntegrationHelper.java`

**职责**：桥接新系统与 TACZ 射击流的统一入口

**核心方法**：

| 方法 | 用途 | 调用点 |
|------|------|--------|
| `checkCanFire()` | 检查故障/保险/Squib | `LocalPlayerShoot.preCheck()` + `LivingEntityShoot.shoot()` |
| `postShootCycle()` | 射击后执行枪机循环 | `ModernKineticGunScriptAPI.shootOnce()` |
| `postBoltCycle()` | 拉栓后执行手动循环 | `ModernKineticGunItem.defaultTickBolt()` |
| `getComprehensiveInaccuracy()` | 综合精度修正 | `GunItemDataAccessor.lerpInaccuracy()` |
| `syncAfterReload()` | 换弹完成后同步状态 | `ModernKineticGunItem.defaultReloadFinishing()` |
| `syncLegacyAmmoState()` | 同步旧系统hasBulletInBarrel | postShootCycle/postBoltCycle内部 |
| `ensureGunStateDataExists()` | 初始化GunStateData | checkCanFire/shootOnce/tickHeat |

### 2.2 ShootResult.MALFUNCTION

**路径**：`api/entity/ShootResult.java`

新增枚举值 `MALFUNCTION`，用于枪械处于故障状态时阻止射击。

### 2.3 LoadedRound.createDefault()

**路径**：`api/item/component/LoadedRound.java`

新增工厂方法，用于从旧系统迁移时创建默认膛内弹药。

### 3.5 GunItemDataAccessor.java（NBT访问器）

**修改**：`lerpInaccuracy()` 方法集成综合精度修正

```java
@Override
default float lerpInaccuracy(ItemStack gun) {
    float baseInaccuracy = TimelessAPI.getCommonGunIndex(getGunId(gun))
            .map(index -> index.getGunData().getHeatData())
            .map(heatData -> {
                float heatPercentage = (getHeatAmount(gun) / heatData.getHeatMax());
                return Mth.lerp(heatPercentage, heatData.getMinInaccuracy(), heatData.getMaxInaccuracy());
            }).orElse(1f);
    // P3集成：综合精度修正（过热扩展+耐久+保养+烧蚀）
    return GunIntegrationHelper.getComprehensiveInaccuracy(gun, baseInaccuracy);
}
```

## 4. 数据流图

### 4.1 射击流

```
客户端: LocalPlayerShoot.preCheck()
  → GunIntegrationHelper.checkCanFire() [故障检查]
  → 原有弹药/过热/拉栓检查
  → doShoot() → 发包

服务端: LivingEntityShoot.shoot()
  → GunIntegrationHelper.checkCanFire() [故障检查]
  → 原有弹药/过热/闭膛检查
  → logicGun.shoot() → ModernKineticGunScriptAPI.shootOnce()
    → ensureGunStateDataExists() [初始化]
    → 弹药消耗 reduceAmmoOnce()
      → setBulletInBarrel(false) + GunStateData.withChamberedRoundFired() [同步]
    → 子弹创建 + applyBallistics() [P2]
    → handleShootHeat() [P3: 热量/烧蚀/积碳/炸膛]
    → postShootCycle() [P1: 状态机循环]
      → GunCycleMachine.fireAutoCycle()
      → 更新 GunStateData/GunWearData/FeedDeviceData
      → syncLegacyAmmoState() [同步hasBulletInBarrel]
    → CasingDropHelper.spawnCasing() [P2: 弹壳掉落]
```

### 4.2 拉栓流

```
客户端: LocalPlayerBolt.bolt()
  → 检查 GunStateData.hasMalfunction() [故障清除]
  → 原有弹药检查
  → 发包 + 动画

服务端: LivingEntityBolt.bolt()
  → 检查 GunStateData.hasMalfunction() [故障清除]
  → startBolt() → tickBolt()
    → defaultTickBolt()
      → 喂弹时刻: postBoltCycle() [P1: 状态机循环]
        → GunCycleMachine.manualBoltCycle()
        → 更新 GunStateData/GunWearData/FeedDeviceData
        → syncLegacyAmmoState() [同步hasBulletInBarrel]
```

### 4.3 精度流

```
GunItemDataAccessor.lerpInaccuracy()
  → 基础过热精度 (TACZ原始)
  → GunIntegrationHelper.getComprehensiveInaccuracy()
    → OverheatExpansion.getHeatInaccuracyModifier() [P3: 过热扩展]
    → GunWearData.calculateOverallAccuracy() [P1: 耐久]
    → GunMaintenanceData.getAccuracyPenalty() [P3: 保养]
    → GunStateData.getErosionAccuracyPenalty() [P3: 烧蚀]
```

## 5. 修复的问题

### 5.1 EnvironmentSensor.detect() 参数错误

**问题**：`defaultTickHeat()` 中 `iGun instanceof LivingEntity le ? le : null` 永远为 null（iGun 是 IGun 接口，不是 LivingEntity）

**修复**：`tickHeat()` 方法签名增加 `shooter` 参数，直接传入 `defaultTickHeat(heatTimestamp, gunItem, shooter)`

### 5.2 Raw NBT tag `tacz_env_check_timer`

**问题**：`defaultTickHeat()` 使用 `gunItem.getOrCreateTag().getInt("tacz_env_check_timer")` 作为计时器，这是临时方案，每tick写NBT造成性能开销

**修复**：移除 NBT 计时器，改为每次 tickHeat 调用时检测环境。tickHeat 本身不是每tick调用的（有冷却延迟），所以检测频率不会过高。

### 5.3 过热→精度修正未集成

**问题**：`OverheatExpansion.getHeatInaccuracyModifier()` 存在但未被 `lerpInaccuracy()` 调用

**修复**：`lerpInaccuracy()` 调用 `GunIntegrationHelper.getComprehensiveInaccuracy()`，综合所有精度修正
