### 1. TACZ模组现有代码架构

通过阅读本项目源码，TACZ的核心架构如下：

| 模块 | 关键类/接口 | 说明 |
|------|------------|------|
| 枪械物品 | `IGun` / `AbstractGunItem` / `GunItemDataAccessor` | 枪械NBT访问接口，支持弹药数/开火模式/配件/过热等数据 |
| 弹药物品 | `IAmmo` / `IAmmoBox` / `AmmoItemDataAccessor` | 弹药ID/弹药箱，与枪械通过ammoId关联 |
| 配件系统 | `IAttachment` / `AttachmentType` / `AttachmentCacheProperty` | 6种配件类型（SCOPE/MUZZLE/STOCK/GRIP/LASER/EXTENDED_MAG），通过Modifier系统修改枪械属性 |
| 枪械数据 | `GunData` / `BulletData` / `GunRecoil` / `GunHeatData` | JSON驱动的枪械属性定义，包含RPM/伤害/精度/后坐力/过热等 |
| 弹道实体 | `EntityKineticBullet` | 投射物实体，处理碰撞/伤害/穿透 |
| 合成系统 | `GunSmithTableRecipe` / `GunSmithTableBlockEntity` | 枪匠台配方，简单材料→枪械/弹药 |
| 射击者数据 | `ShooterDataHolder` / `IGunOperator` | 射击状态管理，包含瞄准/换弹/冷却/过热等 |
| 属性修改器 | `GunProperties` / 17个`XxxModifier` | 配件对枪械属性的修改系统（伤害/精度/后坐力/消音/重量等） |
| Bolt类型 | `Bolt` 枚举 | OPEN_BOLT / CLOSED_BOLT / MANUAL_ACTION |
| 供弹类型 | `FeedType` 枚举 | MAGAZINE / MANUAL / FUEL / INVENTORY |
| 散布类型 | `InaccuracyType` 枚举 | STAND / MOVE / SNEAK / LIE / AIM |

**关键发现**：
- TACZ的枪械数据完全由JSON驱动，枪包（Gun Pack）系统允许无代码创建新枪械
- 配件系统通过`AttachmentCacheProperty`缓存机制，在安装配件时一次性计算所有属性修改
- 枪械NBT使用`minecraft:custom_data`存储（26.2版本的组件化NBT布局）
- 现有的过热系统已存在基础框架（`GunHeatData`），但功能较简单
- 现有合成系统极其简化：AK47 = 38铁锭 + 6青金石 + 10木头，一键完成
- **没有**：故障/卡壳系统、模块化耐久、保养维护、弹道下坠、供弹具差异化、制造链路等

# A. 制造与工业链路系统

## A.1 现实原理简述

现实中的枪械制造是一个极其复杂的工业过程，从矿石到成品涉及以下核心环节：

**冶金环节**：铁矿石→生铁（高炉冶炼，含碳量3-4.5%）→钢（脱碳至0.02-2.1%）→合金钢（添加铬/钼/钒/镍等合金元素）→工具钢（高碳+合金元素，用于刀具/模具）。黄铜（铜锌合金，约70%Cu+30%Zn）用于弹壳制造，因其延展性好、可复装。铅用于弹头核心，因其密度高且廉价。铝合金用于轻量化弹壳。

**化学环节**：黑火药（硫磺+硝石+木炭，传统配方）→硫酸（接触法）→硝酸（奥斯特瓦尔德法）→硝化棉（纤维素+硝酸）→无烟火药（硝化棉+硝化甘油+稳定剂）。现代发射药为双基或三基药，燃烧速率需精确控制。

**零件加工环节**：枪管需要深孔钻→膛线拉削/冷锻→热处理→内膛研磨；机匣需要精密铣削或冲压成型；枪机需要精密加工以确保闭锁面配合。

**装配环节**：各零件需在公差范围内配合，公差过大导致精度下降/可靠性差，过小则加工成本极高。现代工业采用统计过程控制(SPC)管理公差。

### A.2.3 各阶段工艺详解

#### T0: 手工阶段

**核心机制**：玩家使用坩埚、砧板、锤子等基础工具，通过"热度条"机制进行锻造。

**热度条机制**：
- 将金属放入坩埚/熔炉加热，金属物品获得`Heat`组件（0~1000°C）
- 不同操作需要不同温度区间：锻造温度(800~1100°C)、退火温度(600~700°C)、淬火温度(800~900°C)
- 温度自然冷却，冷却速率取决于环境温度和是否在保温容器中
- 在砧板上使用锤子进行锻造操作时，需要金属处于正确温度区间

**T0可用工作台**：

| 方块ID建议 | 显示名称 | 功能 | 交互方式 |
|-----------|---------|------|---------|
| `tacz:crucible` | 坩埚 | 熔炼金属，最高温度1200°C | 放入矿石+燃料，等待熔炼 |
| `tacz:forge_anvil` | 锻造砧 | 热锻金属零件 | 放入热金属，用锤子敲击 |
| `tacz:charcoal_kiln` | 炭窑 | 烧制木炭 | 放入木头，密封加热 |
| `tacz:hand_grinder` | 手磨机 | 粉碎矿石/研磨黑火药 | 手持操作，进度条 |
| `tacz:gunsmith_bench_t0` | 手工枪匠台 | 组装T0级枪械 | 简单配方合成 |

**T0可制造的枪械**：火绳枪、燧发枪、简易滑膛枪（均为单发、黑火药、精度极低）

**T0制造流程示例（火绳枪）**：
```
铁矿石→坩埚→生铁→砧板锻打→熟铁锭
熟铁锭→砧板热锻→枪管毛坯（粗制，无膛线）
木炭+硫磺+硝石→手磨机→黑火药
铅锭→坩埚熔炼→铅弹头（球型）
纸+黑火药→手工装药→纸壳弹药
枪管毛坯+木枪托+铁件→手工枪匠台→火绳枪
```

### A.2.6 质量公差系统

**现实原理**：在真实制造中，零件尺寸不可能绝对精确，存在公差(Tolerance)。公差大小决定了零件的配合精度，进而影响最终产品的性能。军规MIL-STD对武器零件有严格的公差要求。

**游戏化抽象**：
- 每个零件在制造时获得一个**公差评分**（0~100）
- 公差评分由以下因素加权决定：
  - 机器等级（T0手工→T4 CNC）：基础分 40~98
  - 动力稳定性（Create SU波动率）：修正 ±5
  - 材料等级（生铁→合金钢）：修正 ±3
  - 操作者技能/随机因素：修正 ±5
- 最终枪械的**综合公差评分** = 各零件公差评分的加权平均

**公差评分影响**：

| 公差评分范围 | 精度修正 | 可靠性修正 | 耐久修正 | 描述 |
|-------------|---------|-----------|---------|------|
| 95-100 | ×1.0 | ×1.0 | ×1.0 | 军规级，完美 |
| 85-94 | ×0.9 | ×0.95 | ×0.95 | 工业级，良好 |
| 70-84 | ×0.75 | ×0.85 | ×0.85 | 民用级，可用 |
| 50-69 | ×0.6 | ×0.7 | ×0.7 | 粗制级，勉强 |
| 0-49 | ×0.4 | ×0.5 | ×0.5 | 劣质级，危险 |

**公式**（游戏平衡用途，非真实弹道学）：
```
综合公差评分 = Σ(零件公差 × 权重) / Σ(权重)
权重分配：枪管(0.30) + 机匣(0.20) + 枪机(0.25) + 其他(0.25)

精度修正 = 0.4 + 0.6 × (综合公差 / 100)
可靠性修正 = 0.5 + 0.5 × (综合公差 / 100)
```

# B. 弹药系统

## B.1 现实原理简述

弹药是枪械系统的核心消耗品，由弹头、弹壳、发射药和底火四部分组成。弹壳材质直接影响弹药的复装性能：黄铜弹壳因其优异的延展性和弹性回复，可复装5-10次；钢制弹壳廉价但不可复装，且易生锈腐蚀；铝制弹壳轻量但不可复装，且强度较低。

底火是弹药的点火元件，分为Boxer式（中心一个底火砧，击针从中心击发，弹壳只有一个底火孔，便于复装时顶出废底火）和Berdan式（两个偏心底火孔，击针从中心击发但底火砧在弹壳内部，复装时难以取出废底火，因此通常不可复装）。军事弹药普遍采用Berdan式底火以降低成本。

发射药经历了从黑火药到无烟火药的历史演进。黑火药燃烧产生大量烟雾和固体残留物，严重暴露射手位置并加速枪管积碳；无烟火药（硝化棉基）燃烧清洁、能量密度高，但生产链路远比黑火药复杂。发射药的燃烧速率需与口径和枪管长度匹配——短枪管需快燃药，长枪管需慢燃药，否则会导致未充分燃烧（枪口焰大）或过压。

弹头类型多样：FMJ（全被甲）适用于通用场景，穿透力强但停止作用差；空尖弹(HP/JHP)击中目标后扩张，增加伤害但穿透力低；穿甲弹(AP)使用硬质核心（钢/钨），穿透护甲但伤害降低；曳光弹在弹头底部装有曳光剂，可见弹道但暴露位置；亚音速弹配合消音器使用，降低声音特征。

**燃烧速率匹配机制**（游戏化抽象）：
- 每种枪械有一个"最佳燃速区间"（由枪管长度和口径决定）
- 发射药燃速与枪械不匹配时，产生性能惩罚：
  - 快燃药配长枪管：过压风险，炸膛概率+5%，枪口焰增大
  - 慢燃药配短枪管：初速下降10%，未充分燃烧（枪口焰+烟雾）

### B.2.5 复装系统完整流程

**现实原理**：复装(Reloading)是将已射击的空弹壳回收，经过检查、清洁后重新装填底火、发射药和弹头的过程。这是射击运动中常见的经济做法，黄铜弹壳可复装5-10次。

**游戏化抽象**——复装流程为5步操作：

| 步骤 | 操作 | 所需工具 | 判定逻辑 |
|------|------|---------|---------|
| 1. 回收空弹壳 | 战斗后拾取 | 无 | 自动掉落，需手动拾取 |
| 2. 检查弹壳 | 检查裂纹/变形 | 检查台/放大镜 | 随机判定：完好→可复装，裂纹→淘汰，变形→可修复 |
| 3. 重新装底火 | 压入新底火 | 手动压底火台/弹药压装机 | Boxer式可装，Berdan式不可 |
| 4. 定量装填发射药 | 称量药量 | 药秤+漏斗 | 玩家选择药量，过量装药有过压风险 |
| 5. 压入弹头 | 将弹头压入弹壳 | 弹药压装机 | 完成成品 |

**弹壳状态枚举**：

| 状态 | 说明 | 可否继续复装 |
|------|------|------------|
| `PRISTINE` | 完好，首次使用 | 可 |
| `GOOD` | 良好，已复装1-2次 | 可 |
| `WORN` | 磨损，已复装3-4次 | 可，但裂纹概率+10% |
| `CRACKED` | 出现裂纹 | 不可（淘汰） |
| `DEFORMED` | 变形 | 可修复（需退火处理） |
| `CORRODED` | 锈蚀 | 不可（淘汰） |

**弹壳复装计数器**：每次复装后计数+1，超过材质上限时自动判定为CRACKED。

### B.2.6 定量装药的"过量装药"后果

**现实原理**：过量装药(Overcharge)会导致膛压异常升高，增加炸膛风险和部件磨损速率。

**游戏化抽象**：
- 装药量分为：标准(100%)、轻装(80%)、过量(120%)、严重过量(150%)
- 装药量不**立即**导致爆炸，而是通过概率模型影响后续射击：
  - 轻装(80%)：初速-10%，伤害-10%，可靠性-5%
  - 标准(100%)：基准值
  - 过量(120%)：初速+5%，伤害+5%，炸膛概率+3%/发，部件磨损×1.5
  - 严重过量(150%)：初速+10%，伤害+8%，炸膛概率+10%/发，部件磨损×3.0

# C. 弹道与精度系统

## C.1 现实原理简述

弹道学是研究弹头在枪管内和飞行过程中行为的科学。核心概念包括：

**内弹道**：发射药在膛内燃烧产生高压气体，推动弹头沿枪管加速。初速取决于膛压曲线、枪管长度和弹头质量。简化关系：初速∝√(膛压×枪管截面积×枪管长度/弹头质量)。

**外弹道**：弹头离开枪口后受重力、空气阻力和风偏影响。重力导致弹道下坠，下坠量与飞行时间的平方成正比。空气阻力使弹头减速，速度随距离指数衰减。风偏使弹头在水平方向偏移。

**散布**：即使固定枪械，每发子弹的弹着点也会有随机散布。散布来源包括：枪械机械精度、弹药一致性、射手操作、环境因素。

**膛线缠距与弹头稳定性**：膛线赋予弹头旋转，使其在飞行中保持稳定。Greenhill公式（简化版）：T = 150 × D² / L，其中T为缠距（英寸/转），D为弹头直径（英寸），L为弹头长度（英寸）。缠距太慢（T太大）→弹头翻滚失稳；缠距太快（T太小）→过度稳定（游戏内简化为无害）。

**穿透与跳弹**：弹头击中目标后可能穿透或跳弹。跳弹发生在浅角度命中硬表面时，弹头以反射角弹飞。

## C.2 游戏化抽象方案

### C.2.1 初速模型

**简化公式**（游戏平衡用途，非真实弹道学）：

```
V₀ = V_base × √(L_barrel / L_optimal) × √(powder_charge) × material_modifier

其中：
- V_base: 弹药基础初速（由弹药JSON定义）
- L_barrel: 实际枪管长度（mm）
- L_optimal: 最佳枪管长度（由弹药JSON定义）
- powder_charge: 装药量比例（0.5~1.5）
- material_modifier: 材料修正（合金钢1.0, 碳钢0.95, 熟铁0.85）

当 L_barrel < L_optimal 时，初速按比例降低
当 L_barrel > L_optimal 时，初速增益递减（上限×1.1）
```

### C.2.2 弹道下坠与飞行时间

**游戏化模型**：
- 子弹实体(`EntityKineticBullet`)已有重力属性(`gravity`)和寿命(`lifeSecond`)
- 扩展：根据初速计算飞行时间，根据飞行时间计算下坠量
- 下坠公式：`drop = 0.5 × g × t²`（g为重力加速度，t为飞行时间）
- 玩家需要根据距离预判提前量（远距离目标需要抬高瞄准点）

**实现方式**：在`EntityKineticBullet`的tick逻辑中，根据当前速度和距离计算下坠，调整Y轴速度分量。TACZ现有的`gravity`字段已部分实现此功能，但需要扩展为更精确的模型。

### C.2.3 风偏/横风影响（进阶可选项）

**设计建议**：作为可选难度模块，默认关闭。

| 配置项 | 默认值 | 说明 |
|--------|-------|------|
| `enable_wind` | false | 是否启用风偏 |
| `wind_update_interval` | 6000 | 风向更新间隔（tick） |
| `max_wind_speed` | 5.0 | 最大风速（m/s） |
| `wind_effect_multiplier` | 0.01 | 风偏影响系数 |

风偏计算：`horizontal_offset = wind_speed × cos(θ) × t × multiplier`，其中θ为风向与射击方向的夹角。

### C.2.4 散布模型

**静态精度**（枪械+弹药基础值）：
```
base_inaccuracy = gun_inaccuracy × ammo_quality_modifier × tolerance_modifier
```

**动态散布叠加**（以下因素累加）：

| 因素 | 散布增量 | 叠加方式 |
|------|---------|---------|
| 移动中开火 | +2.0 | 加法 |
| 连发后坐力累积 | +0.5 × cumulative_shots | 加法（每发+0.5，上限+10） |
| 腰射vs瞄准 | 腰射×3.0 / 瞄准×1.0 | 乘法 |
| 姿势修正 | 站立×1.0 / 蹲下×0.7 / 趴下×0.5 / 依托×0.35 / 脚架×0.2 | 乘法 |
| 过热 | heat_inaccuracy（来自GunHeatData） | 加法 |
| 疲劳 | +0.5 × fatigue_level | 加法 |
| 公差评分 | (100 - tolerance) / 100 × 2.0 | 加法 |

**最终散布公式**：
```
final_inaccuracy = base_inaccuracy × posture_multiplier × (aim_or_hip)
                 + movement_add + recoil_add + heat_add + fatigue_add + tolerance_add
```

### C.2.5 弹头稳定性：膛线缠距与弹头匹配

**游戏化Greenhill公式**（简化版，游戏平衡用途）：
```
stability_factor = 150 × D² / (T × L)

其中：
- D: 口径（游戏单位，由弹药JSON定义）
- T: 缠距（英寸/转，由枪管JSON定义）
- L: 弹头长度（游戏单位，由弹头类型决定）

判定：
- Sg > 1.5: 完全稳定，精度无惩罚
- 1.0 < Sg ≤ 1.5: 边缘稳定，精度-10%
- 0.5 < Sg ≤ 1.0: 不稳定，弹头翻滚，精度-50%，伤害+20%（翻滚增加杀伤）
- Sg ≤ 0.5: 严重失稳，精度-80%，弹头可能过早解体
```

**缠距不匹配的典型场景**：
- 使用重型弹头（长弹头）配慢缠距枪管→失稳
- 使用轻型弹头（短弹头）配快缠距枪管→过度稳定（无害）

### C.2.6 穿透与跳弹系统

**穿透力表**（游戏化，不同材质方块/生物护甲的穿透力判定）：

| 目标材质 | 穿透阈值 | 说明 |
|---------|---------|------|
| 皮革/木门 | 0.2 | 几乎所有弹药都能穿透 |
| 铁门/石砖 | 0.6 | 需要步枪弹或穿甲弹 |
| 钢板/铁傀儡 | 0.8 | 需要穿甲弹 |
| 黑曜石/末影 | 1.0 | 需要特殊弹药 |
| 生物（无甲） | 0.1 | 所有弹药穿透 |
| 生物（铁甲） | 0.5 | 需要步枪弹 |
| 生物（钻石甲） | 0.7 | 需要穿甲弹 |

**穿透判定**：
```
pierce_value = base_pierce × ammo_type_modifier × velocity_modifier × distance_modifier
if (pierce_value > target_threshold) → 穿透成功，伤害按比例衰减
```

**跳弹判定**：
```
if (hit_angle < 15° AND target_hardness > bullet_hardness):
    → 触发跳弹
    → 弹头以反射角弹飞，伤害衰减为原来的30%
    → 跳弹弹头继续飞行，可造成二次伤害
```

### C.2.7 【AI补充】环境因素对弹道的影响

**温度/气压修正**：

| 因素 | 影响 | 实现成本 | 游戏性价值 | 建议 |
|------|------|---------|-----------|------|
| 温度 | 低温→空气密度高→阻力增大→初速略降；高温→初速略增 | 低 | 低 | **不建议实现**，影响太小（<2%），玩家感知不到 |
| 气压/海拔 | 高海拔→空气稀薄→阻力减小→射程略增 | 低 | 低 | **不建议实现**，与温度同理 |
| 湿度 | 对弹道影响极小 | 低 | 无 | **不建议实现** |

**成本收益分析**：
- 温度/气压修正的真实影响在1-3%范围内，在游戏化环境中这个差异几乎不可感知
- 实现成本虽然不高（几个浮点数计算），但增加了系统复杂度和调试难度
- **最终建议**：不实现温度/气压修正，将开发精力集中在玩家可感知的机制上（如散布、下坠、风偏）

# D. 后坐力与人体工学系统

## D.1 现实原理简述

后坐力是枪械射击时反作用力的表现。不同自动原理的枪械后坐力曲线差异显著：

- **直吹式(Blowback)**：无闭锁机构，枪机质量+复进簧力抵抗膛压，后坐力来得早且猛，典型如MAC-10、UZI
- **延迟后吹式(Delayed Blowback)**：通过滚轮/杠杆等机构延迟开锁，后坐力曲线较平缓，典型如MP5、G3
- **管退式(Recoil Operated)**：枪管与枪机共同后坐一段距离后开锁，后坐力分布均匀，典型如M1911、M2重机枪
- **导气式(Gas Operated)**：从枪管导出燃气推动活塞/枪机框，后坐力曲线可控，典型如AK-47、M16
- **滚轮延迟式(Roller Delayed)**：HK专利，利用滚轮将后坐力分散到较大时间窗口，后坐力最柔和

连发后坐力累积是自动武器射击的关键问题：每一发的后坐力叠加在前一发之上，导致枪口持续上抬。松开扳机后，枪口恢复到原位的速率取决于枪械重量、复进簧力和射手姿势。

瞄准速度(ADS Speed)与武器重量/长度负相关——重型长枪需要更长时间举起并稳定。持枪重量对移动速度有惩罚，这是现代步兵战术中轻量化武器的重要考量。

呼吸摆动（待机晃动）是真实射击中的常见现象，长时间端枪瞄准会导致肌肉疲劳，晃动幅度增加。

## D.2 游戏化抽象方案

### D.2.1 后坐力类型与自动原理挂钩

**扩展TACZ的`Bolt`枚举为`ActionType`枚举**：

### D.2.2 连发后坐力累积与恢复曲线

**游戏化模型**：
```
cumulative_recoil = Σ(shot_i_recoil) × (1 - decay_rate)^(i-1)

每发射击后的后坐力：
shot_recoil = base_recoil × (1 + cumulative_factor × cumulative_shots)

恢复曲线（松开扳机后）：
current_recoil = peak_recoil × e^(-t / recovery_time_constant)

其中：
- cumulative_factor: 后坐力累积系数（由ActionType决定）
- decay_rate: 后坐力衰减率（由ActionType决定）
- recovery_time_constant: 恢复时间常数（由ActionType决定）
```

**各ActionType的后坐力累积参数**：

| ActionType | 累积系数 | 衰减率 | 恢复时间常数(ms) |
|-----------|---------|--------|----------------|
| BLOWBACK | 0.20 | 0.03 | 300 |
| DELAYED_BLOWBACK | 0.10 | 0.05 | 400 |
| RECOIL_OPERATED | 0.08 | 0.06 | 500 |
| GAS_LONG_STROKE | 0.15 | 0.04 | 350 |
| GAS_SHORT_STROKE | 0.10 | 0.05 | 400 |
| GAS_PISTON | 0.12 | 0.05 | 380 |
| ROLLER_DELAYED | 0.08 | 0.06 | 450 |

### D.2.3 瞄准速度(ADS Speed)与武器重量/长度关系

```
ads_time = base_ads_time × (1 + weight_penalty + length_penalty)

其中：
- weight_penalty = max(0, (weapon_weight - 3.0) / 10.0)  // 3kg为基准
- length_penalty = max(0, (weapon_length - 800) / 2000.0)  // 800mm为基准
```

| 武器类型 | 重量(kg) | 长度(mm) | ADS时间(秒) |
|---------|---------|---------|------------|
| 手枪 | 0.8 | 200 | 0.15 |
| 冲锋枪 | 3.0 | 600 | 0.20 |
| 突击步枪 | 3.5 | 900 | 0.25 |
| 狙击步枪 | 5.0 | 1100 | 0.35 |
| 轻机枪 | 8.0 | 1000 | 0.50 |

### D.2.4 持枪重量对移动速度的惩罚

```
speed_penalty = 1.0 - min(0.4, weapon_weight × 0.03)

// 3kg武器: 速度×0.91
// 5kg武器: 速度×0.85
// 8kg武器: 速度×0.76

```

### D.2.5 枪械待机晃动(呼吸摆动)与疲劳系统

**设计建议**：引入"持枪疲劳"概念，但不做完整的体力系统，避免过度复杂化。

**疲劳模型**：
```
fatigue_level = min(100, fatigue_level + fatigue_per_tick)

持续瞄准时：fatigue_per_tick = 0.05 × (weapon_weight / 3.0)
非瞄准时：fatigue_per_tick = -0.1（恢复）

疲劳对晃动的影响：
sway_amplitude = base_sway × (1 + fatigue_level / 50.0)

其中 base_sway:
- 趴下: 0.5
- 蹲下: 1.0
- 站立: 2.0
- 移动中: 4.0
```

**疲劳恢复**：放下武器/切换到非瞄准状态时，疲劳值以0.1/tick的速率恢复。

# E. 枪械状态机与故障(卡壳)系统

## E.1 现实原理简述

半自动/自动枪械的射击循环是一个精密的状态机，包含以下核心步骤：

1. **待发(Ready)**：枪机闭锁，弹匣中待供弹，击锤待击
2. **击发(Fire)**：扣扳机→击锤释放→击针撞击底火→弹药击发
3. **开锁(Unlock)**：膛压推动枪机/活塞→闭锁面脱离→枪机开锁
4. **抽壳(Extract)**：抽壳钩抓住弹壳底缘→枪机后拉→弹壳从膛内抽出
5. **抛壳(Eject)**：弹壳撞击抛壳挺→弹壳从抛壳口飞出
6. **复进(Feed)**：复进簧推动枪机前进→枪机从弹匣中推出下一发弹→推弹入膛
7. **闭锁(Lock)**：枪机闭锁面重新啮合→回到待发状态

任何一步失败都可能导致卡壳。历史上最著名的卡壳案例是越南战争初期的M16，由于弹药配方变更和缺乏清洁工具，导致大量卡壳故障，直接影响战场生存。

## E.2 游戏化抽象方案

### E.2.1 完整枪机循环状态机

**状态枚举**：

```java
public enum GunCycleState {
    EMPTY,           // 空仓挂机：弹匣空，枪机锁定后方
    READY,           // 待发：枪机闭锁，弹在膛内，等待扣扳机
    FIRING,          // 击发中：击针已撞击底火，等待膛压建立
    UNLOCKING,       // 开锁中：枪机正在开锁
    EXTRACTING,      // 抽壳中：枪机后拉，抽壳中
    EJECTING,        // 抛壳中：弹壳正在被抛出
    FEEDING,         // 供弹中：枪机前进，推送新弹入膛
    LOCKING,         // 闭锁中：枪机正在闭锁
    MALFUNCTION,     // 故障状态：卡壳/双重进弹等
    BOLT_OPEN,       // 枪机打开：手动拉栓/空仓挂机
    BOLT_CLOSE,      // 枪机闭锁：手动推栓到位
}
```

**合法状态转移表**：

| 当前状态 | 事件 | 目标状态 | 说明 |
|---------|------|---------|------|
| EMPTY | 装入弹匣 | READY | 空仓挂机后装入新弹匣 |
| READY | 扣扳机 | FIRING | 击发 |
| FIRING | 膛压建立 | UNLOCKING | 正常开锁 |
| FIRING | 底火未点燃 | MALFUNCTION(瞎火) | 哑弹/瞎火 |
| UNLOCKING | 完成 | EXTRACTING | 正常过渡 |
| EXTRACTING | 抽壳成功 | EJECTING | 正常过渡 |
| EXTRACTING | 抽壳失败 | MALFUNCTION(抽壳失败) | 故障 |
| EJECTING | 抛壳成功 | FEEDING | 正常过渡 |
| EJECTING | 抛壳失败 | MALFUNCTION(抛壳失败) | 烟囱/双重进弹 |
| FEEDING | 供弹成功 | LOCKING | 正常过渡 |
| FEEDING | 供弹失败 | MALFUNCTION(进弹失败) | 故障 |
| LOCKING | 完成 | READY | 回到待发 |
| MALFUNCTION | 清除故障 | EMPTY/READY | 取决于故障类型 |
| READY | 弹匣空 | EMPTY | 空仓挂机 |
| READY | 手动拉栓 | BOLT_OPEN | 检查膛内 |
| BOLT_OPEN | 手动推栓 | BOLT_CLOSE | 恢复 |

# F. 炸膛系统

## F.1 现实原理简述

炸膛(Catastrophic Failure)是枪械最严重的故障类型，发生在膛压超过枪管承受极限时。膛压过高导致枪管/机匣破裂，碎片和高压气体可能伤害射手。炸膛的主要原因包括：过压（超量装药/弹头卡管）、材料缺陷（公差差的枪管）、极端过热（烧蚀导致管壁变薄）、枪管内异物（泥沙/水/未清理的Squib弹头）。

## F.2 游戏化抽象方案

### F.2.1 触发条件汇总

| 触发条件 | 基础概率 | 修正因子 | 说明 |
|---------|---------|---------|------|
| 超量装药(120%) | 0.3%/发 | 装药量×1.5 | 过量装药累积风险 |
| 超量装药(150%) | 1.0%/发 | 装药量×2.0 | 严重过量装药 |
| 哑弹未清理继续射击 | 80%/发 | 枪管强度×0.5 | Squib后射击几乎必炸 |
| 枪管材料公差差 | 0.05%/发 | (100-tolerance)/100 | 公差越差风险越高 |
| 极端过热(>90%热量) | 0.2%/发 | heat_percentage×2 | 高温下材料强度下降 |
| 枪管进异物(泥沙) | 0.5%/发 | 异物量×3 | 沙漠/泥泞环境 |
| 枪管进水 | 1.0%/发 | 水量×5 | 水不可压缩，膛压骤增 |

### F.2.2 炸膛后果分级

| 等级 | 名称 | 后果 | 触发条件 |
|------|------|------|---------|
| 1 | 轻微炸膛 | 枪械精度永久下降20%，枪管耐久-50% | 超量装药/轻微过热 |
| 2 | 中等炸膛 | 枪管/枪机部件损毁，需更换部件 | Squib后射击/中等过热 |
| 3 | 严重炸膛 | 武器报废（不可修复），射手受到伤害（3-8点） | 极端过热/严重Squib/枪管进水 |

### F.2.3 炸膛概率模型

**加权判定模型**（游戏平衡用途）：
```
catastrophic_failure_score = 0

// 逐项检查
if (overcharge): catastrophic_failure_score += overcharge_risk
if (squib_in_barrel): catastrophic_failure_score += 80.0
if (barrel_contaminated): catastrophic_failure_score += contamination_risk
if (extreme_overheat): catastrophic_failure_score += overheat_risk
if (poor_tolerance): catastrophic_failure_score += tolerance_risk

// 综合概率
failure_probability = min(95%, catastrophic_failure_score × 0.01)

// 每次射击判定
if (random() < failure_probability):
    severity = determine_severity(catastrophic_failure_score)
    apply_catastrophic_failure(severity)
```

**严重度判定**：
```
if (score < 5): severity = 1 (轻微)
if (5 ≤ score < 20): severity = 2 (中等)
if (score ≥ 20): severity = 3 (严重)
```

# G. 过热系统

## G.1 现实原理简述

枪管在连续射击时积累热量，热量来源于发射药燃烧产生的高温高压气体。枪管温度上升导致：1）热膨胀改变枪管内径，影响精度（热浮动/热漂移）；2）枪管钢材强度下降，加速喉咙烧蚀(Erosion)；3）极端情况下，膛内温度足以引燃弹壳内的发射药（Cook-off/自燃）。

喉咙烧蚀是不可逆的永久性损伤：发射药高温气体和弹头摩擦共同作用，使枪管喉部（膛线起始处）的钢材逐渐被侵蚀，膛线变浅、膛径增大，导致精度持续下降。高初速、大口径、速射武器的烧蚀速度最快。

## G.2 游戏化抽象方案

### G.2.1 枪管温度累积模型

**TACZ已有的基础**：`GunHeatData`已定义了`heatMax`、`heatPerShot`、`coolingMultiplier`、`coolingDelay`等字段，`IGun`接口已提供`getHeatAmount()`/`setHeatAmount()`/`isOverheatLocked()`方法。

**扩展方案**：

```
// 每次射击后
heat_amount += heat_per_shot × powder_type_modifier × caliber_modifier

// 每tick冷却
if (time_since_last_shot > cooling_delay):
    heat_amount -= cooling_rate × cooling_multiplier × environment_modifier

powder_type_modifier:
- 黑火药: 1.5 (更多热量)
- 无烟火药: 1.0

caliber_modifier:
- 手枪弹: 0.5
- 步枪弹: 1.0
- 马格南弹: 1.5

environment_modifier:
- 正常: 1.0
- 水中: 3.0 (快速冷却)
- 沙漠: 0.7 (慢速冷却)
- 雨中: 1.5
```

### G.2.2 过热对精度的实时负面影响

**热浮动导致弹道散布增大**（游戏化模型）：

```
heat_inaccuracy = base_inaccuracy × (1 + heat_percentage × heat_inaccuracy_factor)

其中：
- heat_percentage = heat_amount / heat_max
- heat_inaccuracy_factor = 1.0 (默认，可通过JSON配置)

当 heat_percentage > 0.5 时，热浮动开始影响精度
当 heat_percentage > 0.8 时，影响显著
当 heat_percentage = 1.0 时，精度下降到原来的2倍
```

### G.2.3 长期过热的永久性精度衰减(枪管烧蚀)

**游戏化模型**：
```
erosion_accumulated += erosion_per_shot × (1 + heat_percentage × 2.0)

erosion_per_shot:
- 正常射击: 0.001
- 速射(全自动): 0.003
- 消音器使用: 0.002 (消音器增加膛压和温度)

当 erosion_accumulated 达到阈值时，精度永久下降：
- erosion 1-25: 精度-0%
- erosion 26-50: 精度-5%
- erosion 51-75: 精度-15%
- erosion 76-100: 精度-30%
- erosion > 100: 精度-50%，枪管需要更换
```

### G.2.4 速换枪管机制

**适用于机枪类武器**：

| 枪械类型 | 是否支持速换枪管 | 换枪管时间 | 说明 |
|---------|----------------|-----------|------|
| 手枪 | 否 | - | 枪管固定在机匣上 |
| 步枪 | 否（大部分） | - | 枪管固定 |
| 轻机枪 | 是 | 5秒 | 如M249/RPK |
| 通用机枪 | 是 | 4秒 | 如MG42/M60 |
| 重机枪 | 是 | 8秒 | 需要工具 |

**速换枪管交互**：在枪械改装界面中，选择"更换枪管"操作，如果枪械支持速换枪管，则可以直接替换过热的枪管为备用的冷枪管。

### G.2.5 【AI补充】炸膛风险随温度升高而增加

**设计建议**：**强烈建议实现此联动**。

**原因**：
1. 真实性：过热确实增加炸膛风险，这是枪械物理的基本事实
2. 游戏性：给玩家一个明确的"不要疯狂连射"的信号，形成有意义的风险-收益决策
3. 系统联动：过热系统与炸膛系统的联动是本模组"系统间相互关联"设计理念的体现

**实现方式**：
```
// 在过热系统的tick逻辑中，更新炸膛风险因子
if (heat_percentage > 0.7):
    catastrophic_failure_risk_bonus = (heat_percentage - 0.7) × 0.5
    // heat 80%: +5% 炸膛风险
    // heat 90%: +10% 炸膛风险
    // heat 100%: +15% 炸膛风险
```

**Cook-off（自燃）机制**：
```
if (heat_percentage > 0.85 AND has_round_in_chamber):
    cookoff_probability = (heat_percentage - 0.85) × 0.001 per tick
    // 约0.015%/tick → 在过热状态下，膛内弹约1秒后可能自燃
    // 这是"闭膛待击"武器的重大风险，"开膛待击"武器不受影响
```

# H. 保养与维护系统

## H.1 现实原理简述

枪械保养是确保武器可靠性的关键环节。现代军队的枪械保养流程包括：拆解→擦拭（清除积碳/铜屑）→润滑（涂抹CLP清洁润滑防护油）→重新组装。积碳是发射药燃烧的固体残留物，积聚在枪机/膛室内会影响循环可靠性。黑火药武器的积碳速率远高于无烟火药武器。

锈蚀是枪械的天敌，暴露在潮湿环境中会加速钢铁部件的氧化。军事标准要求枪械在潮湿环境中每日清洁和润滑。

环境因素对枪械可靠性影响巨大：沙尘环境（沙漠）会加速磨损和增加卡壳率；严寒环境会导致润滑油凝滞，影响自动循环速度。

# I. 模块化耐久系统

## I.1 现实原理简述

真实枪械的各部件有独立的磨损寿命：枪管喉咙烧蚀导致精度下降；复进簧疲劳导致循环不可靠；弹匣弹簧疲劳导致供弹不畅；撞针磨损导致击发失败。现代军队维护枪械的方式是更换磨损部件，而非丢弃整把枪。

## I.2 游戏化抽象方案

### I.2.1 独立部件耐久列表

| 部件 | ID | 基础耐久 | 磨损影响 | 磨损速率 |
|------|-----|---------|---------|---------|
| 枪管 | `barrel` | 5000发 | 精度↓/烧蚀↑ | 1/发 |
| 机匣 | `receiver` | 20000发 | 可靠性↓ | 0.1/发 |
| 枪机 | `bolt` | 10000发 | 闭锁可靠性↓/卡壳↑ | 0.5/发 |
| 复进簧 | `recoil_spring` | 5000发 | 循环速度↓/抛壳失败↑ | 1/发 |
| 弹匣弹簧 | `magazine_spring` | 2000发 | 供弹失败↑ | 1/发（每次装弹循环） |
| 扳机组 | `trigger_group` | 15000发 | 击发可靠性↓/瞎火↑ | 0.3/发 |
| 枪口装置 | `muzzle_device` | 8000发 | 消音/制退效果↓ | 0.5/发（消音器更快） |

### I.2.2 部件耐久对整体可靠性/精度的加权影响公式

```
overall_reliability = 1.0
overall_accuracy = 1.0

for each component:
    wear_ratio = 1.0 - (current_durability / max_durability)
    reliability_modifier = 1.0 - (wear_ratio × component_reliability_weight)
    accuracy_modifier = 1.0 - (wear_ratio × component_accuracy_weight)
    overall_reliability *= reliability_modifier
    overall_accuracy *= accuracy_modifier

权重分配：
| 部件 | 可靠性权重 | 精度权重 |
|------|-----------|---------|
| 枪管 | 0.10 | 0.40 |
| 机匣 | 0.20 | 0.10 |
| 枪机 | 0.30 | 0.15 |
| 复进簧 | 0.20 | 0.05 |
| 弹匣弹簧 | 0.15 | 0.00 |
| 扳机组 | 0.05 | 0.05 |
| 枪口装置 | 0.00 | 0.25 |
```

### I.2.3 弹簧疲劳机制

**游戏化模型**：
```
spring_wear = cycles × wear_rate × (1 + heat_modifier)

recoil_spring_wear_rate = 0.001 per cycle
magazine_spring_wear_rate = 0.002 per load/unload cycle

弹簧疲劳影响：
- 复进簧疲劳度 > 30%: 循环速度-5%
- 复进簧疲劳度 > 60%: 抛壳失败概率+1%
- 复进簧疲劳度 > 90%: 循环不可靠，频繁卡壳

- 弹匣弹簧疲劳度 > 30%: 最后3发供弹不畅
- 弹匣弹簧疲劳度 > 60%: 最后5发供弹失败概率+2%
- 弹匣弹簧疲劳度 > 90%: 弹匣几乎不可用
```

### I.2.4 部件维修/更换体系

| 维修方式 | 适用条件 | 所需工具 | 效果 |
|---------|---------|---------|------|
| 现场保养 | 磨损度<30% | 保养套装 | 恢复10%耐久 |
| 工作台修复 | 磨损度30-70% | 对应阶段枪匠台+材料 | 恢复50%耐久 |

### I.4.1 模块化耐久数据（枪械NBT扩展）

# J. 模块化改装系统

## J.1 现实原理简述

现代枪械的模块化设计允许射手根据任务需求更换不同部件。导轨系统（如MIL-STD-1913皮卡汀尼导轨、M-LOK、KeyMod）是配件安装的标准化接口，不同枪型的导轨标准不同，配件不能无脑通用。

瞄具归零(Zeroing)是调整瞄具使其在特定距离上与弹道落点对齐的过程。不同距离需要不同的归零点，否则弹着点会偏离瞄准点。

消音器(Suppressor)通过内部挡片减速和冷却膨胀气体来降低声音特征，但亚音速弹药配合消音器才能达到最佳效果。消音器内部挡片随使用次数烧蚀，消音效果逐渐衰减。

### J.2.3 瞄具归零(Zeroing)机制

```

if (归零距离 == 实际距离): 偏差=0，完美命中
if (实际距离 > 归零距离): 弹着点偏低（需抬枪）
if (实际距离 < 归零距离): 弹着点偏高（需压枪）

偏差量（游戏化）：
- 偏差50m: 约0.5°角度偏差
- 偏差100m: 约1.2°角度偏差
- 偏差200m: 约3.0°角度偏差
```

# K. 声学与隐蔽系统

## K.1 现实原理简述

枪声是射击时最显著的特征之一，其传播距离受口径、枪管长度、消音器、弹药类型等因素影响。大口径步枪的声音传播距离可达数公里，而亚音速弹药配合消音器可将声音降低到难以辨识的水平。声音传播在战术环境中直接影响敌对单位的警觉判定。

## K.2 游戏化抽象方案

### K.2.1 不同口径/消音状态的声音传播范围模型

| 口径类型 | 无消音器传播距离(格) | 有消音器传播距离(格) | 亚音速+消音器(格) |
|---------|-------------------|-------------------|------------------|
| .22LR | 24 | 12 | 6 |
| 9mm | 40 | 20 | 10 |
| 5.56mm | 56 | 32 | 16 |
| 7.62mm | 64 | 36 | 16 |
| .50BMG | 80 | 48 | 24 |

**声音传播衰减模型**：
```
sound_level = base_sound_level × (1 - distance / max_distance) × environment_modifier

当 sound_level > alert_threshold 时，敌对单位被惊动
alert_threshold: 0.3 (30%声音强度)

environment_modifier:
- 开阔地: 1.0
- 森林: 0.8 (树木吸收)
- 室内: 1.3 (回声)
- 水下: 0.3 (声音传播方式不同)
```

### K.2.2 亚音速弹+消音器组合的"隐蔽射击"判定阈值

**游戏化模型**：
```
stealth_rating = 100 × (1 - sound_level / alert_threshold)

if (stealth_rating > 70): "完全隐蔽"——敌对单位无法侦测
if (stealth_rating > 30): "部分隐蔽"——敌对单位有30%概率侦测
if (stealth_rating ≤ 30): "暴露"——敌对单位100%侦测

亚音速+消音器组合的典型stealth_rating: 85-95（完全隐蔽）
超音速+消音器: 50-65（部分隐蔽）
无消音器: 0-15（暴露）
```

## K.3 所需道具/机器/工作台清单

无需新增道具，声学系统是纯逻辑系统。

## K.4 数据结构建议

### K.4.1 声学数据（枪械JSON扩展）

```json
{
  "acoustics": {
    "base_sound_distance": 64,
    "sound_type": "rifle",
    "suppressed_sound_distance": 36,
    "muzzle_blast_volume": 1.0
  }
}
```

## K.5 与TACZ现有系统的衔接方式

1. **声音系统**：TACZ已有`SilenceModifier`和`GunProperties.SILENCE`，提供了声音传播距离和是否使用消音器音效的配置。扩展此系统加入更细致的声音传播模型。

2. **声音传播**：在射击时，根据声音传播距离向周围生物发送"警觉"事件。需要修改`EntityKineticBullet`或`AbstractGunItem.shoot()`中的声音播放逻辑。

3. **隐蔽判定**：新增AI事件系统，当枪声传播到敌对单位时，根据距离和声音强度判定是否警觉。

### M.2.2 动力中断对生产线的影响

**设计原则**：断电即停产，不允许"离线也生产"。

| 场景 | 影响 | 恢复方式 |
|------|------|---------|
| SU供应不足 | 机器减速（按比例），加工时间延长 | 增加动力源 |
| 完全断电 | 所有机器停止，加工进度冻结 | 恢复动力供应 |
| SU波动 | 影响公差评分（波动越大，公差越差） | 使用齿轮箱稳速 |

**SU波动对公差的影响**：
```
su_stability = 1.0 - (su_variance / average_su) × 0.5

tolerance_modifier = su_stability

// 10%波动: modifier = 0.95 (公差-5)
// 30%波动: modifier = 0.85 (公差-15)
// 50%波动: modifier = 0.75 (公差-25)
```

| 物流环节 | Create组件 | 对接方式 | 说明 |
|---------|-----------|---------|------|

**机器与Create组件的接口**：

## N.1 供弹具机构差异化系统

### N.1.1 现实原理简述

不同类型的供弹具在结构、容量、换弹方式、可靠性方面有根本性差异。将所有供弹具简化为同一套"弹匣"代码是很多枪械模组的不专业之处。

### N.1.2 游戏化抽象方案

**供弹具类型枚举**：

| 供弹具类型 | ID | 特征 | 容量 | 换弹方式 | 可靠性 |
|-----------|-----|------|------|---------|--------|
| 转轮弹巢 | `cylinder` | 固定在枪上，不可拆卸 | 5-8发 | 逐个装弹/快速装弹器 | 极高 |
| 管状弹仓 | `tubular_magazine` | 固定在枪管下方 | 4-8发 | 逐发从装弹口塞入 | 高 |
| 桥夹固定弹仓 | `stripper_clip_internal` | 固定在枪内，用桥 clip压入 | 5-10发 | 桥夹压入→弹仓→逐发供弹 | 高 |
| 可拆卸弹匣 | `detachable_magazine` | 可从枪上取下 | 10-30发 | 拔出旧弹匣→插入新弹匣 | 中 |
| 漏夹 | `en_bloc_clip` | 弹夹整体插入弹仓 | 5-8发 | 整体插入→弹仓→空夹弹出 | 中 |
| 弹链 | `belt` | 金属/布弹链 | 50-200发 | 更换弹链箱 | 低（需润滑） |
| 弹鼓 | `drum_magazine` | 大容量可拆卸 | 50-100发 | 拔出→插入（笨重） | 低（弹簧疲劳快） |

### N.1.3 各供弹具的独立数据结构

## N.2 扳机组细节系统

### N.2.1 现实原理简述

扳机组是枪械的击发控制核心，分为单动(Single Action)和双动(Double Action)两种基本类型。单动扳机仅释放击锤，需手动待击；双动扳机同时待击和释放击锤。扳机拉力(Trigger Pull Weight)直接影响射击精度——过重的扳机拉力会导致射手在扣扳机时产生偏移。

### N.2.2 游戏化抽象方案

| 扳机类型 | ID | 击发方式 | 扳机拉力 | 射击稳定性影响 |
|---------|-----|---------|---------|-------------|
| 单动 | `single_action` | 手动待击→扣扳机→击发 | 轻(2-3磅) | 精度+5% |
| 双动 | `double_action` | 扣扳机→自动待击+击发 | 重(8-12磅) | 精度-5% |
| 双动/单动 | `da_sa` | 首发双动，后续单动 | 首发重→后续轻 | 首发精度-5%，后续+5% |
| 双动仅 | `dao` | 每次都是双动 | 重(8-12磅) | 精度-5% |

**游戏化影响**：
- 扳机拉力影响"瞄准偏移"：扣扳机时准星会有微小偏移
- 单动扳机：偏移小（±0.5°）
- 双动扳机：偏移大（±2.0°）
- 双动/单动：首发偏移大，后续偏移小

## N.3 武器重量与人体工学对整体战斗节奏的系统性影响

### N.3.1 现实原理简述

武器重量是影响步兵战术的核心因素。轻武器(手枪/冲锋枪)允许快速移动和快速瞄准，但牺牲了射程和精度；重武器(机枪/狙击步枪)提供火力和精度，但严重限制机动性。现代步兵装备的"人体工学"设计（握把角度、枪托形状、重心位置）直接影响射击舒适度和疲劳速率。

### N.3.2 游戏化抽象方案

**重心位置系统**（游戏化抽象）：

| 重心位置 | 瞄准偏移 | 疲劳速率 | 换弹速度 | 说明 |
|---------|---------|---------|---------|------|
| 前重(枪管重) | 上抬趋势 | ×1.3 | ×1.0 | 典型如MG42、RPK |
| 均衡 | 中性 | ×1.0 | ×1.0 | 典型如M4、AK-74 |
| 后重(机匣重) | 下压趋势 | ×0.8 | ×1.1 | 典型如MP5、手枪 |

**整体战斗节奏影响矩阵**：

| 武器类型 | 重量(kg) | 移动速度 | ADS时间 | 换弹时间 | 持续射击时间 | 疲劳速率 |
|---------|---------|---------|---------|---------|------------|---------|
| 手枪 | 0.8 | ×1.0 | 0.15s | 1.5s | 无限 | ×0.5 |
| 冲锋枪 | 3.0 | ×0.95 | 0.20s | 2.0s | 无限 | ×0.8 |
| 突击步枪 | 3.5 | ×0.90 | 0.25s | 2.5s | 30秒 | ×1.0 |
| 狙击步枪 | 5.0 | ×0.85 | 0.35s | 3.0s | 15秒 | ×1.5 |
| 轻机枪 | 8.0 | ×0.75 | 0.50s | 5.0s | 60秒 | ×2.0 |
| 重机枪 | 15.0 | ×0.60 | 0.80s | 8.0s | 120秒 | ×3.0 |

## N.4 其他遗漏但重要的机制

### N.4.1 【AI补充】武器保险/安全机制

**现实原理**：枪械保险是防止误触发的安全机制。不同枪械的保险位置和操作方式不同。

**游戏化**：
- 枪械有"保险"状态，保险状态下无法射击
- 按特定键切换保险状态，切换时间0.5秒
- 不同保险类型（拇指保险/握把保险/拨片保险）有不同的切换动画

### N.4.2 【AI补充】枪口焰/闪光效果

**现实原理**：射击时枪口产生的火焰是暴露射手位置的重要因素。

**游戏化**：
- 黑火药：大型枪口焰，夜间可见距离80格
- 无烟火药+无消音器：小型枪口焰，夜间可见距离30格
- 消音器：几乎无枪口焰
- 枪口焰可被AI用于"定位射手"判定

### N.4.3 【AI补充】空仓挂机/最后一发提示

**现实原理**：大多数现代半自动/自动武器在弹匣打空后，枪机锁定在后方（空仓挂机），提示射手需要换弹。

**游戏化**：
- 弹匣打空时，枪机锁定后方
- 换弹后需要按"拉机柄"键才能上膛（不同于TACZ现有的自动上膛）
- 这是"闭膛待击"武器的标准行为，"开膛待击"武器无此机制

### N.4.4 【AI补充】弹壳抛出方向和位置

**现实原理**：不同枪械的抛壳方向和抛壳距离不同，影响弹壳回收的便利性。

**游戏化**：
- 弹壳从抛壳口飞出，有物理轨迹
- 可用于"弹壳回收"——复装系统的前置步骤
- 弹壳在地面3分钟后消失（可配置）

### N.4.5 【AI补充】枪械磨损的可视化反馈

**游戏化**：
- 枪械HUD上显示关键部件的磨损状态（颜色编码：绿/黄/红/黑）
- 检查枪械时显示各部件的详细耐久状态
- 严重磨损的枪械在射击时有视觉/音效反馈（如金属摩擦声）
