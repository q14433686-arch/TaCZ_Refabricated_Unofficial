## 1. 判定依据（静态读码，逐条可复核）

### 1.1 本线的裁剪机制与「掩码纪元」无关

本线是 `DepthCopyRenderType` + `ScopeDepthCopyState`：draw 时把 `tacz_ScopeMaskMode` 打到 2，
片元用「世界深度备份 + 目镜孔径深度拷贝」判 `apertureDepth < worldDepth - eps` 丢弃
（`scope_flash_clip.fsh` 是 vanilla `entity.fsh` 的逐字克隆 + 前置掩码）。已经用这套裁了：

| 已裁 | 入口 |
|---|---|
| 枪身 | `BedrockGunModel:336` → `clipForViewmodel` |
| 配件 | `AttachmentRender:60` → `clipForViewmodel` |
| 枪口火光（背景层 + 辉光涡旋） | `MuzzleFlashRender:99/102` → `flashTranslucentClipped` / `flashSwirlClipped` |
| 镜内文字 | `ScopeTextSubmitter` → `maskedText`（反语义 MASK） |
| mesh GPU 枪身 | `PolyMeshGpuRenderer` → `mesh_entity_scope_clip` |

**不裁的只有手臂**（`LeftHandRender` / `RightHandRender` → `RenderHelper.renderFirstPersonArm`）。

### 1.2 与 26.2 的对照：同类，不是同物

| | 26.2（掩码纪元） | 26.1.2（深度孔径纪元） |
|---|---|---|
| 载体 | `ScopeBodyRenderTypes.armClipped(skin)`，复用 `FLASH_TRANSLUCENT_CLIPPED_PIPELINE` | 直接复用 `ScopeRenderTypes.flashTranslucentClipped(skin)`（本就是 `entityTranslucent` + 孔径 discard） |
| 掩码来源 | `SCOPE_MASK` 采样器 + `ScopeMaskTextureHandle` | 两份私有深度拷贝（`ScopeDepthCopyState`，`Operation.MASK_OUTSIDE`） |
| 闸门 | `maskReadyForViewmodel(true)`，submit-task 期 | `hasScheduledViewmodelAperture()`，extract 期（与火光一致） |
| 换 RenderType 的手法 | `SubmitNodeCollector` 动态代理 | 同（手臂的 RenderType 是 `AvatarRenderer` 内部挑的，调用点换不到） |

26.2 复用火光管线的理由写在他们的注释里：「火光与手臂在管线状态上无差别（同 blend、同 snippet、
同 define）」—— 本线这条管线**连 `affectsCrumbling() + sortOnUpload()` 都已齐**
（`ScopeRenderTypes#createFlashTranslucentType`，26.2 是为手臂才补的这两项），
且已登记给 Iris 的 `HAND_TRANSLUCENT`（`scope_flash_translucent`）。

## 2. 两种 PIP 与整屏变焦 —— 三种模式结论不同（关键）

合成走 `ScopePipRenderState#compositeScene`：`createRenderPass(..., main.getColorTextureView(),
OptionalInt.empty())` —— **没有深度附着**，管线是 `ColorTargetState(Optional.empty(), WRITE_COLOR)`
（无混合、全色写），片元只在 `ad < wd - eps`（镜孔内）取样上屏 ⇒ **镜孔区域是无条件整片覆写**。

| 模式 | 合成是否运行 | 手臂会不会挡镜 | 本轮前 | 本轮后 |
|---|---|---|---|---|
| **PIP 重投影**（`ScopePipRenderState`，默认） | 是（`compositeAfterHand`，无深度整片覆写） | **不会** —— 被镜内画面盖掉 | 无缺口 | 无变化（裁了也看不出） |
| **PIP 二次渲染**（`ScopePipRerender`） | 是（窄遍画好后同样走 `compositeScene`；窄遍里手不参与） | **不会** | 无缺口 | 无变化 |
| **光影下 PIP**（`compositeAfterIrisFinal`） | 是（Iris final 之后，同一 `compositeScene`） | **不会** | 无缺口 | 无变化 |
| **经典整屏变焦**：PIP 关 / 倍率 < `ScopePipMinMagnification` / 光影下未 opt-in / PIP 失败回退 / 开镜进度 < `PIP_REVEAL_THRESHOLD` 的过渡帧 / 掩码周期不成立（`hasMaskCycleThisFrame()` 假，合成 fail-closed） | **否** | **会** —— 手臂挡在目镜里 | **这是真缺口**（枪身、火光都裁了，唯独手臂没裁） | 已裁 |

⇒ 26.2 那句 "blocking the see-through/PIP picture" 对本线**只对一半**：
"PIP picture" 那半不成立（合成覆盖），"see-through"（整屏变焦）那半成立。

## 3. 实现

| 文件 | 改动 |
|---|---|
| `com/tacz/guns/util/RenderHelper.java` | 新增带 `clipToScopeExterior` 的重载；`wrapForScopeClip()` 用 `SubmitNodeCollector` 动态代理把穿过来的 `entityTranslucent(skin)` 换成 `flashTranslucentClipped(skin)`；两条 log-once（成功 `engaged` / 失败 `unavailable`） |
| `com/tacz/guns/client/model/functional/LeftHandRender.java` | extract 期算闸门并传入 |
| `com/tacz/guns/client/model/functional/RightHandRender.java` | 同上 |

**为什么用代理**：手臂的 RenderType 是 `AvatarRenderer#renderLeftHand/renderRightHand` **内部**挑的
（`submitModelPart(arm, pose, RenderTypes.entityTranslucent(skin), ..)`），调用点换不到；
复刻提交就得复刻 vanilla 那串模型状态整备（resetPose / 袖层可见性 / 手臂显隐），版本一动就烂。
代理让 vanilla 逻辑原样跑完，只在提交穿过时换掉 RenderType。

**失败哲学**（与枪身/火光/文字一致）：闸门为假、`SubmitNodeCollector` 不是接口、代理构造抛异常 ——
一律**返回真 collector**，最坏回到「镜内见手臂」的现状，绝不画错手臂。

## 4. 实机验收清单（**本沙箱无运行环境，全部未验**）

1. 装高倍镜、**关掉 PIP**（或把倍率压到 `ScopePipMinMagnification` 以下）→ 开镜：目镜圈内
   **不应出现手臂/袖子**（枪身与火光本来就是裁的，作对照组）。
2. 打开 PIP（重投影 / 二次渲染各一遍）→ 与改动前**一致**，不得出现新瑕疵。
3. 日志：应出现一次 `[TACZ Scope] In-scope arm clipping engaged: ...`。
   若出现 `unavailable` → 代理没建成，行为等同现状（不崩）。
4. 低倍镜 / 无瞄具 / 关镜状态 → 手臂完全正常（闸门为假时走原 collector）。
5. 装 PlayerAnimator / NEA → 手臂与袖层不错序、不缺件。
6. 光影下 → 手臂按 `HAND_TRANSLUCENT` 程序走，无黑臂、无错序。

## 5. 未验项与已知风险（AGENTS §2：不夸大）

- **`RenderTypes.entityTranslucent` 是否按贴图 memoize**：这是 26.2 侧的**字节码实读**结论，
  本线没有 `javap` 复核（沙箱无 Java 工具链）。**若未 memoize，identity 比较永不命中 ⇒ 效果等于没做**，
  且不报错、不崩 —— 注意：此时**日志仍会打 `engaged`**（代理建成 ≠ 真的裁掉了）。
  这是实机第 1 条要盯的点：日志有了但目镜里还有手，就是这一处。
- **`SubmitNodeCollector` 是接口**：由 `docs/SCOPE_FINAL_OVERLAY_BACKPORT_26_1_2_2026_08_30.md:48`
  （「`SubmitNodeStorage` … `implements SubmitNodeCollector` ✓」）证实；另加运行期 `isInterface()` 兜底。
- **每帧两次手臂提交的反射开销未测**（26.2 评估为可忽略）。
- **双持 / 副手边界**：闸门在 extract 期取值，同一 flush 里后一把枪的目镜状态会覆盖前一把的判定
  （极端边界，未验；最坏是某一只手不裁，回到现状）。
