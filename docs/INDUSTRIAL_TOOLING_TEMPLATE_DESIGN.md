# 平台工装模板、动作夹具与旧式枪械工艺

## 目的

`gun_blueprint` 不再由甜浆果、末影珍珠、金粒等无关物品直接“合成出某型号”。这类物品此前只是在静态 JSON 中充当型号选择器，并不代表任何可测绘、可复制或可校准的工艺来源。

现在同一个 NBT 工装介质分成明确的三层：

1. **原始工艺档案（Master Manufacturing Dossier）**：世界战利品、武器匠来源，或以一把实际样枪测绘得到；
2. **平台工装模板（Platform Tooling Template）**：由档案转印、或由另一张生产模板复制得到；用于校准模具和量规；
3. **实际工装**：组件冲压模、动作族夹具、关键配合量规和最终验收检具；它们才进入量产线。

这不是把一张“蓝图”改名。平台模板不再作为成枪流水线的一个部署材料；它只在**建线**时建立模具/检具身份。成枪流水线从已经成型的机匣或枪身工件开始，因此校准完成后能够真实量产。

## 物理流程

```text
纸张 + 黑色染料 + 黄铜板
→ Basin 压实
→ 空白工装页

空白工装页 + 原始工艺档案（部署工位持有，不消耗）
→ 平台工装模板

空白工装页 + 已有平台工装模板（部署工位持有，不消耗）
→ 复制的平台工装模板

空白工装页 + 实际样枪（部署工位持有，不消耗）
→ 原始工艺档案
```

- 多种原料只在 Basin 中组成空白工装页；
- 传送带／置物台上始终只有一张空白工装页；
- 档案、模板或样枪位于供料／部署工位，不会成为第二个置物台工件；
- 成品身份来自档案或实际 `GunId` 样枪，不来自任意“种子材料”。

默认枪包的每个平台都有 `survey_dossier_<platform>` 配方。因此捡到、交易到或保留的一把真实样枪可以被测绘；这不是让玩家在游戏外运行 Python。

## 模板在何处强制使用

| 环节 | 是否强制平台模板 | 原因 |
| --- | --- | --- |
| 钢材、枪管毛坯、外装毛坯 | 否 | 这些仍是通用材料／中性毛坯工艺。 |
| 组件冲压模校准 | 是 | 平台身份在这里被写入可重复使用的模具。 |
| 外装套件校准 | 是 | 中性木材／皮革／黄铜毛坯在这里成为命名套件。 |
| 简单动作的最终配合 | 使用动作族夹具 | 不把纸质模板塞进成枪，但仍要求真实夹具。 |
| 栓动、转轮、泵动、旧式闭锁手枪 | 使用动作夹具 + 平台关键配合量规 | 枪膛间隙、转轮定时、闭锁／滑套配合不能省略。 |
| advanced / precision 成枪 | 使用动作夹具 + 平台最终验收检具 | 成枪必须通过最终平台检验。 |

因此答案不是“每一步都强制模板”，而是：**模板强制参与建线；夹具和量规强制参与关键配合与验收。**

## 动作档案与工装范围

每个默认平台声明两个独立字段：

```json
{
  "manufacturing_tier": "legacy",
  "action_profile": "break_action",
  "tooling_scope": "family_jig"
}
```

- `manufacturing_tier` 决定资料取得和探索／交易层级；
- `action_profile` 决定实际动作机构、动作夹具、部件语义；
- `tooling_scope` 决定模板在何处形成强制门槛。

有效范围为：

| `tooling_scope` | 实际含义 |
| --- | --- |
| `family_jig` | 用可复用动作族夹具完成最终配合；适用于真正简单的折管／杠杆动作。 |
| `critical_gauge` | 还必须用平台关键配合量规；适用于栓动、转轮、泵动、闭锁手枪。 |
| `platform_tooling` | 模板仅强制用于上游专用模具／外装工装校准；量产终端不再直接部署模板。 |
| `final_acceptance` | 除工装校准外，成枪必须经过平台最终验收检具。 |

最终验收检具不复用普通模具体：它先由高碳钢板、黄铜板、钻石和回响碎片在**机械合成器**形成“精密验收检具料坯”，再通过动作夹具选择空白，再由平台模板校准。这样 `critical_gauge` 与 `final_acceptance` 不会共享同一组 Create 输入而产生配方碰撞，也给精密武器留下真实的额外工装成本。

## 默认老式／简单路线

老旧不自动等于低精度。以下是当前默认包的明确处理：

| 平台 | 动作档案 | 范围 | 成品部件语义 |
| --- | --- | --- | --- |
| DB Long / DB Short | `break_action` | `family_jig` | 折管机匣、铰链闭锁组、双枪管组、双扳机击发组、护木／退壳组件。 |
| Springfield 1873 | `lever_action` | `family_jig` | 杠杆机匣、杠杆闭锁组、枪膛枪管、阻铁击发组、管式弹仓。 |
| Kar98 | `bolt_action` | `critical_gauge` | 栓动机匣、枪机／抽壳组、已校准枪膛枪管、阻铁击发组、枪托座／后坐凸笋。 |
| Rhino 357 / Taurus 500 | `revolver` | `critical_gauge` | 转轮枪身、转轮／摆臂、过渡锥枪管、定时锁件、握把框架。 |
| M870 | `pump_action` | `critical_gauge` | 泵动机匣、滑套枪机、霰弹枪管、泵动连杆／护木、管式弹仓。 |
| M1911 | `locked_breech_pistol` | `critical_gauge` | 它是旧式平台，但仍需套筒—枪管闭锁与复进组件的关键配合，不被错误地降级成折管枪难度。 |

动作名称和中性毛坯类别是分开的。比如“铰链闭锁组”可以从中性枪机类钢坯加工，但它在配方、提示和回收声明中不再被伪称为一组枪机。

## 旧存档兼容

旧世界已有的平台蓝图通常只有：

```text
IndustryPlatform
IndustryPartKind = blueprint
IndustryDisplayName = item.tacz.gun_blueprint.<platform>
```

它们不会失效。玩家用一张新的空白工装页，将旧版蓝图放在部署工位，即可通过 `restore_template_<platform>` 转成新的生产工装模板。之后所有新模具／量规配方使用新模板。已存在的旧组件模具仍可继续冲压：组件成型配方故意只匹配其稳定的平台、部件和显示身份，不要求新加的动作档案元数据。

## JEI / REI 配方树

组件毛坯、已校准模具、最终组件、工装页、档案、模板、动作夹具和量规都不是只写入 JSON 后依赖查看器“碰巧识别”。`IndustryProcessManager` 将实际 `data/*/recipe/create/**` 配方投影为同步的工业工艺数据：

- **JEI** 注册每种 Create 工位的 `tacz:industry/<machine>` 分类，并在服务器枪包数据同步到客户端后补充对应的工艺定义；
- **REI** 使用实时 display generator，在玩家查看某个具体 NBT 模具／组件的“配方”或“用途”时才读取已同步缓存，因此不会因 REI 插件早于服务器同步初始化而得到永久空列表；
- 组件模 → 组件、样枪 → 原始档案、档案 → 模板、模板 → 模具／量规都应能从任意一端反查。

组件模和组件的 `IndustryPlatform + IndustryPartKind + IndustryDisplayName + DieTargetKind` 是稳定物理身份；`IndustryActionProfile` / `IndustryToolingScope` 是模板、量规和总装声明上的来源元数据，不再额外写入组件模或组件成品。否则“校准模具输出”与“成型配方输入”为兼容旧存档而使用不同 NBT，会在 JEI/REI 中被误认成两件不同物品，造成链条断裂。

如果查看器仍没有显示，请先确认服务端日志存在类似：

```text
Loaded <n> TACZ Create process(es) for JEI/REI recipe-viewer synchronization.
```

`<n> = 0` 通常表示服务器没有启用 `CREATE_FLY` 工业档，或 Create Fly 没有实际加载；这不是缺少某一张组件配方。

Create Fly 26.2 原生 JEI 的顺序装配视图只有 **7 个**阶段格；第 8 个阶段会触发其内部罗马数字数组越界。所有默认终端线因此由生成器硬性限制为不超过 7 个真实阶段，而不是只在 UI 中截断：

- `platform_tooling`：五次真实子总成部署，保留枪管配合和最终外装配合两次冲压；
- `family_jig`：五次子总成部署 + 动作夹具 + 最终压配；
- `critical_gauge` / `final_acceptance`：动作夹具先在**上游**选择量规毛坯，终端部署五个子总成、外装套件和已校准平台量规，再做最终压配。

这样不会重新把模板塞进终端线，也不会以隐藏工序换取不崩溃的假象；每个被省出的终端阶段都对应已经单独存在且可在查看器中反查的上游夹具／量规工序。

## 数据驱动入口

- `tools/industry/default_gun_policy.json`
  - `process_profiles`：动作部件语义、动作夹具机械合成器布局；
  - `action_profile_by_gun_type` / `action_profile_overrides`：默认包动作分配；
  - `tooling_scope_overrides`：需要显式例外的工装范围；
- `tools/industry/platforms/*.json`
  - 手调平台可声明自己的 `action_profile`、`tooling_scope` 和真实部件名；
- `data/tacz/industry/assembly/gun/*.json`
  - 运行时可审计的成枪动作档案、工装范围、部件与中性毛坯类别。

生成器会拒绝同一 Basin、机械合成器或部署输入导向不同输出的 Create 配方冲突，并检查：生产模板必须来自“空白工装页 + 原始档案”、组件模必须要求生产模板、终端线不能部署原始模板、以及需要夹具／量规的范围确实在终端线中出现。

第三方未知枪械的通用工业材料门槛仍由运行时自动发现器处理。对未知 `GunId` 的完整“样枪测绘 → NBT 档案”界面／机器还需要单独的运行时解析工位；本设计先为其保留了与默认包相同的模板、动作档案和工装数据契约，而不把一个假静态配方冒充成第三方支持。
