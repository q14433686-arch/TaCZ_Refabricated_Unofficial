## 二、A：删除假 MAE stub，打包真实 MAE 1.1.1（应做）

### 现状证据

26.1.2 的 `build.gradle` 已声明：

```groovy
implementation("com.maydaymemory:mae:1.1.1")
```

但源码又定义了同二进制名：

```text
src/main/java/com/maydaymemory/mae/basic/Pose.java
src/main/java/com/maydaymemory/mae/basic/DummyPose.java
```

本地 `Pose` 是空接口；真实 MAE 1.1.1 的 `Pose` 有：

```java
Iterable<BoneTransform> getBoneTransforms();
```

源码类会覆盖 classpath 同名依赖，形成潜在 `AbstractMethodError`/ABI 分叉。所谓“MAE 在
26.1.2 不可用”也是假注释：它是纯 Java 动画库，项目本来就在解析该 Maven 坐标。

### 改法

1. `build.gradle` 改成 nested dependency：

```groovy
implementation(include("com.maydaymemory:mae:1.1.1")) {
    exclude group: 'com.google.code.findbugs', module: 'jsr305'
    exclude group: 'it.unimi.dsi', module: 'fastutil'
    exclude group: 'org.joml', module: 'joml'
}
```

2. 删除上面两个同包名源码文件。
3. 保留 SimpleBedrockModel 的两个最小 ABI 接口：
   `IFPAnimationInstance` / `IFPGeoItemRenderer`。它们不是要删的对象；只需把注释从
   “stub”改成“active minimal ABI replacement”。
4. 添加 MAE MIT 许可：

```text
src/main/resources/META-INF/licenses/MAE-LICENSE.txt
```

许可原文来自 `286799714/MaydayAnimationEngine`：Copyright (c) 2024 MaydayMemory。
若 26.1.2 没有 `LICENSES.md`，可新增或在 README Third-party libraries 里登记。

### 验证

```bash
./gradlew clean build
unzip -l build/libs/*.jar | grep -E 'META-INF/jars/.*mae|MAE-LICENSE'
```

并确认源码树已不存在 `com/maydaymemory/mae/basic/{Pose,DummyPose}.java`。

## 三、B1：弹药盒染色——26.2/26.1.2 不能只补 `dyeable` tag（应做）

### 为什么

上游 1.21.1 带 `data/minecraft/tags/item/dyeable.json`，但 26.1.x/26.2 的 vanilla 已把
染色改成逐物品 `minecraft:crafting_dye` 数据配方。弹药盒模型虽已声明
`minecraft:dye` tint，当前 26.1.2 没有匹配它的染色 recipe，因此无法在工作台染色。

### 新增文件 1：兼容 tag

`src/main/resources/data/minecraft/tags/item/dyeable.json`

```json
{
  "replace": false,
  "values": ["tacz:ammo_box"]
}
```

### 新增文件 2：真正生效的 26.1.2 染色配方

`src/main/resources/data/tacz/recipe/ammo_box_dyed.json`

```json
{
  "type": "minecraft:crafting_dye",
  "dye": "#minecraft:dyes",
  "group": "dyed_ammo_box",
  "result": {"id": "tacz:ammo_box"},
  "target": "tacz:ammo_box"
}
```

### 动手前的 26.1.2 字节码确认

不要因为 26.2 可用就直接假定。用 26.1.2 merged jar 核对 `DyeRecipe`：

- codec 字段仍为 `target / dye / result`；
- `assemble` 仍经 `TransmuteRecipe.createWithOriginalComponents` 保留原弹药盒的
  AmmoId、Level、count 等组件；
- 最后只覆盖 `DataComponents.DYED_COLOR`。

若三条成立，上述 JSON 可原样使用。

### 验证

- 铁/金/钻石弹药盒分别与任意染料合成；
- AmmoId、内部弹量、等级不丢；
- 物品模型颜色变化，9 个开/关/创造变体仍正常。

## 四、B2：恢复 Blood Strike 专属画，而不是普通随机画（应做，但按 26.1.2 现有 serializer 适配）

### 当前 26.1.2 的真实问题

显式覆盖文件 `data/tacz/recipe/misc/blood_strike_1.json` 目前输出：

```json
{"item":"minecraft:painting","count":1}
```

因此 `minecraft:item_name` 与
`minecraft:entity_data.variant=tacz:blood_strike_1` 全丢，合出来只是普通随机画。

26.1.2 在 `029d322` 加的 custom-result normalizer 很有价值，**不能删除或用 26.2
serializer 整文件覆盖**；但它会把 `id` 归一成 `item`，仍然不认识 `components`。
正确做法是给它增加“现代组件形态旁路”。

### 1. 扩展 `CraftingHelper#getItemStack`

添加 imports：

```java
import com.mojang.serialization.JsonOps;
import net.minecraft.core.RegistryAccess;
import net.minecraft.resources.RegistryOps;
```

在旧 `item + nbt` 分支前加：

```java
if (json.has("id")) {
    var ops = RegistryOps.create(
            JsonOps.INSTANCE,
            RegistryAccess.fromRegistryOfRegistries(BuiltInRegistries.REGISTRY));
    ItemStack stack = ItemStack.CODEC.parse(ops, json).getOrThrow();
    if (disallowsAirInRecipe && stack.is(Items.AIR)) {
        throw new JsonSyntaxException("Invalid item: minecraft:air");
    }
    return stack;
}
```

旧 `item + nbt` 代码完整保留，第三方旧枪包仍靠它。

### 2. 修改 26.1.2 自己的 `normalizeCustomResultJson`

在它把 `id` 改写成 legacy `item` 之前，先保留带 components 的现代 ItemStack：

```java
JsonElement itemElement = jsonObject.get("item");
JsonObject inner = itemElement != null && itemElement.isJsonObject()
        ? itemElement.getAsJsonObject()
        : jsonObject;

if (inner.has("id") && inner.has("components")) {
    JsonObject modern = inner.deepCopy();
    if (!modern.has("count") && jsonObject.has("count")) {
        modern.add("count", jsonObject.get("count"));
    }
    return modern;
}

// 后面继续走 26.1.2 已有的 item/id/string/nbt legacy 归一化，勿删
```

不要把这段放到 26.2 的 serializer 中照抄；26.1.2 的 normalizer 是该分支额外完成的
第三方枪包保护层。

### 3. 替换显式覆盖 recipe

`src/main/resources/data/tacz/recipe/misc/blood_strike_1.json`

```json
{
  "materials": [
    {"item":"#c:rods/wooden","count":8},
    {"item":"#minecraft:wool","count":1}
  ],
  "result": {
    "type":"custom",
    "group":"tacz:misc",
    "item": {
      "id":"minecraft:painting",
      "components": {
        "minecraft:item_name": {
          "translate":"item.tacz.painting.blood_strike_1"
        },
        "minecraft:entity_data": {
          "id":"minecraft:painting",
          "variant":"tacz:blood_strike_1"
        }
      },
      "count":1
    }
  },
  "type":"tacz:gun_smith_table_crafting"
}
```

### 4. 添加所需 c tag 覆盖

bundle 中没有 `c:rods/wooden`，新增：

`src/main/resources/data/c/tags/item/rods/wooden.json`

```json
{
  "values": [
    "minecraft:stick",
    {"id":"#forge:rods/wooden","required":false}
  ]
}
```

### 5. 资源 bundle 注意

不要重打 53 MB bundle。以上均放显式 `src/main/resources` 覆盖层：

- `blood_strike_1.json` 已经有显式文件，直接替换；
- 三个新文件在 bundle 中不存在，不会与 `DuplicatesStrategy.EXCLUDE` 冲突。

### 验证

1. `/reload`、JEI、REI、工作台都不能因该配方报错或整批丢配方；
2. 合成结果名称是 Blood Strike 联动画；
3. 放置后固定为 `tacz:blood_strike_1`，不是随机画；
4. 再用一个旧式 `{item,nbt}` 第三方 custom recipe 回归，确认旧兼容未退化。

## 五、C：恢复 Iris shadow supplier 初始化（应做；只改入口，不覆盖 26.1.2 Iris 实现）

### 当前 26.1.2 实码

`IrisCompat` 有：

```java
private static Supplier<Boolean> isRenderingShadow = () -> false;
public static void initCompat() { ...把 supplier 指到 IrisCompatNewly/Legacy... }
```

但全分支 `git grep initCompat` 只有定义、没有调用；`CompatRegistry#onEnqueue` 又写着
“不需要 imperative setup”。因此 `isRenderShadow()` 在 Iris 存在时仍恒 false。

### 改法

`CompatRegistry.java`：

```java
import com.tacz.guns.compat.iris.IrisCompat;

public static void onEnqueue() {
    checkModLoad(IRIS, IrisCompat::initCompat);
    // Carry On 继续只走 data/carryon/tags/blocks/block_blacklist.json
}
```

**只做这两行语义改动。** 26.1.2 的 `IrisCompat` 有自己更完整的 HAND /
HAND_TRANSLUCENT pipeline 分类和 depth-aperture 逻辑，禁止用 26.2 文件覆盖。

### 验证

- 无 Iris 专服/客户端启动不加载任何 Iris 类；
- Iris + 光影下 shadow pass 不重复提交枪口火光/枪模功能节点；
- 普通 hand、scope depth aperture 与发光层无回归。

## 六、D：原版末影龙部件归属（先查 26.1.2 字节码，满足条件才做）

26.1.2 当前把所有 multipart part 当成自己的 core，因为 Fabric 没有 NeoForge 通用
`PartEntity#getParent`。这个结论对第三方 modded multipart 成立，但对 vanilla 末影龙
可以特判。

### 必须先核对

在 26.1.2 merged jar 上确认：

```text
net.minecraft.world.entity.boss.enderdragon.EnderDragonPart
public final EnderDragon parentMob
```

若字段名、类型、public/final 都成立，再改；否则不要凭 26.2 猜。

### 改法

```java
import net.minecraft.world.entity.boss.enderdragon.EnderDragonPart;
```

```java
public static MaybeMultipartEntity of(Entity hitPart) {
    Entity core = hitPart instanceof EnderDragonPart dragonPart
            ? dragonPart.parentMob
            : hitPart;
    return new MaybeMultipartEntity(hitPart, core);
}
```

伤害仍打 `hitPart`（vanilla part 自己转发给 dragon）；击杀事件、击退、无敌帧与
living-core 判断改归 `parentMob`。第三方 modded multipart 继续 fail-safe 为自身，
不做反射猜 parent。

### 验证

射击龙头/翼/尾：伤害照常，Post/Kill event 的 hurt entity、击杀反馈与无敌帧归属龙本体。
