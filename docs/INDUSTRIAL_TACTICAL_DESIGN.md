# TACZ 工业化制造与真实弹匣系统设计草案

> 状态：**设计冻结前草案**  
> 适用分支：`arena/019fcefd-tacz-refabricated-unofficial`  
> 调研日期：2026-08-04  
> 目标：把「在一个 GUI 里用一堆铁锭瞬间点出整枪」改成可理解、可自动化、不会无谓折磨玩家的工业链；同时把枪内的整数备弹改成可携带、可装填、可更换的物理弹匣。

---

## 1. 先给结论

### 不应把 Create 作为 26.2 Fabric 版的硬前置

截至本草案日期，官方/主流的 **Create Fabric** 发布页只列到 Minecraft 1.20.1；没有可用于本项目 Minecraft 26.2 的 Fabric 构建。因此把 `create` 写进 `fabric.mod.json` 的硬依赖会让当前项目无法正常安装，也会把 TACZ 的版本可用性绑死在 Create 的移植节奏上。

- Create Fabric 项目页：<https://modrinth.com/mod/create-fabric>
- Create Fabric 26.2 查询结果（空）：<https://api.modrinth.com/v2/project/create-fabric/version?loaders=%5B%22fabric%22%5D&game_versions=%5B%2226.2%22%5D>

**推荐策略：不硬依赖 Create；做一个无外部科技模组也能玩完整闭环的 `TACTICAL` 配置档，再提供可选的科技模组适配。**

### 26.2 上最合适的可选机械前置是 PolyFactory，而不是硬塞 Create

PolyFactory 已有 Fabric 26.2 发布（`0.12.1+26.2`，2026-08-02），并且其已有内容恰好覆盖本方案需要的机械语义：研磨机、机械压力机、工业冶炼、传送带/漏斗、风车/蒸汽/柴油动力。该版本还新增了硫粉，以及以硫粉、煤粉、木粉制作火药的机械配方。

- PolyFactory：<https://modrinth.com/mod/polyfactory>
- 26.2 版本记录：<https://api.modrinth.com/v2/project/polyfactory/version?loaders=%5B%22fabric%22%5D&game_versions=%5B%2226.2%22%5D>
- Polymer（PolyFactory 所需库）：<https://modrinth.com/mod/polymer>

但它依赖 Polymer，并带有服务端资源包/指南生态；把它变成 TACZ 的**必装**依赖会改变本模组的安装和服务器部署模型。因此建议：

| 模式 | 外部前置 | 适用场景 | 行为 |
|---|---:|---|---|
| `LEGACY` | 无 | 原 TACZ 服务器、内容包兼容 | 保留当前配方和整数备弹 |
| `TACTICAL` | 无 | 本模组默认的工业化玩法 | TACZ 自己提供轻量材料、工位、弹匣和配方 |
| `POLYFACTORY` | PolyFactory + Polymer | 追求机械流水线的整合包 | 复用研磨/冲压/工业冶炼等机器；没有该模组时不能启用此档 |

Fabric API 已是项目依赖；库存/物流兼容优先使用其 Transfer API，不需要再引入 Porting Lib。Porting Lib 通常由使用它的模组内嵌，单独依赖容易制造版本冲突。

## 2. 现有实现审计：为什么必须重构，而不只是把铁锭数量乘十

仓库当前内置默认枪包含有：

- **172 条**枪械工作台配方；
- **53 把枪、24 种弹药、95 个配件**；
- 这些终端配方累计直接消耗约 **4,670 铁锭、808 金锭、565 铜锭**；
- 枪械例如 AK-47 直接吃 `38 铁 + 6 青金石 + 10 原木`，Glock 17 直接吃 `16 铁`；
- 7.62×39 弹药直接吃 `15 铜 + 3 火药`，产出 35 发。

这有两个根本问题：

1. **没有生产决策。** 所有矿物都直接进入最终物品，采矿量就是唯一门槛；不需要冶炼、冲压、平台件、工装或自动化。
2. **弹匣并不存在。** `GunCurrentAmmoCount` 只是写在枪物品 `custom_data` 中的整数。当前所谓 `extended_mag` 是配件槽里的容量修正，不是可以装弹、掏出、换入、保留余弹的实体物品。

此外，默认枪包资源声明为 `CC BY-NC-ND 4.0`。本实现**不能直接修改或再分发其中的枪包配方 JSON**。工业化配方应通过 TACZ 自己的 GPL 代码/数据层进行覆盖或转换，并保留 `LEGACY` 回退，不碰受 ND 约束的原始包文件。

## 3. 设计原则

1. **零成品枪拆解。** “不同枪的枪机和枪身”应理解为型号/平台对应的零件，不是要求玩家拿一把完成品枪去合成另一把枪。完成品只能在拆解台回收部分零件和废料。
2. **同平台能复用、不同平台不万能。** AK 与 RPK 可共享 AK 系列枪机/机匣规格；AR 系列可共享一部分 AR 件；AK 件不能拿去装 Glock。这样有真实的平台感，又不让 53 把枪变成 53 套完全孤立的材料地狱。
3. **把复杂度放到“批量中间件与物流”，不要放到 3×3 微合成。** 一条铸锭/冲压/装配线比连续点几十次九宫格更有工业感。
4. **弹药是持续成本，枪是耐用品。** 第一把枪不应需要数小时，但持续射击必须推动硫、碳、金属、底火和装填线。
5. **服务器权威且可回滚。** 物理弹匣、换弹和制造都只由服务端提交；模式可配置，老存档不丢弹、不强迫第三方枪包立即适配。
6. **真实感优先于现实危险化学细节。** 游戏内使用抽象的 Minecraft 物品和批次配方；不试图复刻现实世界的火药、底火或武器制造工艺参数。

## 4. 工业链：建议的材料层级

### 4.1 原料与基础化工

| 阶段 | 物品/概念 | 获得方式 | 设计作用 |
|---|---|---|---|
| 矿物 | 铁、铜、煤、原木、石灰岩/方解石 | 原版采集 | 初期原料 |
| 新矿物 | 硫矿、铅矿、锌矿 | 小规模世界生成；硫偏下界、铅/锌偏地下 | 防止所有枪械只围绕铁铜转 |
| 粉料 | 碳粉、硫粉、铅粉、石灰粉 | 研磨；无 PolyFactory 时由 TACZ 研磨工位处理 | 火药、合金和弹头的输入 |
| 化工中间件 | 硝盐、工业火药、底火组件 | 浸取/混配/压制的批量配方 | 让弹药具备独立的持续供应链 |

**平衡规则：**

- 1 煤/木炭应产出多单位碳粉，避免煤成为无意义的“1:1 第二铁锭”；
- 火药应按批次产出（例如 8 或 16 单位），而不是一发弹消耗一个独立火药；
- 硫、铅、锌的矿脉稀少于铁但不稀有到需要刷数千格；
- 硝盐采用游戏化的“浸取盐”中间件，而不是提供现实化学操作指引。

### 4.2 冶金

| 输入 | 工位 | 输出 | 用途 |
|---|---|---|---|
| 原铁 + 碳粉 + 石灰粉 | 鼓风炉 / 工业冶炼 | 生铁（批量） | 铸件、后续钢材 |
| 生铁 + 碳粉 + 助熔材料 | 鼓风炉 / 工业冶炼 | 高碳钢 | 枪机、枪管、弹簧、冲压件 |
| 铜 + 锌 | 熔炼/混合 | 黄铜 | 弹壳、底火杯 |
| 铅锭 + 铜粉 | 压制/包覆 | 弹头坯 | 轻武器弹头 |
| 高碳钢 | 冲压/锻压 | 钢板、弹簧钢、机加工坯料 | 枪身、弹匣壳、机匣 |

“高碳钢”在本方案中是游戏内的高强度钢材料名；后续若需要区分枪管钢和弹簧钢，可由它继续加工，而不是再要求玩家反复制作同一种锭。

### 4.3 工位与自动化

| 工位 | `TACTICAL` 无前置版本 | `POLYFACTORY` 适配版本 | 产物 |
|---|---|---|---|
| 研磨 | TACZ 研磨工位 | Grinder | 各类粉末 |
| 鼓风炉 | TACZ 鼓风炉（燃料、温度/批次） | Industrial Smeltery | 生铁、钢、黄铜 |
| 冲压台 | TACZ 冲压/装配台 | Mechanical Press | 弹壳、钢板、机匣坯、弹匣壳 |
| 枪械装配台 | TACZ 高级装配台 | Blueprint Workbench + 适配配方 | 枪械零件与整枪 |
| 装弹台 | TACZ 装弹台 | Press/Workbench + 适配配方 | 成批弹药、装填器 |
| 拆解台 | TACZ 拆解台 | 可选机械拆解 | 回收旧枪/旧弹匣的部分零件 |

`TACTICAL` 只需少量可视化方块和一个统一、数据驱动的加工菜单，不应再造一整套通用工业科技模组。`POLYFACTORY` 负责“把这条链做成转动的流水线”，而不是让 TACZ 复制它的动力网络。

## 5. 枪械零件模型

### 5.1 每一把可制造枪的最低组成

最终装配至少应检查：

1. **对应平台的机匣/枪身**（receiver/body）；
2. **对应平台的枪机或枪机组**（bolt / bolt-carrier group）；
3. **口径匹配的枪管**；
4. **击发组件**（扳机、击锤/击针、保险抽象为一件）；
5. **复进组件**（弹簧/导气或后坐缓冲件）；
6. **握把/枪托/护木等外装件**；
7. **可拆卸供弹枪的弹匣井与一只空弹匣**；
8. **对应平台蓝图/模具**（不消耗，具有耐久或工艺等级）。

这正好满足“至少要不同枪的枪机和枪身”，也补上了枪管、击发组、复进簧、供弹结构和工装这些不能省略的制造逻辑。

### 5.2 平台族，而不是“一枪一个不可复用垃圾件”

| 平台族 | 可共享的例子 | 专用件的例子 |
|---|---|---|
| AK | AK 机匣坯、AK 枪机组、7.62×39 弹匣 | AK-47 木制家具 / RPK 加强枪管与两脚架 |
| AR/STANAG | AR 上下机匣、STANAG 弹匣、缓冲组件 | M16 固定枪托、M4 伸缩枪托、HK416 导气系统 |
| 手枪 | 聚合物/钢制套筒平台、短枪管、手枪击发组 | Glock、M1911、P320 各自枪身与闭锁件 |
| 精确步枪 | 加强机匣、旋转枪机、重型枪管 | 各口径枪管、枪托、瞄具座 |
| 霰弹枪/转轮枪 | 管式弹仓/转轮组件 | **不使用可拆卸实体弹匣** |
| 机枪 | 加强机匣、枪机组、重枪管 | 弹链/弹鼓供弹组件 |

完成品拆解只返回约 35%–60% 的零件或废钢，且损失小件；它是补救与回收，而不是复制成品的免费捷径。

## 6. 弹药配方与消耗平衡

### 6.1 抽象弹药链

```text
硫/煤/盐类 → 工业火药 ┐
铜+锌 → 黄铜 → 冲压弹壳 ├→ 装弹台 → 成批弹药
铅/铜 → 弹头坯         │
黄铜/红石抽象件 → 底火 ┘
```

### 6.2 批量建议

| 弹药类别 | 单批产出 | 相对资源成本 | 理由 |
|---|---:|---:|---|
| 手枪弹（9 mm、.45） | 48 | 1.0× | 常用、允许练枪 |
| 中间威力步枪弹（5.45、5.56、7.62×39） | 32 | 1.5× | 主战消耗 |
| 全威力/精确步枪弹（.308、7.62×54、.338） | 16 | 2.5–4× | 高伤害与远程优势要有代价 |
| 霰弹 | 16 | 2× | 弹丸/壳体更多 |
| .50 BMG / 40 mm / RPG | 1–4 | 8–20× | 必须是明确的战术资源 |

资源强度应主要由**射击次数**而非第一次造枪决定。普通玩家应能在得到第一条钢材链后拥有一把手枪与 2–3 个弹匣；半自动步枪需要稳定钢材和冲压；机枪、反器材、爆炸性弹药要求成熟的自动化链。

### 6.3 防止“硬核 = 乏味”的四条红线

- 不把每一发子弹拆成十几次手搓；全部以批次处理。
- 不让模板一次性消耗；模板是耐用品，需要维护而非重复刷。
- 不让所有枪都需要钻石/下界合金；这些留给特种瞄具、耐高压枪管、重武器。
- 不引入随机炸炉/随机失败作为常规惩罚；品质、耐久、过热可以后续做，首版优先可预测性。

## 7. 真实物理弹匣：目标行为

### 7.1 数据模型

新增 `tacz:magazine` 物品（每个物品堆只允许 1 个），其 `custom_data` 至少包含：

```text
MagazineFamily       兼容平台族，例如 ak_762 / stanag_556 / glock_9
CompatibleAmmo       允许弹种
Capacity             容量
AmmoCount            当前装填数
Condition            预留：磨损/故障，不在首版开启
```

枪物品新增：

```text
InstalledMagazine    完整序列化的 Magazine ItemStack；没有时表示未插弹匣
GunCurrentAmmoCount  与 InstalledMagazine.AmmoCount 保持镜像，供旧 HUD/脚本/内容包兼容
HasBulletInBarrel    继续独立保存膛内一发
```

**关键点：** 弹匣不是“容量数字”，而是一个真正会从背包拿走、进入枪内、再被退回背包的 `ItemStack`。因此半满弹匣的状态天然被保存，掉落/箱子/交易也不会丢失余弹。

### 7.2 首版换弹规则

1. 仅对数据声明为 `detachable` 的枪启用物理弹匣；
2. 枪膛一发继续独立处理，闭膛枪的“+1”状态不会被错误清空；
3. 按换弹键时，从热键栏优先、再从背包中选择**容量匹配且装填数最高**的弹匣；
4. 在现有动画的 feed 时点进行服务端原子交换：旧弹匣返回背包，背包满则掉到脚边；新弹匣进入枪内；
5. 战术换弹会保留旧弹匣中的余弹；空仓换弹也会保留空弹匣，避免凭空消失；
6. 潜行 + 换弹用于单独退匣（以后可绑定独立“退匣”按键）；
7. 物品栏中用右键将散装匹配子弹装入弹匣，右键空槽可取出一叠；不允许混装不同弹种；
8. 创造模式用虚拟满弹匣，不污染普通弹匣；
9. 背包、枪和地面掉落的一切变化由服务端执行，不信任客户端提交的弹数。

### 7.3 哪些枪不应假装有可拆卸弹匣

- 管式霰弹枪、杠杆枪：保持逐发/内部弹仓逻辑；
- 转轮手枪：后续可做转轮装填器，首版仍是内部弹仓；
- 弹链机枪：后续做弹链箱/弹鼓，不能硬套 AR 弹匣；
- 单发枪与榴弹发射器：保持单发装填。

当前 TACZ 的 `reload.type = magazine` 不能直接等于“现实中的可拆卸弹匣”：默认包内的 M870、SPAS-12、转轮手枪等也使用该旧枚举。因此必须新增更精确的 `feed_mechanism`/`magazine_family` 数据字段；没有声明的第三方枪包继续走旧整数备弹，绝不擅自把其管式/转轮枪改坏。

### 7.4 存档迁移

启用物理弹匣后，已存在的、明确声明为 detachable 的枪：

- 将旧 `GunCurrentAmmoCount` 无损转换为枪内的隐藏兼容弹匣；
- 第一次成功换弹后才转为普通可取出的实体弹匣；
- 未声明的新/第三方枪不迁移，继续按旧行为工作；
- 关闭配置档时，实体弹匣内的余弹会安全同步回旧字段，保证回滚。

## 8. 实现边界与技术方案

### 8.1 不直接改默认枪包

默认枪包资源不能修改。实施时采用：

1. 在 TACZ GPL 代码中增加 `IndustryProfile` 与 `IndustrialRecipeTransformer`；
2. 仅在 `TACTICAL` / `POLYFACTORY` 档，转换受本项目维护的默认枪配方 ID；
3. `TableRecipeManager` 转换后的配方仍走现有同步通道，因此服务端、枪械工作台 GUI、JEI 和 REI 看见的是同一份材料表；
4. 其他命名空间、未知第三方包、用户数据包默认不转换；它们可通过新增 schema 自愿声明工业零件和物理弹匣；
5. `LEGACY` 下完全不变。

这也规避了当前枪包加载器内多个包同路径覆盖顺序不稳定的问题。

### 8.2 不需要的前置

- **不引入 Create / Porting Lib 硬依赖**；
- **不引入 KubeJS**：本仓库已经标注其 26.2 Fabric 不可用，且关键安全逻辑不该依赖脚本；
- **不引入通用能源 API**：首版只需要明确的加工工位，PolyFactory 模式由其自身动力网络负责；
- **不复制 PolyFactory 内容**：只以可选适配和公共标签互通。

### 8.3 需要新增的代码面

| 模块 | 主要类/职责 |
|---|---|
| 配置 | `IndustryProfile`、服务端同步配置、存档迁移开关 |
| 物品 | `MagazineItem`、`MagazineDataAccessor`、蓝图/模具、工业中间件 |
| 数据 | `MagazineDefinition`、`GunFeedDefinition`、平台族/口径 schema |
| 换弹 | `MagazineService`；接入 `LivingEntityReload`、`LivingEntityShoot`、`LivingEntityBolt`、`ModernKineticGunScriptAPI` |
| 工位 | 统一的加工 recipe/type 与轻量 block entity；PolyFactory 适配层独立隔离 |
| 配方 | 默认配方转换器、工业配方数据、公共材料 tags |
| 体验 | 物品 Tooltip、HUD 的弹匣/膛内显示、REI/JEI 展示、中文/英文文本 |
| 测试 | 单机/专服换弹事务、满背包退匣、断线同步、旧存档迁移、第三方包回退 |

## 9. 推荐实施顺序

### Phase 0 — 配置与数据契约

- 加入 `LEGACY` / `TACTICAL` / `POLYFACTORY` 档位；
- 写出 `feed_mechanism`、`magazine_family`、`magazine_capacity` 的枪包 schema；
- 先为少量代表性枪（Glock 17、AK-47、M4A1、RPK）提供数据；
- 不改变默认玩法，确保第三方包不受影响。

### Phase 1 — 物理弹匣 MVP（优先）

- 实现 `MagazineItem` 的装填、取弹、Tooltip；

> 先做这一步的原因：枪械零件与最终配方的“包含一只弹匣”只有在弹匣真的存在时才有价值。

## 10. 验收标准

### 物理弹匣

- [ ] 7.62×39 AK 弹匣装 30 发后取出，余弹数量不丢；
- [ ] 半满 AK 弹匣战术换弹后返回背包，枪内变为新弹匣；
- [ ] 背包满时旧弹匣掉在玩家脚边，绝不删除；
- [ ] 空仓换弹后闭膛枪正确上膛，HUD 能区分“弹匣余量 + 膛内一发”；
- [ ] M870/转轮枪没有被错误要求装可拆卸弹匣；
- [ ] 老存档枪开启/关闭模式均不丢子弹；
- [ ] 客户端伪造的弹匣 NBT 不会增加服务端弹药。

### 工业制造

- [ ] 新手可在合理时间内得到第一把手枪和 2–3 个弹匣；
- [ ] AK/M4 需要钢、冲压件、对应枪身/枪机/枪管/蓝图；
- [ ] 连续战斗的主要成本是批量弹药而不是反复重造枪；
- [ ] 自动化能显著提升吞吐，但手动工位不是无法游玩；
- [ ] `LEGACY` 档与未声明工业数据的第三方枪包保持原行为；
- [ ] `POLYFACTORY` 档在缺少 PolyFactory 时明确拒绝启用并给出可读提示。

## 11. 当前阻塞项

本沙箱缺少 `java` / `javac`（`bash ./gradlew compileJava --no-daemon` 在 Gradle 启动前报 `JAVA_HOME is not set and no 'java' command could be found in PATH`）。在具备 Java 25 的构建环境前，不应把未经编译验证的大型游戏逻辑直接并入主分支。

设计、数据契约和小范围代码可先完成；物理弹匣 Phase 1 开始时必须先恢复可执行的 `compileJava`，随后增加专服和单机回归测试。
