# TACZ 工业化制造与真实弹匣系统设计草案

> 状态：**设计冻结前草案**  
> 适用分支：`arena/019fcefd-tacz-refabricated-unofficial`  
> 调研日期：2026-08-04  
> 目标：把「在一个 GUI 里用一堆铁锭瞬间点出整枪」改成可理解、可自动化、不会无谓折磨玩家的工业链；同时把枪内的整数备弹改成可携带、可装填、可更换的物理弹匣。

## 1. 先给结论

### 官方 Create Fabric 不能直接用，但 Create Fly 是可行的 26.2 替代

官方/主流的 **Create Fabric** 发布页只列到 Minecraft 1.20.1，因此它本身不能作为本项目 26.2 Fabric 的前置。

- 官方 Create Fabric 项目页：<https://modrinth.com/mod/create-fabric>
- 官方 Create Fabric 的 26.2 查询结果（空）：<https://api.modrinth.com/v2/project/create-fabric/version?loaders=%5B%22fabric%22%5D&game_versions=%5B%2226.2%22%5D>

但是，用户指出的 **Create Fly** 是一个独立的高版本 Fabric 分支。已核实其 Modrinth 记录把 `26.2-rc-2-6.0.9-1` 标为 Fabric 26.2 可用，模组 ID 仍为标准的 `create`，并实现了本方案真正需要的 `create:milling`、`create:pressing`、`create:mixing`、`create:compacting`、`create:sequenced_assembly` 等配方类型。

- Create Fly：<https://modrinth.com/mod/create-fly>
- Create Fly 26.2 发行记录：<https://api.modrinth.com/v2/project/dKvj0eNn/version?loaders=%5B%22fabric%22%5D&game_versions=%5B%2226.2%22%5D>
- 26.2 源码分支：<https://github.com/ZurrTum/Create-Fly/tree/26.2>

它让“机械动力作为工业制造前置”成为可实施方案，且能大幅减少 TACZ 自己重写研磨、冲压、转动动力和流水线的工作量。

### 已选策略：Create Fly 是工业档的必需前置，但不是 TACZ 全局硬依赖

用户已选择“**默认工业化 + 可回退**”和 Create Fly 替代方案。落地为：

| 模式 | 外部前置 | 适用场景 | 行为 |
|---|---:|---|---|
| `LEGACY` | 无 | 原 TACZ 服务器、老存档、第三方枪包 | 保留当前配方和整数备弹 |
| `CREATE_FLY`（默认工业档） | Create Fly，客户端与服务端同版本 | 本项目的目标工业玩法 | 使用研磨、冲压、加热搅拌/鼓风炉、机械装配和物理弹匣 |

这里**不**把 `create` 写成 TACZ 的全局 `fabric.mod.json` 硬依赖：否则管理员即使选择 `LEGACY` 也不能启动原版 TACZ。取而代之的是服务器加载 `CREATE_FLY` 档时强校验 `FabricLoader.isModLoaded("create")`；缺失时拒绝转换默认配方并给出可读报错，绝不静默降级或生成无来源材料。这样 Create Fly 对工业玩法是实质前置，同时保留用户要求的回退通道。

Create Fly 是社区分支而非官方 Create 发行，且其 README 明确提示不要沿用旧存档、数据加载变更可能造成数据丢失，并把“兼容其他 Mod”列为待办。因此第一期只依赖稳定的数据配方面，不在 TACZ 代码中直接调用其内部 Java API；所有 Create Fly 配方以数据 JSON 和 `create` 模组存在检查接入。这既减少编译耦合，也使将来替换兼容层可控。

Fabric API 已是项目依赖；库存/物流兼容优先使用其 Transfer API，不需要引入 Porting Lib。Create Fly 自身也不要求 Fabric API，但两者可共存。

## 2. 现有实现审计：为什么必须重构，而不只是把铁锭数量乘十

仓库当前内置默认枪包含有：

- **172 条**枪械工作台配方；
- **53 把枪、24 种弹药、95 个配件**；
- 这些终端配方累计直接消耗约 **4,670 铁锭、808 金锭、565 铜锭**；
- 枪械例如 AK-47 直接吃 `38 铁 + 6 青金石 + 10 原木`，Glock 17 直接吃 `16 铁`；
- 7.62×39 弹药直接吃 `15 铜 + 3 火药`，产出 35 发。

这有两个根本问题：

1. **没有生产决策。** 所有矿物都直接进入最终物品，采矿量就是唯一门槛；不需要冶炼、冲压、平台件、工装或自动化。
2. **弹匣并不存在。** `GunCurrentAmmoCount` 只是写在枪物品 `custom_data` 中的整数。当前所谓 `extended_mag` 是配件槽里的容量修正，不是可以装弹、掏出、换入、保留余弹的实体物品。

此外，默认枪包资源声明为 `CC BY-NC-ND 4.0`。本实现**不能直接修改或再分发其中的枪包配方 JSON**。工业化配方应通过 TACZ 自己的 GPL 代码/数据层进行覆盖或转换，并保留 `LEGACY` 回退，不碰受 ND 约束的原始包文件。

## 3. 设计原则

1. **零成品枪拆解。** “不同枪的枪机和枪身”应理解为型号/平台对应的零件，不是要求玩家拿一把完成品枪去合成另一把枪。完成品只能在拆解台回收部分零件和废料。
2. **同平台能复用、不同平台不万能。** AK 与 RPK 可共享 AK 系列枪机/机匣规格；AR 系列可共享一部分 AR 件；AK 件不能拿去装 Glock。这样有真实的平台感，又不让 53 把枪变成 53 套完全孤立的材料地狱。
3. **把复杂度放到“批量中间件与物流”，不要放到 3×3 微合成。** 一条铸锭/冲压/装配线比连续点几十次九宫格更有工业感。
4. **弹药是持续成本，枪是耐用品。** 第一把枪不应需要数小时，但持续射击必须推动硫、碳、金属、底火和装填线。
5. **服务器权威且可回滚。** 物理弹匣、换弹和制造都只由服务端提交；模式可配置，老存档不丢弹、不强迫第三方枪包立即适配。
6. **真实感优先于现实危险化学细节。** 游戏内使用抽象的 Minecraft 物品和批次配方；不试图复刻现实世界的火药、底火或武器制造工艺参数。

## 4. 工业链：建议的材料层级

### 4.1 原料与基础化工

| 阶段 | 物品/概念 | 获得方式 | 设计作用 |
|---|---|---|---|
| 矿物 | 铁、铜、煤、原木、石灰岩/方解石 | 原版采集 | 初期原料 |
| 新矿物 | 硫矿、铅矿、锌矿 | 小规模世界生成；硫偏下界、铅/锌偏地下 | 防止所有枪械只围绕铁铜转 |
| 粉料 | 碳粉、硫粉、铅粉、石灰粉 | Create Fly 研磨机/粉碎轮 | 火药、合金和弹头的输入 |
| 化工中间件 | 硝盐、工业火药、底火组件 | 浸取/混配/压制的批量配方 | 让弹药具备独立的持续供应链 |

**平衡规则：**

- 1 煤/木炭应产出多单位碳粉，避免煤成为无意义的“1:1 第二铁锭”；
- 火药应按批次产出（例如 8 或 16 单位），而不是一发弹消耗一个独立火药；
- 硫、铅、锌的矿脉稀少于铁但不稀有到需要刷数千格；
- 硝盐采用游戏化的“浸取盐”中间件，而不是提供现实化学操作指引。

### 4.2 冶金

| 输入 | 工位 | 输出 | 用途 |
|---|---|---|---|
| 原铁 + 碳粉 + 石灰粉 | 鼓风炉 / 工业冶炼 | 生铁（批量） | 铸件、后续钢材 |
| 生铁 + 碳粉 + 助熔材料 | 鼓风炉 / 工业冶炼 | 高碳钢 | 枪机、枪管、弹簧、冲压件 |
| 铜 + 锌 | 熔炼/混合 | 黄铜 | 弹壳、底火杯 |
| 铅锭 + 铜粉 | 压制/包覆 | 弹头坯 | 轻武器弹头 |
| 高碳钢 | 冲压/锻压 | 钢板、弹簧钢、机加工坯料 | 枪身、弹匣壳、机匣 |

“高碳钢”在本方案中是游戏内的高强度钢材料名；后续若需要区分枪管钢和弹簧钢，可由它继续加工，而不是再要求玩家反复制作同一种锭。

### 4.3 工位与自动化

| 工位 | Create Fly 对应机制 | TACZ 产物 |
|---|---|---|
| 研磨 | Millstone / Crushing Wheels | 各类粉末 |
| 鼓风炉 | Basin + Mechanical Mixer + Blaze Burner 的加热/超热工艺 | 生铁、钢、黄铜 |
| 冲压台 | Mechanical Press（置物台/传送带上单一输入） | 弹壳、钢板、机匣坯、弹匣壳 |
| 枪械装配台 | Sequenced Assembly（单一过渡工件 + 多个部署工位） | 枪械零件与整枪 |
| 装弹台 | Mechanical Press + Basin + Deploying | 成批弹药、装填器 |
| 拆解台 | 后续单独实现的 TACZ 回收配方 | 回收旧枪/旧弹匣的部分零件 |

Create Fly 就是本档的动力与机器层；TACZ 只提供枪械工业专用材料、工艺配方、平台零件和最终装配语义，不复制 Create 的动力网络。玩家把加热 Basin + Blaze Burner 视为“鼓风炉单元”，从而得到真正需要热源、搅拌与物流的冶炼流程，而不必让 TACZ 再造一套同类机器。

### 4.4 置物台的单工件约束

Create 的**置物台（Depot）不是多格装配台**：同一时刻只能承载一种物品堆。由此产生的工艺边界必须写进配方，而不是只画在 REI 图标上：

- `create:pressing` 只能把一个输入堆冲压成一个中性毛坯；不同口径/部件身份必须在后续由模具或其他工位赋予；
- `create:deploying` 的置物台/传送带上只有一个目标工件，第二个物品是**部署器手持栏**中的模具、模板或待装配零件；
- 需要多种物料同时混合的弹药、冶金、弹匣壳配方只能用 **Basin** 的 `create:mixing` / `create:compacting`；
- 整枪的多个部件不能一起摆到置物台。它们必须由 `create:sequenced_assembly` 的多个部署工位按顺序加入同一枚过渡工件，或改用具有独立格位的机械合成器。

因此“多种输入都列在配方 JSON 中”不等于“它们可同时放到置物台”。每条配方必须明确属于工作盆多输入，还是单工件的部署/顺序装配。

工作盆还有另一条硬限制：`create:compacting` 是无序匹配，优先级看的是输入**种类数**而不是同种材料的数量。若多条配方给出相同输入（即使结果 NBT 不同），或“3 钢 + 生铁”和“2 钢 + 生铁”这类配方在同一工作盆都能匹配且种类数相同，Create 只会按加载顺序选中其中一条。热量也不能把它们可靠区分，因为无热要求在高温工作盆仍会匹配。故压实只允许产出中性库存/毛坯；口径、模具几何、弹匣族等最终身份必须由后续部署器持有的非消耗实体量规选择。

## 5. 枪械零件模型

### 5.1 每一把可制造枪的最低组成

最终装配至少应检查：

1. **对应平台的机匣/枪身**（receiver/body）；
2. **对应平台的枪机或枪机组**（bolt / bolt-carrier group）；
3. **口径匹配的枪管**；
4. **击发组件**（扳机、击锤/击针、保险抽象为一件）；
5. **复进组件**（弹簧/导气或后坐缓冲件）；
6. **握把/枪托/护木等外装件**；
7. **可拆卸供弹枪的弹匣井与一只空弹匣**；
8. **对应平台蓝图/模具**（不消耗，具有耐久或工艺等级）。

这正好满足“至少要不同枪的枪机和枪身”，也补上了枪管、击发组、复进簧、供弹结构和工装这些不能省略的制造逻辑。

### 5.2 平台族，而不是“一枪一个不可复用垃圾件”

| 平台族 | 可共享的例子 | 专用件的例子 |
|---|---|---|
| AK | AK 机匣坯、AK 枪机组、7.62×39 弹匣 | AK-47 木制家具 / RPK 加强枪管与两脚架 |
| AR/STANAG | AR 上下机匣、STANAG 弹匣、缓冲组件 | M16 固定枪托、M4 伸缩枪托、HK416 导气系统 |
| 手枪 | 聚合物/钢制套筒平台、短枪管、手枪击发组 | Glock、M1911、P320 各自枪身与闭锁件 |
| 精确步枪 | 加强机匣、旋转枪机、重型枪管 | 各口径枪管、枪托、瞄具座 |
| 霰弹枪/转轮枪 | 管式弹仓/转轮组件 | **不使用可拆卸实体弹匣** |
| 机枪 | 加强机匣、枪机组、重枪管 | 弹链/弹鼓供弹组件 |

完成品拆解只返回约 35%–60% 的零件或废钢，且损失小件；它是补救与回收，而不是复制成品的免费捷径。

## 6. 弹药配方与消耗平衡

### 6.1 抽象弹药链

```text
硫/煤/盐类 → 工业火药 ┐
铜+锌 → 黄铜 → 冲压弹壳 ├→ 装弹台 → 成批弹药
铅/铜 → 弹头坯         │
黄铜/红石抽象件 → 底火 ┘
```

### 6.2 批量建议

| 弹药类别 | 单批产出 | 相对资源成本 | 理由 |
|---|---:|---:|---|
| 手枪弹（9 mm、.45） | 48 | 1.0× | 常用、允许练枪 |
| 中间威力步枪弹（5.45、5.56、7.62×39） | 32 | 1.5× | 主战消耗 |
| 全威力/精确步枪弹（.308、7.62×54、.338） | 16 | 2.5–4× | 高伤害与远程优势要有代价 |
| 霰弹 | 16 | 2× | 弹丸/壳体更多 |
| .50 BMG / 40 mm / RPG | 1–4 | 8–20× | 必须是明确的战术资源 |

资源强度应主要由**射击次数**而非第一次造枪决定。普通玩家应能在得到第一条钢材链后拥有一把手枪与 2–3 个弹匣；半自动步枪需要稳定钢材和冲压；机枪、反器材、爆炸性弹药要求成熟的自动化链。

### 6.3 防止“硬核 = 乏味”的四条红线

- 不把每一发子弹拆成十几次手搓；全部以批次处理。
- 不让模板一次性消耗；模板是耐用品，需要维护而非重复刷。
- 不让所有枪都需要钻石/下界合金；这些留给特种瞄具、耐高压枪管、重武器。
- 不引入随机炸炉/随机失败作为常规惩罚；品质、耐久、过热可以后续做，首版优先可预测性。

## 7. 真实物理弹匣：目标行为

### 7.1 数据模型

新增 `tacz:magazine` 物品（每个物品堆只允许 1 个），其 `custom_data` 至少包含：

```text
MagazineFamily       兼容平台族，例如 ak_762 / stanag_556 / glock_9
CompatibleAmmo       允许弹种
Capacity             容量
AmmoCount            当前装填数
Condition            预留：磨损/故障，不在首版开启
```

枪物品新增：

```text
InstalledMagazine    完整序列化的 Magazine ItemStack；没有时表示未插弹匣
GunCurrentAmmoCount  与 InstalledMagazine.AmmoCount 保持镜像，供旧 HUD/脚本/内容包兼容
HasBulletInBarrel    继续独立保存膛内一发
```

**关键点：** 弹匣不是“容量数字”，而是一个真正会从背包拿走、进入枪内、再被退回背包的 `ItemStack`。因此半满弹匣的状态天然被保存，掉落/箱子/交易也不会丢失余弹。

### 7.2 首版换弹规则

1. 仅对数据声明为 `detachable` 的枪启用物理弹匣；
2. 枪膛一发继续独立处理，闭膛枪的“+1”状态不会被错误清空；
3. 按换弹键时，从热键栏优先、再从背包中选择**容量匹配且装填数最高**的弹匣；
4. 在现有动画的 feed 时点进行服务端原子交换：旧弹匣返回背包，背包满则掉到脚边；新弹匣进入枪内；
5. 战术换弹会保留旧弹匣中的余弹；空仓换弹也会保留空弹匣，避免凭空消失；
6. 潜行 + 换弹用于单独退匣（以后可绑定独立“退匣”按键）；
7. 物品栏中用右键将散装匹配子弹装入弹匣，右键空槽可取出一叠；不允许混装不同弹种；
8. 创造模式用虚拟满弹匣，不污染普通弹匣；
9. 背包、枪和地面掉落的一切变化由服务端执行，不信任客户端提交的弹数。

### 7.3 哪些枪不应假装有可拆卸弹匣

- 管式霰弹枪、杠杆枪：保持逐发/内部弹仓逻辑；
- 转轮手枪：后续可做转轮装填器，首版仍是内部弹仓；
- 弹链机枪：后续做弹链箱/弹鼓，不能硬套 AR 弹匣；
- 单发枪与榴弹发射器：保持单发装填。

当前 TACZ 的 `reload.type = magazine` 不能直接等于“现实中的可拆卸弹匣”：默认包内的 M870、SPAS-12、转轮手枪等也使用该旧枚举。因此必须新增更精确的 `feed_mechanism`/`magazine_family` 数据字段；没有声明的第三方枪包继续走旧整数备弹，绝不擅自把其管式/转轮枪改坏。

### 7.4 存档迁移

启用物理弹匣后，已存在的、明确声明为 detachable 的枪：

- 将旧 `GunCurrentAmmoCount` 无损转换为枪内的隐藏兼容弹匣；
- 第一次成功换弹后才转为普通可取出的实体弹匣；
- 未声明的新/第三方枪不迁移，继续按旧行为工作；
- 关闭配置档时，实体弹匣内的余弹会安全同步回旧字段，保证回滚。

## 8. 实现边界与技术方案

### 8.1 不直接改默认枪包

默认枪包资源不能修改。实施时采用：

1. 在 TACZ GPL 代码中增加 `IndustryProfile` 与 `IndustrialRecipeTransformer`；
2. 仅在 `CREATE_FLY` 档且确认 `create` 已加载时，读取受维护枪的终端装配声明；
3. 只有声明所指向的真实 `create:sequenced_assembly` 资源存在、且每一步都通过“置物台单工件”形状校验时，才移除对应的旧枪械工作台成枪配方；否则保留旧配方作为安全回退；
4. 最终枪由 Create 生产线产出，JEI 使用 Create Fly 原生展示，REI 从同步的实际 `recipe/create/` JSON 展示同一工艺树；
5. 其他命名空间、未知第三方包、用户数据包默认不转换；它们可通过新增 schema 自愿声明工业零件、终端顺序装配和物理弹匣；
6. `LEGACY` 下完全不变。

这也规避了当前枪包加载器内多个包同路径覆盖顺序不稳定的问题。

### 8.2 依赖边界

- **Create Fly 是 `CREATE_FLY` 档的必需前置**，但不成为 `LEGACY` 的全局强制依赖；
- **不引入 Porting Lib**：Create Fly 已自行实现其迁移层，TACZ 没有理由再把另一套 Porting Lib 引入类路径；
- **不引入 KubeJS**：本仓库已标注其 26.2 Fabric 不可用，且关键安全逻辑不该依赖脚本；
- **不引入通用能源 API**：动力、应力、热源和传输由 Create Fly 负责；
- **不复制 Create Fly 内容**：TACZ 仅提供 `data/tacz/recipe/create/**` 的工业配方和最小的存在检查；
- **不直接调用 Create Fly 内部 Java 类**：第一期只用其稳定的 `create:*` recipe JSON 类型，避免把社区分支内部 API 固化到 TACZ。

### 8.3 需要新增的代码面

| 模块 | 主要类/职责 |
|---|---|
| 配置 | `IndustryProfile`、服务端同步配置、存档迁移开关 |
| 物品 | `MagazineItem`、`MagazineDataAccessor`、蓝图/模具、工业中间件 |
| 数据 | `MagazineDefinition`、`GunFeedDefinition`、平台族/口径 schema |
| 换弹 | `MagazineService`；接入 `LivingEntityReload`、`LivingEntityShoot`、`LivingEntityBolt`、`ModernKineticGunScriptAPI` |
| 工艺适配 | `CREATE_FLY` 模组存在检查、研磨/冲压/混合/序列装配 JSON、REI/JEI 展示回归 |
| 配方 | 默认配方转换器、工业配方数据、公共材料 tags |
| 体验 | 物品 Tooltip、HUD 的弹匣/膛内显示、REI/JEI 展示、中文/英文文本 |
| 测试 | 单机/专服换弹事务、满背包退匣、断线同步、旧存档迁移、第三方包回退 |

## 9. 推荐实施顺序

### Phase 0 — 配置与数据契约

- 加入 `LEGACY` / `CREATE_FLY` 档位，并在工业档启动时校验 `create`；
- 写出 `feed_mechanism`、`magazine_family`、`magazine_capacity` 的枪包 schema；
- 先为少量代表性枪（Glock 17、AK-47、M4A1、RPK）提供数据；
- 不改变默认玩法，确保第三方包不受影响。

### Phase 1 — 物理弹匣 MVP（优先）

- 实现 `MagazineItem` 的装填、取弹、Tooltip；
- 实现枪内 `InstalledMagazine` 与服务端原子换弹；
- 接入闭膛、开膛、栓动的弹数处理；
- 做潜行退匣与满背包掉落保护；
- 覆盖 4 个代表性可拆卸弹匣平台。

> 先做这一步的原因：枪械零件与最终配方的“包含一只弹匣”只有在弹匣真的存在时才有价值。

### Phase 2 — Create Fly 生产材料与批量装弹

- 添加硫粉、碳粉、生铁、高碳钢、黄铜、弹壳、底火、弹头坯；
- 添加 Create Fly 研磨、冲压、加热 Basin（鼓风炉单元）与装弹工艺 JSON；
- 将 9 mm、5.56、7.62×39、12G 四条弹药链做成平衡样本；
- 配方查看器与 GUI 先完整呈现，再扩大覆盖面。

### Phase 3 — 平台零件与整枪装配

- 添加 AK、AR、手枪、精确步枪的机匣/枪机/枪管/击发组/蓝图；
- 转换默认枪包中对应的枪械配方；
- 实现拆解回收；
- 用资源等价物、制造时间和实测游玩时长校准成本。

### Phase 4 — 全枪包覆盖与 Create Fly 生产线回归

- 为余下默认枪按平台归类；
- 完成 Create Fly 工艺、公共 tag、缺失前置检测和机械装配展示；
- 完整回归第三方包、JEI/REI、多人服务器与存档迁移。

## 10. 验收标准

### 物理弹匣

- [ ] 7.62×39 AK 弹匣装 30 发后取出，余弹数量不丢；
- [ ] 半满 AK 弹匣战术换弹后返回背包，枪内变为新弹匣；
- [ ] 背包满时旧弹匣掉在玩家脚边，绝不删除；
- [ ] 空仓换弹后闭膛枪正确上膛，HUD 能区分“弹匣余量 + 膛内一发”；
- [ ] M870/转轮枪没有被错误要求装可拆卸弹匣；
- [ ] 老存档枪开启/关闭模式均不丢子弹；
- [ ] 客户端伪造的弹匣 NBT 不会增加服务端弹药。

### 工业制造

- [ ] 新手可在合理时间内得到第一把手枪和 2–3 个弹匣；
- [ ] AK/M4 需要钢、冲压件、对应枪身/枪机/枪管/蓝图；
- [ ] 连续战斗的主要成本是批量弹药而不是反复重造枪；
- [ ] 自动化能显著提升吞吐，但手动工位不是无法游玩；
- [ ] `LEGACY` 档与未声明工业数据的第三方枪包保持原行为；
- [ ] `CREATE_FLY` 档在缺少 Create Fly 时明确拒绝启用并给出可读提示。

## 11. 当前实现状态

### 已落地：实体弹匣与集中换弹事务

- `tacz:magazine` 已作为真实 `ItemStack` 保存平台族、弹种、容量与余弹；
- 服务端在换弹开始时预留一只具体弹匣，并只在既有动画状态机的 `FEEDING → FINISHING` 点完成交换；
- 默认 Java 换弹与 `xmag_reload_logic` 等 Lua 脚本的散装弹药 API 调用在物理会话期间被抑制，旧脚本只提供动画时间；
- 潜行退匣、满背包掉落、旧存档整数备弹迁移与 LEGACY 镜像回退已接入；
- 目前覆盖 24 个默认的可拆卸弹匣枪条目，管式/转轮/弹链仍保持旧逻辑。

### 已落地：Create Fly 工业纵切

- 新增碳粉、硫粉、朱砂粉、生铁、高碳钢、高碳钢板、工业推进药、带口径的弹壳坯、带类型/口径的弹头坯、底火组件；
- 26.2 原版硫黄/强效硫黄用于硫粉，朱砂用于朱砂粉和底火组件；
- 新增 Create Fly 研磨、粉碎、加热/炽热搅拌、冲压、压实配方；
- 压实配方已去除重复/同种类数重叠的结果分支：工作盆只产出中性弹匣壳体和中性模具体，最终弹匣族、口径、弹头类型和组件几何由部署器持有的非消耗实体量规选择；
- 9 mm、5.56×45、7.62×39、12G 已改为连续工业装弹：每次工作盆循环装配一发，产量由自动化吞吐而非多发复制配方决定；
- AK / AR / Glock 的模板、机匣、枪机、枪管、击发组、复进组件已作为数据驱动 NBT 部件生产；
- `CREATE_FLY` 档会移除上述四种旧工作台散装弹配方；AK-47、M4A1、Glock 17 的旧工作台成枪配方只有在对应的单工件 `create:sequenced_assembly` 工艺存在并通过校验后才会移除。
- 三把枪均以机匣/枪身为唯一流动过渡工件：蓝图部署器以 `keep_held_item: true` 保留模板，枪机、枪管、击发组、复进组件与外装材料由后续部署器逐站加入；没有任何步骤要求在置物台上同时放多个物品。
- Create Fly 当前 26.2 构建没有打包其 REI source set，TACZ 因此从真实 `recipe/create/` JSON 同步工艺投影，在 REI 中补出完整输入/输出树，并为工作盆多输入与置物台单工件顺序装配明确标注边界；JEI 保持使用 Create Fly 自己的原生展示。
- 终端装配、旧弹药替换和工艺显示均有数据目录约定，详见 `docs/INDUSTRY_DATA_FORMAT.md`；第三方包可以在自己的命名空间声明，而不需要改 Java 硬编码。

其余默认枪、更多弹药、专用供弹结构与拆解回收仍按 Phase 4 继续扩展。
