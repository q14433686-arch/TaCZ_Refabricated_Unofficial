# 真实可拆卸供弹器：工业制造与回归清单

> 对应实现：Create Fly 实体弹匣／实体弹链箱 + 规格量规制造链
>
> 前置：Minecraft 26.2、Fabric、TACZ 当前分支、Create Fly（mod id `create`）

## 0. 范围与不变项

服务端配置：

```toml
IndustryProfile = "CREATE_FLY"
PhysicalMagazines = true
```

- `detachable_magazine` 使用可拆卸 `tacz:magazine`；`belt` 使用同一实体物品承载的弹链箱；
- 默认包当前有 **34 种独立的族／口径／容量供弹器身份**，由 `tools/industry/magazine_carriers.json` 与 `data/tacz/industry/gun_feed/*.json` 双向校验；第三方已验证外部载具走独立 surveyed Gunsmith Table 多槽委托，不伪装成默认包高保真 Create 规格量规线；
- `tube`、`revolver`、`internal_box`、`single_shot` 是枪内供弹状态或枪械组件，**不伪造为可拆卸弹匣**；
- 最终散装弹药仍由专用四槽弹药装配机制造；弹匣、桥夹、漏夹和快装器在玩家真实背包/容器多槽界面中逐发装/退，每发有服务端计时，**不是瞬时背包右键或假装配 GUI**；
- `LEGACY` 档仍使用原有整数备弹行为。

## 1. 新的实体供弹器制造链

旧路线已经删除：不再允许“通用弹匣壳体毛坯 + 一把完整成枪 → 成品弹匣”。完整枪不是弹匣模具。

现在每种可拆卸供弹器均遵循：

```text
Basin：高碳钢板 + 黄铜板/粒
  → 中性弹匣壳体毛坯

Basin：高碳钢锭 + 高碳钢板 + 黄铜粒 + 铁粒
  → 中性供弹组件毛坯

Basin：高碳钢板 + 黄铜板 + 石英 + 铁粒
  → 中性供弹器规格量规毛坯

量规毛坯 + 任一兼容枪的平台生产工装模板（模板保留）
  → 可复用的指定供弹器规格量规

或：量规毛坯 + 一只完全卸空的对应实体弹匣/弹链箱（样本消耗）
  → 同一规格量规

一个中性壳体毛坯在传送带上移动
  + 按规格所需的额外中性壳体毛坯逐个供入
  + 规格量规（保留）
  → 命名的指定供弹器壳体

一个中性供弹组件毛坯在传送带上移动
  + 按规格所需的额外中性供弹组件毛坯逐个供入
  + 同一规格量规（保留）
  → 命名的托弹板/弹簧组件或弹链节/供弹盘组件

指定供弹器壳体（唯一移动工件）
  + 命名供弹组件（部署供入并消耗）
  → 空的实体弹匣或弹链箱
```

这条线的关键约束：

1. Basin 才承接真正多输入的金属原料；
2. 置物台/传送带上始终只有**一个**壳体或供弹组件工件；额外毛坯由后续供料/部署工位逐个加入；
3. 量规是独立、可复用的实物，且真正决定 `MagazineFamily`、`MagazineAmmoId`、`MagazineCapacity`；
4. 最终装配只把两个已经命名的子总成结合，绝不会显示“安装铁粒／木板／石头”这类原料步骤；
5. 75 发弹链箱和高容量/异形弹匣要求更多中性壳体和供弹组件毛坯，成本差异是实际连续供料，不是同输入伪造不同输出；
6. 所有顺序装配最多 5 个真实阶段，低于 Create Fly 26.2 原生 JEI 的 7 阶段上限。

共享标准也是真实共享：例如任一已建立的 30 发 STANAG 兼容平台模板均可校准同一把 STANAG 30 发规格量规；不会任意指定某一把枪“拥有”该弹匣。

## 2. 获取、逆向与回收

### 模板建立量规

1. 制作中性供弹器规格量规毛坯；
2. 将量规毛坯放入传送带/置物台；
3. 供料工位持有任一 `source_guns` 对应枪的平台**生产工装模板**；
4. 预期：模板不消耗，输出带精确族、口径和容量的规格量规。

### 空供弹器逆向量规

1. 将实体弹匣/弹链箱彻底卸空；
2. 让规格量规毛坯作为唯一移动工件，供料工位持有该空样本；
3. 预期：样本被消耗，输出只对应这一族/弹种/容量的规格量规；装有散装子弹的样本因 `MagazineAmmoCount != 0` 不匹配，不能绕过卸弹。

### 工业回收站

1. 输入一只已配置且完全卸空的实体弹匣/弹链箱；
2. 预期：回收站返回中性弹匣壳体毛坯；
3. 要重新投入使用，仍需规格量规成型指定壳体并制作新的供弹组件；不会凭空改造成另一种弹匣，也不会把完整枪当校准工具。

旧世界中已有的 `tacz:magazine_blank` 仍是新壳体成型路线的有效中性输入。

## 3. 装填与换弹

1. 在玩家背包/容器界面把一只新造的实体弹匣、漏夹或桥夹拿在光标上，依次右击同口径 FMJ/AP/HP（12 gauge 则 shot/slug）散装弹槽；
2. 预期：每次右击只启动一发服务器计时；时间结束后 `MagazineRounds` 与 `MagazineAmmoCount` 才增加一发、来源恰好减少一发；错误口径、未知 profile 和满载具均不得装入；
3. 依次装入 FMJ → AP → HP 后，tooltip 的下一发必须为 HP；把载具拿在光标上右击空槽，潜行连续退弹应依次输出 HP → AP → FMJ；来源/输出/载具移动、取消、关闭容器时不得复制、吞弹或换源；
4. 用 AK-47、M4A1、Glock 17、P90、RPK、M249、FN Evolys 分别验证：
   - 单点 `R` 必须在**按下**时立即开始正常换弹，不能等待松键；当前按住 R 也不得弹出轮盘或延迟/吞掉这次换弹；
   - 换弹动画仍由原枪械逻辑提供时间点；
   - 实际物品交换和余弹变动发生在服务端；
   - 混装载具的每次实弹射击必须依次使用顶部 AmmoId：AP/HP/Slug 的投射物、伤害/护甲忽略/穿透、slug 单弹丸和已击发壳都不能退化为基础 FMJ；
   - 枪膛一发、已安装供弹器余弹与 HUD 数字一致；
   - 战术换弹退回半满旧供弹器，背包满时掉在脚边；
   - 潜行退匣只取出实体供弹器，不影响膛内一发。

### Cold War `rainforest:fal` 扩容载具样本

> 前置：安装 `Cold War from 1947-1991 v0.51`，并确认
> `/tacz industry feed inspect rainforest:fal` 报告基础 `20`、原始扩容
> `[25,30,32]`，且适配为已验证的 `detachable_magazine`。这是 main
> 参考包的首个外部载具样本，不是对同 namespace 其他枪的自动推广。

1. 在 surveyed Gunsmith Table 中确认有四条独立供弹器委托，输出容量分别为 `20`、`25`、`30`、`32`；每条均消耗中性弹匣壳体毛坯和 FAL 平台套件，保留 FAL production template 与 survey fixture；
2. **不安装旧 `extended_mag` 配件**时，20/25/30/32 发四种已声明实体 FAL 弹匣都应可被识别、插入和退回；物理载具本身替代原包的虚拟扩容状态，不能要求玩家同时装两张“弹匣”；
3. 分别插入四种容量后，HUD、tooltip、脚本最大容量与实际扣弹必须跟随已安装实体载具，而不是继续显示基础 20 发；
4. 对四个容量分别验证空仓、战术换弹、潜行退匣、取消 reload、背包满时掉落、断线重连和 HUD/膛内一发同步；
5. 将一把旧 FAL 的 legacy 余弹设为 25/30/32 后分别验证：有对应声明变体时绝不截断；若未来包更新 Ammo、基础容量或扩容数组，定义必须被 runtime validator 拒绝并保持 legacy。

## 4. 特殊供弹机制回归

- M870、SPAS-12、M1014：管式供弹按枪内容量逐发从散装弹扣除；
- Rhino/Taurus：转轮按枪内容量扣除；
- RPG-7、M320、双管枪：单发/双膛不能接受实体弹匣；双管空仓一次换弹须真实扣除两发；
- Kar98、M700、SKS：固定内仓按声明容量受服务器控制；不得因本次可拆卸供弹器重构而获得错误的 `tacz:magazine` 插槽；
- AI AWP、M95、M107、AA-12、SPR-15 HB：已审计为可拆卸外部供弹，必须验证各自专用实体弹匣的插入/退匣和独立余弹，不能再退回 `InternalFeedAmmoCount`；
- AUG、B93R、两把 Desert Eagle、SCAR-H、Timeless .50、81-1 式也各有独立已制造实体弹匣；其中只有明确共用 `magazine_family` 的平台可互插。

## 5. 存档、多人和查看器

1. 将旧 `GunCurrentAmmoCount` 枪带入 `CREATE_FLY` 存档，验证首次换弹/退匣的无损迁移；
2. 在 JEI/REI 对规格量规、壳体、供弹组件、成品供弹器分别查看用途与配方：
   - 量规应连到模板校准与空样本逆向；
   - 量规应连到壳体和供弹组件成型；
   - 两个命名子总成应连到最终装配；
   - 成品空供弹器应连回逆向量规；
3. 多人、断线重连、背包/箱子/掉落物转移半满供弹器后，`InstalledMagazine`、`MagazineAmmoCount` 与旧整数镜像必须一致；
4. 客户端篡改 NBT 不能提高余弹，所有抽取/退还仍由 `PhysicalMagazineService` 在服务端完成。
