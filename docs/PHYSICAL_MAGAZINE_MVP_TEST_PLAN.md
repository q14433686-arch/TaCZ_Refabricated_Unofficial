# 真实可拆卸供弹器：工业制造与回归清单

> 对应实现：Create Fly 实体弹匣／实体弹链箱 + 规格量规制造链
>
> 前置：Minecraft 26.2、Fabric、TACZ 当前分支、Create Fly（mod id `create`）

## 0. 范围与不变项

服务端配置：

```toml
IndustryProfile = "CREATE_FLY"
PhysicalMagazines = true
```

- `detachable_magazine` 使用可拆卸 `tacz:magazine`；`belt` 使用同一实体物品承载的弹链箱；
- 默认包当前有 **22 种独立的族／口径／容量供弹器身份**，由 `tools/industry/magazine_carriers.json` 与 `data/tacz/industry/gun_feed/*.json` 双向校验；
- `tube`、`revolver`、`internal_box`、`single_shot` 是枪内供弹状态或枪械组件，**不伪造为可拆卸弹匣**；
- 最终散装弹药仍由专用四槽弹药装配机制造；弹匣装填仍是背包交互／装弹器操作，**没有新增假装配 GUI**；
- `LEGACY` 档仍使用原有整数备弹行为。

## 1. 新的实体供弹器制造链

旧路线已经删除：不再允许“通用弹匣壳体毛坯 + 一把完整成枪 → 成品弹匣”。完整枪不是弹匣模具。

现在每种可拆卸供弹器均遵循：

```text
Basin：高碳钢板 + 黄铜板/粒
  → 中性弹匣壳体毛坯

Basin：高碳钢锭 + 高碳钢板 + 黄铜粒 + 铁粒
  → 中性供弹组件毛坯

Basin：高碳钢板 + 黄铜板 + 石英 + 铁粒
  → 中性供弹器规格量规毛坯

量规毛坯 + 任一兼容枪的平台生产工装模板（模板保留）
  → 可复用的指定供弹器规格量规

或：量规毛坯 + 一只完全卸空的对应实体弹匣/弹链箱（样本消耗）
  → 同一规格量规

一个中性壳体毛坯在传送带上移动
  + 按规格所需的额外中性壳体毛坯逐个供入
  + 规格量规（保留）
  → 命名的指定供弹器壳体

一个中性供弹组件毛坯在传送带上移动
  + 按规格所需的额外中性供弹组件毛坯逐个供入
  + 同一规格量规（保留）
  → 命名的托弹板/弹簧组件或弹链节/供弹盘组件

指定供弹器壳体（唯一移动工件）
  + 命名供弹组件（部署供入并消耗）
  → 空的实体弹匣或弹链箱
```

这条线的关键约束：

1. Basin 才承接真正多输入的金属原料；
2. 置物台/传送带上始终只有**一个**壳体或供弹组件工件；额外毛坯由后续供料/部署工位逐个加入；
3. 量规是独立、可复用的实物，且真正决定 `MagazineFamily`、`MagazineAmmoId`、`MagazineCapacity`；
4. 最终装配只把两个已经命名的子总成结合，绝不会显示“安装铁粒／木板／石头”这类原料步骤；
5. 75 发弹链箱和高容量/异形弹匣要求更多中性壳体和供弹组件毛坯，成本差异是实际连续供料，不是同输入伪造不同输出；
6. 所有顺序装配最多 5 个真实阶段，低于 Create Fly 26.2 原生 JEI 的 7 阶段上限。

共享标准也是真实共享：例如任一已建立的 30 发 STANAG 兼容平台模板均可校准同一把 STANAG 30 发规格量规；不会任意指定某一把枪“拥有”该弹匣。

## 2. 获取、逆向与回收

### 模板建立量规

1. 制作中性供弹器规格量规毛坯；
2. 将量规毛坯放入传送带/置物台；
3. 供料工位持有任一 `source_guns` 对应枪的平台**生产工装模板**；
4. 预期：模板不消耗，输出带精确族、口径和容量的规格量规。

### 空供弹器逆向量规

1. 将实体弹匣/弹链箱彻底卸空；
2. 让规格量规毛坯作为唯一移动工件，供料工位持有该空样本；
3. 预期：样本被消耗，输出只对应这一族/弹种/容量的规格量规；装有散装子弹的样本因 `MagazineAmmoCount != 0` 不匹配，不能绕过卸弹。

### 工业回收站

1. 输入一只已配置且完全卸空的实体弹匣/弹链箱；
2. 预期：回收站返回中性弹匣壳体毛坯；
3. 要重新投入使用，仍需规格量规成型指定壳体并制作新的供弹组件；不会凭空改造成另一种弹匣，也不会把完整枪当校准工具。

旧世界中已有的 `tacz:magazine_blank` 仍是新壳体成型路线的有效中性输入。

## 3. 装填与换弹

1. 拿起一只新造的空实体弹匣，右键点击匹配的 TACZ 散装子弹堆；
2. 预期：`MagazineAmmoCount` 增加、散装子弹减少，错误口径不能装入；
3. 右键点击空槽位：应吐出正常堆叠的同口径散装子弹，不能复制或丢失；
4. 用 AK-47、M4A1、Glock 17、P90、RPK、M249、FN Evolys 分别验证：
   - 换弹动画仍由原枪械逻辑提供时间点；
   - 实际物品交换和余弹变动发生在服务端；
   - 枪膛一发、已安装供弹器余弹与 HUD 数字一致；
   - 战术换弹退回半满旧供弹器，背包满时掉在脚边；
   - 潜行退匣只取出实体供弹器，不影响膛内一发。

## 4. 特殊供弹机制回归

- M870、SPAS-12、M1014：管式供弹按枪内容量逐发从散装弹扣除；
- Rhino/Taurus：转轮按枪内容量扣除；
- RPG-7、M320、双管枪：单发/双膛不能接受实体弹匣；双管空仓一次换弹须真实扣除两发；
- AI AWP、Kar98、M700、M95、SKS、M107、SPR15HB、AA-12：内置弹仓按声明容量受服务器控制；
- 它们不得因本次可拆卸供弹器重构而获得错误的 `tacz:magazine` 插槽。

## 5. 存档、多人和查看器

1. 将旧 `GunCurrentAmmoCount` 枪带入 `CREATE_FLY` 存档，验证首次换弹/退匣的无损迁移；
2. 在 JEI/REI 对规格量规、壳体、供弹组件、成品供弹器分别查看用途与配方：
   - 量规应连到模板校准与空样本逆向；
   - 量规应连到壳体和供弹组件成型；
   - 两个命名子总成应连到最终装配；
   - 成品空供弹器应连回逆向量规；
3. 多人、断线重连、背包/箱子/掉落物转移半满供弹器后，`InstalledMagazine`、`MagazineAmmoCount` 与旧整数镜像必须一致；
4. 客户端篡改 NBT 不能提高余弹，所有抽取/退还仍由 `PhysicalMagazineService` 在服务端完成。
