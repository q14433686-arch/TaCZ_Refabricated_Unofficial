## 1. 【回 §5-1】26.1.2 的 `renderSolidFeatures` / `renderAllFeatures` 调用点全表

来源：CI javap 探针 round 4（commit `9626fe7`，日志在 `build-reports/compile-java.log`），
结论落地于 `99e505f`，全文与审计表见本线 `docs/MESH_GPU_WORLD_FLUSH_TOPOLOGY_2612_20260901.md` §1。

**26.1.2 的 `LevelRenderer.renderLevel` 主 pass lambda 内：**

```
  @220  submitEntities
  @273  renderSolidFeatures()      ← 世界实心几何在这里 draw（flush 真身）
        → translucent
        → particles
        → clear
```

`renderAllFeatures()` 在 26.1.2 只剩**两个站位**：

| 站位 | 位置 | 我们的闸门 |
|---|---|---|
| 手部尾 | `renderItemInHand` 内的手部渲染 | `inHandPass` 拒收 |
| 尾部 | `GameRenderer.renderLevel @570`（`@517 renderItemInHand` **之后**） | 落在 `levelRenderActive` 窗口外，拒收 |

⇒ 消费点挂在 `renderAllFeatures` RETURN 时，**两个站位全部落空**：
vanilla 主通道没人消费世界表（`worldFlushAlive()` 恒假 ⇒ `shouldSubmitGpuWorld` 永久 false ⇒
回退 collector），Iris 26.1 的「level 内手部渲染」又在手部时刻消费它、且 MV 槽被手部污染
⇒ 几何贴在视空间。**正确注入点 = `FeatureRenderDispatcher.renderSolidFeatures` RETURN**（26.1.2）。

### 补充他们 §3 要的那一列：1.21.11 与 26.2 的差异

| 世代 | 结构 | 与 26.1.2 的差别 |
|---|---|---|

| **26.2** | **本线未核**（我们这轮只查了 26.1.2 与 1.21.11 的字节码）。若它仍是「先 extract 后 render」两段式（他们叫 `LevelExtractor`），则 §3 推论成立 | 请 26.2 自查，或让本线跑一轮探针（需要一次 CI 往返） |

## 2. 【回 §5-2】区分「贴视空间」与「绕序×剔除相互抵消」的可复制判据

**两个开关**（`MeshGpuWorld` 与 `MeshGpuUnderShaders`，都支持运行时改、不需重启）：

| 组合 | 现象 | 判定 |
|---|---|---|
| `MeshGpuWorld=false` | 世界 mesh 枪全走 collector | 基线：若此时仍有「贴视空间」，与 GPU 路径无关 |
| `MeshGpuWorld=true` + **无**光影 | 世界 mesh 枪烘焙；第三人称/掉落物正常 | 第一步：证明烘焙与消费点成立 |
| `MeshGpuWorld=true` + **有**光影 | 若几何贴在视空间 ⇒ 症状 2（消费点在 `renderAllFeatures`、MV 槽被手部污染） | 挂到 `renderSolidFeatures` 后应消失 |
| 上述都正常、但**光照/反射方向不对** | 那是**法线矩阵读取时刻**问题（不是贴视空间、也不是绕序抵消），见 §4 | 与 26.2 `83daf16` 同一根因 |

**三条日志**（都能在 `latest.log` 里 grep，前缀 `[TacZMeshLoader]`）：

1. `GPU world submit refused: {reason} …` —— 提交侧被拒的**原因**（`shouldSubmitGpuWorld` 的每一道闸各一条、按原因去重累计）。
   现象 1（永远回退 collector）看它：没有这行 = 没被拒；有这行 = 看 reason。
2. `GPU mesh pass drew N bones (M indices) … world flush` —— 世界 flush **真的消费了**。
   这行不出现 ⇒ 钩子没挂到真消费点（`worldFlushAlive()` 就恒假）。
3. `GPU world-baked N bones (M vertices) at quantized light 0x…` —— 该档烘焙完成（前两次 INFO，之后 DEBUG）。
   烘焙成功但没画 = 消费点问题；压根没烘焙 = 提交侧/额度问题。

绕序×剔除那条不在上述判据里：**它是另一个已结案的议题**（两仓 `MeshPolyMirrorReverseWinding` 均默认 false，
`SYNC_ROUNDUP_R3` §0 共识事实）。若 A/B 后怀疑它，用 `MeshPolyMirrorReverseWinding` 单独翻转再比一次 ——
但注意 collector 路径走 `entityCutout` 剔背面，翻错会让整枪近乎全黑，这是**已知的正常反应**，不是新病。

## 3. 【转 26.2 · 他们 §3 要的推论】「镜外实体偶发消失」与一次性状态袋

本线 `0bf4c482`（用户实机回报后定位，字节码实读 26.1.2 merged jar）：

- `LevelRenderer.renderLevel` 结尾是 `LevelRenderState.reset()`（@560）；
- `GameRenderer.extract → LevelRenderer.extractLevel`（public，@103）**每帧只填一次**那个共享状态袋
  （entities / blockEntities / sky / weather / particles / blockOutline / cloudColor /
  chunkSectionsToRender / cameraRenderState 含 fogData）；
- 窄 FOV 那遍（二次渲染）消费并 reset 了它 ⇒ vanilla 那遍从空袋渲染 ⇒
  **镜外的实体、太阳、雾、天气一起消失**。

修法（本线 `0bf4c482`，待实机）：窄遍之后① 用 `LevelRendererAccessor` 清残留 submit 节点，
② 重跑一次 `extractLevel`（vanilla 等价参数），让 vanilla 那遍看到本帧新鲜的抽取。

**给 26.2 的推论**：1.21.11 的 camera/projection/culling 是 `renderLevel` 的显式参数、没有共享袋
（这就是他们「从来没有这个 bug」的原因）；26.2 若仍是「先 extract 后 render」两段式
（`LevelExtractor`），症状应完全对得上 —— 26.2 那个「镜外实体偶发消失」与 `0bf4c482` 同族的概率很高。
本线只能证明**自己这一代**，26.2 的结构请他们自查（需要的话本线可以跑一轮 26.2 侧探针，一次 CI 往返）。

## 4. 【回 §5 中段】本线 `drawList` 的 MV 栈自查结果：**不是** 83daf16 修前的形状

他们问：本线是不是「压栈 → `prepare()` → 立刻弹栈 → 再绘制」？

**不是。** 本线 `PolyMeshGpuRenderer#drawList` 的形状是**逐 entry**：

```java
modelViewStack.pushMatrix();
modelViewStack.mul(entry.model());
try {
    pass.setUniform("DynamicTransforms", …);
    pass.setVertexBuffer(0, entry.bone().vertexBuffer);
    pass.setIndexBuffer(…);
    pass.drawIndexed(0, 0, entry.bone().indexCount, 1);
} finally {
    modelViewStack.popMatrix();
}
```

即 **pose 留在栈上过完整次绘制才弹**（`finally`，异常也不漏）—— 与 1.21.11 这轮采用的形状一致，
与 26.2 `83daf16` 修后的语义一致。代码注释里也写清了为什么必须这样：
Iris 的 `ExtendedShader.iris$setupState` 在**绘制执行那一刻**读 `getModelViewMatrixCopy()` 的栈顶做逆转置
（不吃 `prepare()` / DynamicTransforms 快照），poly 顶点法线是骨骼本地系裸写，全靠这个矩阵补旋转。

所以本线**不需要**再为「法线矩阵读取时刻」补一刀。这条回应也顺带给 26.2：他们 `83daf16` 的结论在
26.1.2 上是同形成立的（本线早在 `93178de`/`99e505f` 那一轮就落了这个形状）。
