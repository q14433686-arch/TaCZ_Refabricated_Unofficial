# 26.3 → Fabric 1.21.11 差异甄别（2026-10-21）

源：`origin/26.3` @ `e1f57a2`（R1-hotfix2，含 PR #111）；目标：本分支起点 `bdf18af`（1.21.11 R3-hotfix2）。**不是**把 1.21.11 升级到 Minecraft 26.3：此同步代码提交保持 Java 21、Loom remap、原有依赖及当时版本号；后续独立版本号提交将 hotfix2 提升为 hotfix3。按最终代码而不是 26.3 的移植中间态判断。

| 26.3 变更 | 本线实际基线及处置 |
|---|---|
| `382dcb5`：JEI 枪包同步刷新清掉服务端配方 | **按实际依赖改为预防性加固**：本线原先伪造 `AFTER_RECIPES_UPDATED`，但固定依赖 JEI `27.23.0.71` 对应的源码 tag `v27.23.0` 的事件只 stop/start，**没有** `receivedRecipeSync` 或 `Internal.clearClientRecipes()`，故不能说本线现版本已复现 26.3 丢配方。上游 JEI `1.21.11` 分支的后续源码则已添加「无真实同步包就清配方」的门禁。两者的 `getReloadListener()` 均只 stop/start；改由可选 JEI mixin 捕获 listener；无钩子时每次连接最多正常资源重载一次，绝不伪造配方事件。**与 26.3 不同**：本线在 Loom remap 模式，第三方 mixin 的方法选择器不写带 Mojmap 返回类型的描述符，以免生产环境 remap 后不匹配。REI 的全阶段重载风险未修。 |
| `382dcb5`：弹孔六面朝向 | **回移**：本线 `SingleQuadParticle` 也是 XY 四边形，原代码仍直接使用 `direction.getRotation()`。加入 +Z→+Y 基变换及 UV 旋转、法线偏移、相机插值坐标。模型测试覆盖六面，但本线字节码/实机未核。 |
| `c8837d2`：枪匠配方注册表 codec 对旧材料语法惰性解析 | **回移解析边界**：本线 Gson 通道已有 `GunSmithTableIngredient` 的原始 JSON 延迟解析，但独立的 `GunSmithTableSerializer.INGREDIENT_CODEC` 仍直接用 `Ingredient.CODEC` 解码，遇到老包 `{tag:...}` 会在进入 Gson 通道之前被丢弃。现 codec 读 JSON、复用现有延迟路径；编码端尽量用注册表 ops 序列化已解析材料，失败回写原文。CI 已编译通过；仍需带旧包进档测试。 |
| `021b546`：挖多方块工作台上半部双掉落 | **回移**：本线三种工作台的 loot table 已限定根半边（自定义 B/C 台还从根方块实体拷贝 BlockId），非根被挖后 `updateShape` 使根半边走自己的 loot；`AbstractGunSmithTableBlock#playerWillDestroy` 还会手工额外弹出一件，已移除。**不复制** 26.3 的 loot JSON schema（本世代仍用 `conditions/functions/block_state_property`）。需实机验证上/下半部及创造/爆炸。 |
| 26.3 GLSL/renderpearl/Iris 管线预热、`GlRenderPipeline#info`、`setupDraw`、loot schema | **仅 26.3 引擎改动**，1.21.11 的 `blaze3d` / 深度孔径 / 旧 loot schema 不适用；绝不整文件复制。 |
| `f52dab8` GunPackLangCompat | 26.3 `ClientLanguage` 删掉逐命名空间异常兜底才触发的绕过；不预防性覆盖本线语言资源流，更不声称修复枪包坏 JSON。 |
| `c716048` recipe_sync EncoderException | 26.3 新增 Fabric `RecipeSynchronization` 注册才触发的发送路径；本线没有调用此注册 API。保留本线自有同步、不搬其 serializer/RecipeMap 私有 mixin。 |
| `abfaeff` / `146aa42` REI、Zoomify、SSR | 26.3 移植期为缺构件临时禁用，后恢复；本线已各有自己的依赖与兼容层，**不换成 26.3 坐标**。REI 的空材料防护本线有 null→empty 的语义，不能直接复制 26.3 的显示过滤。 |
| `42b0bb2`、`3cddfb7` mesh 纹理预热 / Iris 法线 | 本线已有提交时/自建 pass 前纹理预加载、镜内 poly collector 裁剪及光影逐骨骼独立 pass（见 `docs/MESH_LOADER.md`、`docs/MESH_GPU_IRIS_PASS_LIFETIME_1211_20260908.md`），不把 26.3 的 renderAllFeatures 消费点搬来。 |
| `0a7cd08` YSM 门面 | 26.3 自身也只是**无人调用**的 TaCZ 侧预备契约，ModernYSM `port/26.3` 仍把 compat 排除。目标是本线 1.21.11，不能把它的 `FirstPersonHandsAndItemsRenderer` 注入直接移植到 `ItemInHandRenderer`。本轮**未移植 YSM**，要做须先确认 1.21.11 的 YSM 客户端及双方调用契约，不宣称已兼容。 |

## 验证 / 边界

- `python3 scripts/verify_recipe_viewer_reload.py`：本线十个内置配方资源与 JEI 可选 mixin/生命周期静态约束。
- `python3 scripts/verify_bullet_hole_orientation.py`：六面法线、UV、相机插值、源码接线的数学/文本测试。
- `python3 scripts/verify_263_sync_baseline.py`：本线旧 loot 表、根半边条件、codec 惰性解析/编码静态约束。
- `python3 docs/verify_shader_imports.py` 依赖 Loom 合并游戏 jar；`docs/verify_mixin_targets.py` 依赖 JDK、Loom 合并游戏 jar；本地沙箱缺 JDK，未在本地运行 `gradlew` 或进游戏。提交 `a5f1c95` 已在 GitHub Actions [build](https://github.com/q14433686-arch/TaCZ_Refabricated_Unofficial/actions/runs/39683735416)（完整 `./gradlew build`、mixins 配置/版本门禁）及 [compile-check](https://github.com/q14433686-arch/TaCZ_Refabricated_Unofficial/actions/runs/39683735457) 通过；此后的 JEI 说明更正仅修改注释/文档。静态测试和编译均**不等于运行期验证**：JEI mixin 是否注入、1.21.11 六面弹孔、工作台掉落及旧包注册表仍待实机。
- 本次代码回移提交未改 `mod_version` / 依赖版本；后续独立版本号提交将 hotfix2 升至 hotfix3，仅代表源码号，不代表已发布 Release。建议实机：JEI 查十个 vanilla 型模组配方→枪包同步→检查无 `This fabric server does not provide recipes to JEI`；断线换服重测；挖三种工作台上/下部确认只掉一件（自定义 B/C 台还须带 BlockId）；含旧 `{tag:...}` 材料枪包装载和工作台合成；六面弹孔无光影/Iris。
