# 接收单：Fabric 26.1.2

**OPEN。** 接收基线 [`569869f`（R3-hotfix4）](https://github.com/q14433686-arch/TaCZ_Refabricated_Unofficial/tree/569869f107a60aacfa211c4fc658fcd1c58aee93)。供体和分批用例见[总表](README.md)。这是两条 Fabric 线中更适合先搬公共逻辑的一条：Java 同为 **25**，不必 remap；但资源打包与渲染都不是 26.2 的做法。

1. **保留目标工具链。** [目标构建](https://github.com/q14433686-arch/TaCZ_Refabricated_Unofficial/blob/569869f107a60aacfa211c4fc658fcd1c58aee93/build.gradle)使用非混淆 Loom、Loader `0.19.3`、Fabric API `0.155.2+26.1.2`、Forge Config API Port `26.1.5`。先在此环境接覆盖层、分片、玩法时钟与装拆结算；配方/进度/loot 用本版 codec 解读。转换层应匹配 `[26.1.2]`，完整栈用运行中目标的 DataVersion，不写死 26.2 的 `4903`。
2. **先查旧 JAR 的有效资源，再动默认包。** `processResources` 用 `resources/tacz-26.1.2-source-and-resource-bundle.jar` 兜底、`DuplicatesStrategy.EXCLUDE` 去重；`src/main/resources` 的文件数不是已有内容数。保持 bundle 不动，把新资源和有意覆盖放进源码，对退役路径在 `from(zipTree(...))` 内显式排除，否则旧 OEM 配方会复活。逐项比对打包后每个路径的来源和散列。一个真实冲突：目标 `glock_17.animation.json` 已去掉 `draw.sound_effects` 的悬空 `p24_pi_golf17_stockskel_raise`，而 26.2 的 1.2 动画仍含这条、其他内容也有变化。不要在「保住旧修复」与「接收新动画」之间直接选整文件；核对差异、许可和实际资源解析结果，并让目标资源守卫检验选定的版本。
3. **先验证制作，再接查看器。** 先在无可选模组的专服手摆 3×3、专用台各做一次足料／缺料；然后分别用 JEI `29.5.0.26` 与 REI `26.1.819`。目标 `RecipeViewerReloadBridge` 有 JEI recipe-update 和 REI 全插件重载路径，不能照搬 JEI 30 转移接口，或把全量重载当作无损刷新。检查本版插件生命周期，只更新自己创建的展示；普通合成、包定义的工作台、改名同 `BlockId`、仅专服新增的配方都要在重载后复查。[作弊给物另测](README.md#rei)。
4. **不要移植离屏镜孔渲染器。** 目标 [`ScopeDepthCopyState`](https://github.com/q14433686-arch/TaCZ_Refabricated_Unofficial/blob/569869f107a60aacfa211c4fc658fcd1c58aee93/src/main/java/com/tacz/guns/client/render/scope/ScopeDepthCopyState.java)已有「备份世界深度 → 目镜写深度 → 拷贝镜孔 → 还原 → 分划采两份深度」；沿这条路径传裁剪方向。在 `ScopeFinalOverlayState` 接冻结的真实分划；热像读取世界深度而非目镜写过的深度，采样纹理与测试附件分开。保留 `ScopePipRerender` 窄视场一遍结束后重提取主遍状态的逻辑；退出 ADS 后镜外实体、天空和地形不能消失。先做[红板、刻线与热像墙对照](README.md#optics)，再开可选重渲染，不用 26.2 的 `ScopeMaskTarget` 替换整套流水线。

**目标仓根目录的第一道检查**（Bash，`PRODUCT_JAR` 指本次构建的实际模组 JAR，不是 sources/bundle）：

```bash
bash scripts/check_release_consistency.sh --strict
./gradlew clean build
python3 scripts/check_visible_bug_resources.py --jar "${PRODUCT_JAR:?指定 build/libs 下的成品 JAR}"
sha256sum "$PRODUCT_JAR"
```

上述资源脚本在基线还会和旧动画逐字段比对；接收新资产时应保留「不再引用缺失音效、成品只含一个正确覆盖件」的断言，另钉新的来源，不要直接关掉检查。最后用这份 JAR 进入**独立的 26.1.2 专服与客户端**，跑[总表](README.md)的升级、重载/退出/重连、库存和画面对照。CI 编译或集成服务器通过不能替代这一步。
