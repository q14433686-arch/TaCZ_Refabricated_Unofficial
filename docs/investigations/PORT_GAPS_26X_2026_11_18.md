# 26.X 实际待移植项复核（2026-11-18）

> **历史快照**：本文的「普通 26.3」固定指合并前的 `cc990c3`，不是不断移动的 `26.3` HEAD。要从已验证的新版向旧线移植，请从[三线交接单](../lineage/26.3-backports/README.md)开始。

**在当时的两个快照上，26.3 不能共用一张待办表。** `26.3_tacz-1.2.X` 的默认包已覆盖目标的全部 4,176 个有效目的地。它还缺的是具体行为，例如改绑鼠标键后触发动作、展示架放置预览、第一人称动画约束、部分粒子材质，以及可选模组接入。普通 `26.3` 和 `26.1.2`、`26.2(main)` 则还没有整组 1.2 玩法、协议和资源。`26.4` 分支名也不代表已移植到 26.4。

本次是**审计，不是修复或发布**。以 [Sh1roCu 的 1.21.1 Fabric `356bdf9`][up]（`1.0.1-neo1.2.0-hotfix+mc1.21.1`）为行为目标，不把原版 NeoForge、其它附属或更新设想自动算进欠账。旧基线是 [`d290355`][old]（`0.7.0-forge1.1.8-hotfix`）。检查了全树、两版间的改名/新增/修改/删除、构建与资源覆盖规则；对候选缺口再追注册、调用方及已有替代路径。下文的「确认」指在固定源码里能指出行为分叉；没有把它写成这次在游戏里复现了故障。

## 2. 26.3 特性线：确认还缺的行为

下列验收是**下一步怎么判定已补齐**，不是本轮新跑过的测试。建议先处理 ①–⑤：它们直接影响玩家操作或包作者已经写进模型/特效的数据，不依赖外部模组发布。

| 项目 | 目标与当前实现的具体差别 | 最小验收 |
|---|---|---|
| ① 键鼠重绑、独立卸弹 | 上游注册的 [`GunInputHandler`][up-input] 按实际绑定同时分派键盘/鼠标。本线换弹、检视、改装等仍接键盘事件，切换式瞄准的按下入口只接鼠标（按住瞄准另有 tick 读取）。[本线 `ReloadKey`][reload] 的 **Alt + 已绑定的换弹键确实会卸弹**，但没有独立可改绑的卸弹动作。 | 换弹/检视/改装改鼠标侧键、切换瞄准改键盘，分别按下/释放；独立绑定卸弹，确认普通换弹不被吞、卸弹不触发换弹。不要照搬目标 Fabric 中卸弹和换弹默认均为 R、修饰键判断不完整的冲突。 |
| ② `constraint` 骨骼负值 | 上游 [旋转][up-rot]、[位移][up-pos] 均先取幅值，再混合。本线 `ConstraintRotateListener` 仍把 −1° 环绕为 359° 而不是 1°；`ConstraintTranslateListener` 保留符号，混合取最大值时可能丢掉负向幅值。不是废类：[`BedrockAnimatedModel.supplyListeners`][model] 选择它们，[第一人称变换][fp] 读取同一个对象。默认 `kar98` 的模型有该骨骼，`static_idle` 就有负位移。 | 同一骨骼给等幅正/负关键帧，分别测普通更新、blend、切动画后复位；比较约束输入以及实际手部姿态。不要把所有 ADS 偏移问题都归因于此。 |
| ③ 第一人称曳光的参考帧 | [上游][up-trace] 在该弹第一次渲染时保存枪口偏移和完整相机四元数（含 roll），以后用该弹的快照。[本线][trace] 虽保存初始偏移/欧拉角，实际平移却每帧读**全局** `muzzleRenderOffset` 和**当前** `camera.rotation()`。这是客户端显示差异，不是服务端弹道或伤害错误。 | 在游戏中让同一条近距离曳光跨数帧可见，转头/倾斜或切枪；检查它没有重新跟随新枪口。保持已有的手部基座校正、远距衰减及第三人称对照。 |
| ④ 挂板/展示柜的放置预览 | 上游两个方块渲染器均有 [`renderPlacementPreview`][up-rack]：对准可用空格时绘制手中物品的单件预览，alpha 0.65；潜行、锁柜或格内已有物品时不绘制。[本线 `DisplayRackRenderer`][rack] 跳过空槽，只提取实际物品；[`DisplayRackHighlight`][outline] 画目标格线，不画手持物品模型。**缺的是预览，不是放置、旋转、锁或存储。** | 挂板、拐角、开锁柜各对空格预览并放入带配件物品；锁上、潜行、换不可展示物、对准已占格时不留残影，预览不改库存。 |
| ⑤ Snowstorm 材质与朝向 | 核对了目标**实际捆绑的 2.6.3 JAR**，见下文。其手部粒子 `particles_alpha` 与 blend 均走半透明；add、energy swirl、emissive 走各自分支。本线 [`submitEmitter`][emit] 把 alpha 与 opaque 走 cutout，后三者合用一个 swirl 路径，镜内也合并。上游传真实相机 pitch/roll；本线向 [`BillboardHelper`][billboard] 传 `0,0,null`，其中 `ROTATE_Y`/`LOOKAT_Y` 会实际用到前两项。已有洋红探针可见不证明这几类等价。 | 用同一张带渐变透明度的原创贴图区分六种材质，在深色/亮色背景、相机俯仰/侧倾、镜内外各取对照；世界与手部、普通与 Iris 分开。不以出帧次数替代画面差异。 |
| ⑥ 游戏内燃烧弹的命中碎屑 | 上游 `ServerMessageBulletHitBlock → HitBlockEffectHandler → HitSurfaceParticleSpawner` 将 `incendiary` 传到表面碎屑生成器，据此选择 `LAVA` 而不是方块材质。本线[命中消息][hit] 不带该位，[生成器][fragments] 固定用方块碎屑；服务端另发的熔岩粒子仍在，不能代替受数量/客户端开关控制的这批碎屑。 | 同一测试方块分别用普通/燃烧配置，改变 `hit_block_particle_count`，开关命中粒子；区分服务端单独效果、表面碎屑、弹孔和脚步材质音，不能重复配送。 |
| ⑦ 多包创造栏排序 | 上游 `ContentPackOrder` 让 `tacz` 优先、其它 namespace 字母序，枪/弹/配件再按包内 `sort`；工作台也按 namespace。本线 `AbstractGunItem`、`AmmoItem`、`AttachmentItem` 只按数值，`GunSmithTableItem` 没有此排序。包筛选按钮把 `tacz` 提到首位，不会重排「全部」页签的物品。 | 装两个 namespace，使用互相交错的 `sort`；在全部列表及重载后看四类物品的真实顺序。 |
| ⑧ 工作台空筛选提示 | 上游 `GunSmithTableScreen.addEmptyByHandFilterHint` 在因手中物品筛选而无结果时解释原因，并给出一键清除、重置页码的按钮。[本线界面][smith] 已能按手中物筛选和接受 viewer 选方，但没有这个空状态入口。 | 手持无匹配配方的物品进入工作台；从空页点清除恢复列表。不把 JEI/REI 转移误实现成移动材料：这里的转移只选配方。 |
| ⑨ 配件/方块物品说明 | 对比 `ClientAttachmentItemTooltip`：目标按能力显示测距、火控标记、余弹计数，并区分增/减枪焰与烟；本线已有 OEM、倍率、热像和 modifier 提示，**缺上述几类的条件展示**。目标 `ModItems.GUN_DISPLAY_CASE` 还追加柜子说明，本线注册为普通 `BlockItem`。翻译键在资源里不等于玩家能看到。 | 分别悬停有/无对应能力的物品；与实际 display 对照，中英文各测一次。不重复已有的后坐推动提示。 |
| ⑩ 包作者/下游 API | 上游 [`TimelessAPI`][up-api] 公开 `getAllClientAttachmentVariantIndex()` 和 `getAllClientSlotAdapterIndex()`；[本线][api] 有按 ID 查询及 common 端全集，但没有这两个客户端枚举入口。改装界面能用并不能替代下游 API。 | 客户端扩展通过公开 API 枚举、按 ID 反查，重载后结果更新；专服不加载客户端类。 |
| ⑪ 升级已有配置、默认包再导出 | 上游 `AmmoBlockConfigRead` 调 `AmmoConfig.migrateLegacyDestroyBlocks`，仅当列表**恰等于**旧的两个 `#forge:` 玻璃标签时才保存为 `#c:`；本线新配置默认值正确，但不迁旧文件。另一个独立差别：`GetJarResources` 的导出指纹有资源条目信息，但没加入目标的 `mod-version`，仅版本变化时不会据此判定重导出。不是「修改资源也检测不到」。 | 用旧默认/自定义/新默认三份 TOML 对照；再用资源指纹不变、仅 mod 版本不同的两个测试包验证导出/备份策略，保留用户自定义。 |
| ⑫ 管理员诊断命令 | 上游 `RootCommand → DebugCommand → PegboardStressCommand`；本线只有 `/tacz debug <bool>`，没有 `/tacz debug pegboard …` 的批量展架场景。这是开发/压测工具，不是玩家挂板功能。 | 在测试世界核对权限、子命令、场景上限与清理，再单独测性能。 |

**粒子证据的版本很重要。** 对照物是 [`libs/simplebedrockmodel-fabric-2.6.3+mc1.21.1.jar`][sbm-jar]，SHA-256 `2097d96a9d7ee97ffab2a4ac2249067262362850d6a19154dcde61687959ae3c`。检查了 `ParticleRenderer$1` 的枚举映射、`ParticleRenderer.getRenderType` 的实际分派、`FirstPersonRenderHandler.renderParticlesNow` 到手部粒子系统的调用。公开 [Fabric 源码][sbm-f] 所查版本为 **2.6.2**；[本线移植署名来源][notice] 也不是那份 2.6.3 二进制。这里是渲染输入/管线差异的证据，不是两台游戏的像素实测。

## 3. 已定位差别，但不宜直接照搬或定性为故障

| 范围 | 证据、边界与决定条件 |
|---|---|
| 测距/落点的极端参数 | 目标 `Rangefinder` 没有本线的 1,024 格查询上限和 32 倍标记比例上限。目标 `RangefinderManager` 以视线和最多 600 tick 算预览；本线 `RangefinderReadout → ImpactPreview` 还尊重弹丸寿命，超寿命/不可达时不画，`ImpactMarkerRender` 走实际相机投影。默认 XM157 有像素测试。需要对大值、短寿命、俯仰、经典/PIP 做对照，决定哪些是应保留的预算/显示规则；**不建议解除查询上限，也不是缺整个测距功能**。 |
| 子效果脚本作用域 | 2.6.3 的 `EventExecutor.executeParticleEffect` 在**父** Molang 上下文执行 `compiledPreEffect` 后创建子发射器；本线 `EventExecutor → WorldEmitterManager.addEmitter` 在新**子**环境中执行 `pre_effect_expression`。对需要父变量或期待父状态改变的包不是同一契约。用父/子各自读写同名变量的事件夹具决定兼容策略；不把 `pre_effect_script` 总体列为未支持。 |
| 普通发光骨骼与格线 | 上游 `BedrockPart`/`FunctionalBedrockPart` 对 `*_illuminated` 不只给满光照，还经 `UnshadedVertexConsumer` 改法线。本线通用快照传 `partLight` 与原法线，另有镜内发光准星专用材质。上游展示格线显式 `NO_DEPTH_TEST`，本线提交 `RenderTypes.lines()`。分别测非准星发光骨骼的多方向照明、格线被已放物品遮挡的画面；不把两者说成「发光/格线未实现」。 |
| 结构旋转 | 目标对 `AbstractGunSmithTableBlock`、`TargetBlock`、`StatueBlock` 显式旋转 `FACING`，本线三者继承 `BaseEntityBlock`，没这些 override；柜、板、弹药库另有 rotate。本地可检的原版 **26.2** 字节码中 `BlockBehaviour.rotate` 原样返回 state，`Block`/`BaseEntityBlock` 未改写；这**不是** 26.3 结构放置实测。用各目标版本的结构模板旋转 90°/180°，核对朝向、多格工作台配对与 BE 数据后定级；普通手动放置是不同路径。 |
| 第三人称与外显性能 | 上游 PlayerAnimator 有 tick/render-pre 每实体每 tick 去重及手部上下文隔离。本线用 PAL 四层控制器、render-state 下的模型/手臂处理和原生 collector；有外显、近/远 LOD、弹壳、按资源重载重建的 `GunRigBaker`/`DisplayBake`。需要 PAL 玩家离屏再入镜、切枪/F5、Iris 和大规模展架的帧序/耗时对照。不是缺整套第三人称，也没有证明旧 VBO 的性能已复现。 |
| 旧包转换 | [本线转换器说明][conversion]：可生成经本版 codec 检查的 overlay；严格 Forge share-tag、`forge:tag_empty` 等不能证明等价的条件要报告/人工处理。已有 DFU、组件合并、合法配方加载，不应把安全拒绝写成无损支持，或为通过样例而静默改义。 |

## 4. 旧线真正需要回移什么？

按 `compat_1_21_1` 的胜出文件和 26.X 单数数据目录对齐，**不是直接做两个工作目录的 `diff`**。目标内置包 4,405 个物理文件，229 个被同包 overlay 覆盖，得到 **4,176** 个目的地。这 229 个被覆盖文件与下表的 **229 个索引**恰好同数，含义不同。

| 本地固定树 | 有效文件 | 与目标同路径 / 其中同 blob | 缺目标路径 / 额外旧路径 | 索引：枪 / 配件 / 弹药 / 转接座 / 工作台方块 |
|---|---:|---:|---:|---|
| 26.3 特性线、Arena 审计快照 | 4,176 | 4,176 / 3,929 | **0 / 0** | **70 / 126 / 25 / 5 / 3** |
| 26.1.2、26.2、普通 26.3、名为 26.4 的基线、PR #108 head（各自计算） | 3,322 | 3,314 / 2,415 | **862 / 8** | **54 / 99 / 24 / 0 / 3** |

- **26.1.2 不是空包。** [`processResources`][bundle-build] 读取跟踪的 `resources/tacz-26.1.2-source-and-resource-bundle.jar`，源目录显式资源优先。包内 3,322 项与源码的一项 `glock_17.animation.json` 覆盖合并后仍是 3,322，不是 1 或 3,323。其它旧树在源码目录提供 3,322 项。此处是按构建规则核算，不是声称本次重新打了各版 JAR。
- 特性线的另外 **247** 项有[逐文件来源与适配规则][pack-ledger]：202 配方、23 进度、12 处未分配动画轨道、5 份装填脚本、2 份 ADS 行走脚本，loot、metadata、README 各 1。[包外资源][outside]另记。本次只读重算与离线校验通过；[246 条未解析引用][source-gaps] 是已记录的目标包例外，**没有新缺失目的地**不是「每个上游引用都有效」。
- 旧线实际没有目标的 `qr_24`、`mcx_spear_lt`、`scope_xm157`、`scope_xl50` 等索引，不是仅缺翻译；仅同路径的文件就另有 899 个不同 blob。**862 是文件数，不是还缺 862 把枪或 862 个功能。** 用文末 `--paths` 可导出缺失、不同以及那 8 个已退役资源的完整名单。三个方块索引相同也不代表注册了新版的储物/展示方块。

以下是在这五个旧线/快照树中核对的**成组回移任务**。建议按从上到下的依赖顺序做，而不是直接拷 862 个文件。每条线须按自己的映射、加载器、资源格式、网络能力重新验收。

| 回移包 | 旧线已经有，勿重做 | 仍需补的 1.2 能力；回移后的验收点 |
|---|---|---|

## 5. 可选集成：有依赖但没接，与还没核实依赖是两件事

| 集成 | 证据与结论 |
|---|---|
| **MrCrayfish Controllable：可着手适配** | 26.1.2 [门面][controller-old] 在 mod 已加载时实际注册绑定并分派震动，Gradle 有 compile pin；这不是它已对齐新版全部手柄行为的证明。26.2、两条 26.3、名为 26.4 的基线和 PR head，`ControllableCompat.init/onGunShoot` 是空方法，构建排除 `ControllableInner`。官方已有对应 **Fabric** 签名 JAR：[26.1.2][pad2612]、[26.2][pad262]、[26.3][pad263]。26.2/26.3 不是「等作者出 Fabric 版」，而是要接新版绑定、按住/释放、键鼠与手柄状态及震动；同时测不装 mod 的启动和装 mod 的真手柄。未核实 26.4 快照的可用构件。不是 Controlify。 |
| **Sable / Simulated：缺适配，目标版本依赖待核实** | 上游有移动子世界坐标、射线、弹孔附着和展架姿态；Simulated 通过 `SimBlockMovementChecks` 带走装配的配对方块/相连柜。本线没有这些接点。所查 [Sable Fabric 发布][sable] 对应 1.21.1；[上游构建][up-build] 用 Sable 2.0.6，Simulated 仅 `compileOnly` 1.21.1 common 1.3.2，并有运行时门控。不能把普通世界的命中/结构测试当成移动子世界测试。 |
| **EMI：独立插件缺失** | 目标 `fabric.mod.json` 有 `emi` 入口，含工作台、双向查询及选方；本线没有。已过的 JEI/REI 不能代替 EMI。所查 [EMI 官方发布][emi] 有 1.21.1 产物，未验证各 26.X 的 Fabric 运行时。 |
| **Accelerated Rendering：禁用，不是已修复** | `ARCompat.shouldAccelerate()` 返回 false，普通 collector/TML 不等于跑了 AR。[公开 Fabric fork 的构建目标][ar] 是 1.21.1。需先确认各版 API/artifact，再验证渲染顺序、重载与其它渲染 mod 共存。 |
| **KubeJS：不是相对这个目标新丢失的事件能力** | 旧、新 Fabric 上游的 [`KubeJSGunEventPoster`][kjs-poster] 三个投递体本来就注释；事件对象、metadata 或翻译存在，不代表事件送到了 KubeJS。[所查 KubeJS 2603 构建][kjs] 面向 NeoForge。可单列为新增兼容需求，不列为恢复已运作的 Fabric 1.2 事件桥。 |

「未验证构件」只说明本轮在可核实的发布/源码里没有建立可运行组合，不证明全网不存在版本。不应硬装 1.21.1 JAR，也不应仅去掉 `return false` 就宣称支持。

## 6. 哪些不用再报“完全没移植”？哪些还须实机？

- **已接入**：特性线的仓储事务与 BE 持久化、展示格选取/锁、OEM/变体/转接座、卸弹和动作后事件、射手位移/枪声仇恨、枪模 `%ammo_count%`、版本警告、JEI/REI 选方都有生产调用方。两个 variant/adapter 包合并为 `ClientMessageSelectRefitOption` 不等于丢了两条操作。`LocalPlayerShoot` 在客户端线程检查会话 epoch、玩家、栏位、当前枪及暂停时钟，数据清理会取消任务；没有按上游文件名照搬不是「连发完全不清理」。
- **粒子不是空壳**：[现行实现账本][snow] 及 `SnowstormSmoke`、`RemoteParticleSmoke` 涵盖自定义定义、Molang/曲线/脚本、进入过渡的事件、可见像素、追踪实体 S2C 与到期回收。本线用接收方已有的动画事件指纹，不接收任意远端脚本。真实双客户端、缺相同包的对端、大批发射器及材质/朝向组合仍须验收；不把这份工作退回为「从零移植 Snowstorm」。
- **不能用键名替代消费检查**：按全局字面值查，目标新增的 75 个 `@SerializedName` 键在特性线都找得到；新增配置键中未对上的为两个旧 VBO 选项和 Sable 选项。新增翻译项也对照了目标 locale。§2 的 tooltip、输入和渲染差别说明，JSON/翻译存在仍可能没有对应行为。反之，仓库没复制的整套 `data/c/tags` 镜像、旧 GL shader 描述、NeoForge 包名或 KosmX 类名，不应逐文件当作待移植；应看 Fabric conventions、原生 shader/collector、PAL 等实际消费者。
- **不属此次核心范围**：目标本身 `ModernKineticGunItem.getLevel/getExp/getMaxLevel` 仍返回 0，glTF `Spline` 仍是桩。LRTactical 的 `flash_shield`、未获授权的外部素材、YSM 对端握手各有自己的实现/许可/联调边界。它们不应挤占「从此 Fabric 目标移植」的清单。
- **已有的运行证据**：同一特性线源码 `9bafb4d` 上，[完整 build、JUnit/服务端及普通 Vulkan 客户端、JAR][ci-build]、[compile-check][ci-compile]、[Iris/Sodium + 自编光影][ci-iris]、[JEI 与 REI 两个独立运行作业][ci-viewers] 均 success。`WorldReturnSmoke` 保留关世界/重开；光学/热像和 XM157 有固定场景正负对照。**本轮没有启动新客户端，也没有运行其余分支。** 一台集成客户端收到追踪实体消息不是两个真人客户端；CI 光影不是用户的 Complementary/Euphoria/DH/独显和多外置包；viewer 页面不是所有实际转移点击。另须独立验证真二次渲染热像、实际手柄、第三方包，以及 §2–3 的场景。
