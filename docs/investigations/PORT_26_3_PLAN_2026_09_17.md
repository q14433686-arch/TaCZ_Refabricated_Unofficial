### 2.2 `RenderPipeline.Builder` —— **比评估乐观**

9-02 评估据 Fabric 的 `@ModifyArg` 目标签名，推测 builder 改成了 `Map<ShaderType, Identifier>`。
**实测 Iris 26.3 的 `CompositeRenderer` 仍在链式调用 `.withVertexShader(...).withFragmentShader(...)`**
⇒ **public builder API 未变**，变的只是它内部构造 `Snippet` 的私有签名（那是 Fabric mixin 的事，不是我们的）。

⇒ 本仓 11 处 `RenderPipeline.builder(...)`（`withVertexShader`×13 / `withFragmentShader`×13）
**预计只需改 import**。仍列为「待编译确认」。

### 2.3 第一人称渲染：**一分为三**（本轮最大发现，评估只说对了一半）

9-02 评估写「`ItemInHandRenderer` → `net.minecraft.client.player.FirstPersonHandsAndItems`」。
**这不完整**。实测 26.3 同时存在三个类，职责被拆开：

| 26.3 类 | 角色 | 证据 |
|---|---|---|
| `net.minecraft.client.player.FirstPersonHandsAndItems` | **状态/tick 侧**：持有 `mainHandItem`/`offHandItem`，有 `tick(LocalPlayer)` | Fabric `FirstPersonHandsAndItemsMixin`：`@Mixin(FirstPersonHandsAndItems.class)` + `@Shadow ItemStack mainHandItem` + `@Inject(method="tick")` |
| `net.minecraft.client.renderer.FirstPersonHandsAndItemsRenderer` | **渲染侧**：`submitHandsWithItems(...)`、`submitArmWithItem(...)` | Iris `MixinItemInHandRenderer`：`@Mixin(FirstPersonHandsAndItemsRenderer.class)`，`@Inject(method="submitArmWithItem")` |
| `net.minecraft.client.renderer.state.level.FirstPersonHandsAndItemsRenderState` | **渲染状态对象**（新增） | Fabric `RenderStateMixin` 注册表 + `PlayerRenderState.firstPersonHandsAndItems` 字段 |

**对本仓的后果（严重，是本轮主要工作量）**：
`ItemInHandRendererMixin` 现在**同时**用到两侧 —— `@Shadow mainHandHeight/oMainHandHeight/mainHandItem`
+ `@Inject(method="tick")`（属状态类）与 `@Inject/@WrapOperation(method="submitHandsWithItems")`
（属渲染类）。**一个 mixin 无法同时 `@Mixin` 两个类** ⇒ **必须拆成两个 mixin 类**。

且 `submitHandsWithItems` / `submitArmWithItem` **签名全变**（26.2 传 `LocalPlayer`+`int light`；
26.3 传 `PlayerRenderState` + `FirstPersonHandsAndItemsRenderState`）：

```
26.2: submitHandsWithItems(float, PoseStack, SubmitNodeCollector, LocalPlayer, int)
26.3: submitHandsWithItems(float, PoseStack, SubmitNodeCollector, PlayerRenderState,
                           FirstPersonHandsAndItemsRenderState)

26.2: submitArmWithItem(AbstractClientPlayer, float, float, InteractionHand, float,
                        ItemStack, float, PoseStack, SubmitNodeCollector, int)
26.3: submitArmWithItem(PlayerRenderState, FirstPersonHandsAndItemsRenderState, float, float,
                        InteractionHand, float, ItemStack, float, PoseStack,
                        SubmitNodeCollector, int)
```

⇒ `@WrapOperation` 的 `target=` 描述符字符串、wrapper 方法形参表、以及所有从
`AbstractClientPlayer`/`LocalPlayer` 取数据的逻辑（`FirstPersonAnimationCompat.getMainRenderStack`
等）都要改走 render state。**`KeepingItemRenderer` 的收枪/拔枪 `keep()` 路径落在状态侧**，
拆分时必须确认它跟到 `FirstPersonHandsAndItems` 那一半。

涉及 12 个文件引用 `ItemInHandRenderer`；`GameRendererMixin` 的 `renderItemInHand` 注入点
在 26.3 仍在（Iris `MixinGameRenderer` 有 `@Redirect(method="renderItemInHand")`），
但被 redirect 的目标方法签名已按上表变化。

### 2.5 Shader：`#moj_import` → `#include`

6 个 scope shader 共 **18 行** `#moj_import <minecraft:*.glsl>`（评估说 17 行，实测 18）：
`scope_body.fsh`(3) / `scope_body.vsh`(5) / `scope_pip.fsh`(2) / `scope_ring_final.fsh`(1) /
`scope_text.fsh`(3) / `scope_text.vsh`(4)。

- 26.3 起 OpenGL 也走 ShaderC，include 由 ShaderC 处理，`#moj_import` → `#include`。
- `#version 330`：本仓 6 个文件全是 `#version 330`。**Iris 26.3 自己的 shader 仍在用
  `#version 330 core` / `#version 150 core`** ⇒ 该版本号在 ShaderC 下**大概率仍可用**，
  但**未实测**，列为运行期风险。
- ⚠️ **shader 改动编译期完全测不出**，只能真机加载 scope 才知道。

### 2.6 OIT（**最大的未知，本轮无法消除**）

半透明不再排序，Mojang 自述会引入视觉瑕疵。命中面：镜内遮罩、PIP、目镜环、镜内文字、
枪口焰、半透明配件。26.2 线的 scope 是「`ColorTargetState.WRITE_NONE` + mask sampler」路线。
Fabric 26.3 新引入 `gameRenderer.useImprovedTransparency()` 与 `ModelBakery.DESTROY_TYPES_OIT`
两条分支，说明 **OIT 是可开关的、且 vanilla 自己按开关选不同 RenderType** ——
我们的自建管线是否也要跟着分叉，**必须真机在 F3+X 两态下验证**。

## 3. 分阶段执行计划

### M0 · 坐标与元数据（本轮已做，无编译风险）

1. `gradle.properties`：MC/loader/Fabric API/FCAP/Cloth/JEI/ModMenu/PAL 换 26.3 值；
   `mod_version=1.1.8+fabric.26.3.R1`；摘掉 REI/Zoomify/SSR/architectury 的版本项。
2. `build.gradle`：依赖坐标同步；`sourceSets.exclude` 增补 REI/Zoomify/SSR 的 IMPL。
3. `fabric.mod.json`：`minecraft: "26.3"`、`fabricloader >=0.19.5`、`forgeconfigapiport >=26.3.0`；
   摘 `rei_client`/`rei_common` 入口；`name`/`description` 改 26.3 R1 措辞。
4. `README.md` **6 处**同步（AGENTS.md §1 强制）+ 导航表新增 26.3 行。
5. `scripts/check_release_consistency.sh`：`TACZ_BRANCHES` 默认值需要加入 26.3 线
   —— 否则导航表检查会要求 README 有一条不存在的分支链接。**这一步容易漏。**

### M1 · 机械移植到编译绿（靠 CI 迭代，预计 3–6 轮）

1. **包迁移**：按 §2.1 表做 import 替换（20 文件）。
2. **第一人称拆分**：按 §2.3 把 `ItemInHandRendererMixin` 拆成
   `FirstPersonHandsAndItemsMixin`（状态/tick/keep）+ `FirstPersonHandsAndItemsRendererMixin`
   （submit 系列），改 `tacz.mixins.json`，改 `@WrapOperation` 描述符与形参表。
3. **CrumblingOverlay 删参**：3 个 BER 的 `extractRenderState` 去掉尾参数。
4. **TranslucentFeatureRenderPhase 删类**：改 `FeatureRenderPhase<? super TranslucentSubmit>`
   或直接摘掉该 mixin（**需评估它保住的 scope 语义是否还成立** —— 不是纯机械改动）。
5. **shader**：18 行 `#moj_import` → `#include`。
6. 每轮：`git push` → 读 `build-reports/compile-java.log` → 按真实 javac 错误继续。
7. **M1 出口**：`compile-check` 绿 **且** `build` 绿。
   ⚠️ 编译绿**不等于** mixin 注入成功 —— 方法级注入点只能运行期验证。

### M2 · 运行期验证（**本轮不可能完成，必须由维护者在真机做**）

## 5. CI 闭环用法（本仓既有机制，不另造）

- `.github/workflows/compile-check.yml`：`arena/**` push 会把 javac 日志回推到
  `build-reports/compile-java.log`（头 200 + 尾 800 行），沙箱可直接读文件。
- `.github/workflows/build.yml`：全量 `./gradlew build` + 三项静态校验
  （mixin 配置完整性 / 中英语言键齐平 / 版本一致性）+ jar artifact（14 天）。
  ⚠️ 它 `paths-ignore: '*.md'` ⇒ 只改 README 的提交不会触发。
- `.github/workflows/consistency.yml`：改 `gradle.properties`/`README.md` 即触发。
- **mixin 配置完整性检查会因为摘除 mixin 而红**：`*.mixins.json` 里列的类必须真实存在
  ⇒ 摘 mixin 时**必须同步从 json 删条目**。

## 6. 风险登记（诚实清单）

| 风险 | 等级 | 说明 |
|---|---|---|
