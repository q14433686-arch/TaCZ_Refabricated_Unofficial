## 1. 为什么这两项在 26.3 上也成立

### 1.1 JEI：26.3 的「部分修复」仍留着危险回退

同步前 26.3 的 `RecipeViewerReloadBridge#refreshJei()` 是：

```text
反射 Internal.restartJei()  ->  失败则伪造 JeiLifecycleEvents.AFTER_RECIPES_UPDATED
```

`Internal.restartJei()` 本身不清理配方（26.3 上游 `ClientLifecycleHandler#restartJei()` 只是
`stopJei(); startJei();`），所以正常路径是安全的。问题在回退分支：

```java
// JEI 26.3 Fabric: ClientLifecycleHandler#registerEvents
JeiLifecycleEvents.AFTER_RECIPES_UPDATED.register(() -> {
    if (!receivedRecipeSync) Internal.clearClientRecipes();
    receivedRecipeSync = false;
    if (running) stopJei();
    startJei();
});
```

`receivedRecipeSync` 只由真实的 Fabric 配方同步回调置位、并被首次事件消费。枪包同步几乎总是发生在
进服后的配方更新之后，此时再自造一次事件 → 走 `clearClientRecipes()` → JEI 退回
`VanillaClientRecipeLoader`（`Loaded N vanilla recipes...`、`This fabric server does not provide
recipes to JEI`），所有数据包提供的 `minecraft:crafting_*`（含本模组十个工作台/弹药箱/靶子配方）
从 JEI 消失。26.3 线原本保留这条回退，等于把「反射失败」翻译成「清空服务端配方」。

`RECIPE_VIEWER_CROSS_BRANCH_AUDIT_20261015.md` 对 26.3 的结论正是这一条（「失败后仍回退到危险事件」，
建议去掉回退、改用生命周期 listener）。本次即按此执行。

### 1.2 弹孔：朝向修复在 26.3 上完全缺失

同步前 26.3 的 `extract()` 仍是 `this.direction.getRotation()` + 带 `Camera` 的四参数重载，
即 26.2 修复前的写法。`Direction#getRotation()` 把局部 **+Y** 转到命中面法线，而
`QuadParticleRenderState` 的顶点在 XY 平面（局部 **+Z** 法线），四个角点/UV 顺序按旧 XZ 四边形
排定 —— 于是六个面都不贴面朝向，UV 走向也不对。该缺陷与 Minecraft 版本无关，只与
`SingleQuadParticle`/`QuadParticleRenderState` 的顶点约定有关，26.3 沿用同一套粒子状态类。

## 2. 26.3 与 26.2 的实现差异

JEI 部分 26.3 与 26.2 现在逐行一致（同一 `ResourceManagerReloadListener` 捕获方案），差异只在注释里
的版本与依赖号：

- 26.3 编译依赖 JEI `31.8.0.48`、REI `26.3.823`；26.2 是 `30.13.0.86` / `26.2.820`。
- Mixin 注册位置：都挂在 `tacz.fabric.mixins.json` 的 `client` 段。26.3 的 `tacz.mixins.json`
  只放 `com.tacz.guns.mixin` 包下的原版侧注入，不要混放。
- `MixinPlugin#shouldApplyMixin` 用包名第 6 段推导可选 mod id（`compat.jei` → `jei`），
  26.3 的 `MixinPlugin` 与 26.2 相同，无需改动。
- 反射 `Internal.restartJei()` 的分支**删除**，不再"优先反射、失败回退事件"。理由：JEI 在
  handler 未初始化时 `Preconditions.checkState(restartJeiRunnable != null)` 会直接抛异常；而且静态
  `restartJei()` 并非所有旧 JEI 都有，而 `getReloadListener()` 三条 JEI 版本线都有。
  「反射失败 → 每连接一次资源重载兜底」仍然保留，兜底路径不会伪造配方更新事件。

弹孔部分 26.3 与 26.2 逐行一致，仅 javadoc 里补了「经 26.2 回移后同步回本线」的出处说明。
26.3 原本没有这段代码，因此不涉及与 26.3 特有渲染路径（Iris/stencil、`renderpearl` 包）的交互；
该粒子走 `ParticleRenderType.SINGLE_QUADS` + `TRANSLUCENT_TERRAIN` 层，未使用自定义 pass。

## 3. 已执行的验证

```bash
python3 scripts/verify_recipe_viewer_reload.py     # 4 项：10 个配方 schema、禁止伪造事件、Mixin 注册、生命周期
python3 scripts/verify_bullet_hole_orientation.py  # 5 项：六面法线、UV/角点、相机插值、源码装配、颜色还原
bash scripts/check_release_consistency.sh --strict # 版本/README 一致性
```

- 两个脚本的断言针对本线真实源码与资源文件运行，全部通过。
- 26.2 的 `verify_recipe_viewer_reload.py` 里 `Internal.restartJei` 尚未被禁；本线的版本额外把
  `restartJei` / `JeiLifecycleEvents` 加入禁止出现列表，避免有人把回退加回来。
- 弹孔脚本的几何模型与上游 1.21.1 `BulletHoleParticle.render` 的对比沿用 26.2 记录；
  旋转/顶点约定是在仓库内缓存的 26.2 merged jar 字节码上核对的
  （`Direction#getRotation`、`QuadParticleRenderState#renderRotatedQuad` 的四角与 UV、
  `SingleQuadParticle#extractRotatedQuad` 两个重载、`Mth.PI/HALF_PI`）。

## 4. 编译结果与未验证的边界

**CI（commit `382dcb5`）**：

- `build` run [`39680020522`](https://github.com/q14433686-arch/TaCZ_Refabricated_Unofficial/actions/runs/39680020522)
  成功，含「Mixin config integrity」「Lang key parity」「Version consistency」三个静态步骤与
  完整 `./gradlew build`（Java 25），并产出 jar artifact。
- `compile-check` run [`39680020194`](https://github.com/q14433686-arch/TaCZ_Refabricated_Unofficial/actions/runs/39680020194) 成功。
- 因此 26.3 的 `SingleQuadParticle` 确有六参数
  `extractRotatedQuad(state, quaternion, x, y, z, partialTick)` 重载，`Mth.PI/HALF_PI` 也存在；
  mixin 目标名与 `@Pseudo` 写法通过配置完整性校验（`require = 0` 意味着目标缺失时不会阻断启动）。

仍然未验证的部分：

- **没有进游戏。** JEI 刷新、JEI+REI 并存、六面弹孔（无光影 / Iris）都未实测；
  编译通过不等于行为正确。
- **Mixin 是否真的注入。** `require = 0` 保证 JEI 改实现时不会崩，但也意味着「注入静默失败 →
  桥接回落到每连接一次资源重载」不会报错，只会在日志里体现为
  `[TACZ Recipe Viewer] Viewer reload hook unavailable`。实机验收必须检查这一行是否出现。
- **REI 仍然不安全。** 三个分支的 `refreshRei()` 都会 `reloadPlugins(null, null)` 全量重载，而已同步
  的服务端显示不保证重放；本次没有动它，也没有证据表明它被修好。
- **手动合成 ≠ 查看器显示。** 本次修的是 JEI 客户端显示路径；「服务端配方是否存在/能否手摆合成」
  属于另一条链路，未在本次范围内验证。

## 5. 实机验收清单

1. 专服 + 客户端装 JEI 31.8：进服后触发枪包同步，JEI 仍能查到十个 `minecraft:crafting_shaped`
   内置配方；`latest.log` 不得出现 `This fabric server does not provide recipes to JEI`，
   也不得出现 `[TACZ Recipe Viewer] JEI lightweight refresh unavailable`。
2. 同时装 JEI + REI：两条刷新互不短路；记录 REI 刷新后普通配方数量变化（这是未修项，重点是
   不要把它误判成新引入的回归）。
3. 断线重连 / 换服：A 服配方不带到 B 服；同 JVM 第二次进服 JEI 仍能刷新（listener 属于客户端
   生命周期，`clear()` 不清它）。
4. 弹孔：无光影下分别打六个方块面，移动/转动相机确认贴面、不跟随镜头、UV 方向正确；
   再开 Iris 复测墙/地/天花板，观察 z-fighting 与渐黑淡出；击碎附着方块后粒子消失。
